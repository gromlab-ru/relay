# Ошибки, сверка и восстановление

[Основное руководство](../SKILL.md) · [Подключение](STARTUP.md) · [Инструменты MCP](MCP.md)

## Сначала установи, что действительно произошло

Ошибка чтения означает, что состояние не получено. Ошибка или тайм-аут записи означает, что результат может быть неизвестен: сервер мог сохранить данные до потери ответа.

Сохрани проект, объект, автора, исходные аргументы, ревизию и `requestId`. Сначала проверь объект в той же базе. Новый ключ не является способом безопасно повторить неподтверждённое создание.

| Ситуация                                          | Действие                                                                               |
| ------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `projects_list` не показывает ожидаемый проект    | Сверь сервер, режим и поручение; регистрацией управляет оркестратор                    |
| `PROJECT_REQUIRED`                                | Передай проект из актуального списка; workspace требует его и при одной записи         |
| `PROJECT_NOT_FOUND`                               | Проверь ключ/ID и регистрацию; не записывай в похожий проект                           |
| `CONFIG_NOT_FOUND`                                | Найди выданный конфиг или используй явный URL; новый проект инициализирует оркестратор |
| `WORKSPACE_REQUIRES_SERVER`                       | Используй общий сервер; для аварийного local нужен конкретный проектный конфиг         |
| `ACTOR_REQUIRED`                                  | Задай `actor` MCP либо `--actor` / `RELAY_ACTOR` CLI                                   |
| `SERVER_UNAVAILABLE`                              | Восстанови доступ к тому же серверу; работник сообщает оркестратору                    |
| `SERVER_INCOMPATIBLE` или нет нужного инструмента | Сверь установленную версию, её help/схемы и обновление сервера; не придумывай аналоги  |

## Конфликт ревизий

`REVISION_CONFLICT` означает, что объект изменился после чтения. Документы также требуют `ifRevision` при обновлении (`REVISION_REQUIRED`).

1. Перечитай именно изменяемый объект.
2. Сравни свои намерения с новой версией.
3. Подготовь изменение заново: patch карточки либо полный актуальный `fields` документа.
4. Передай новую ревизию вместе с согласованными данными.

Если конкурентная правка касается того же решения, запроси уточнение. Простая подстановка свежей ревизии к устаревшим полям затрёт чужую работу. У карточки `12` и контекста `task_12` разные ревизии. Добавления логов и комментариев увеличивают ревизию карточки.

## Повторы и ключи

| Операция                                                  | После неизвестного результата                                                   |
| --------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Добавление лога/комментария                               | Повтори тот же запрос, автора и `requestId` в той же задаче и проекте           |
| Создание обычного проектного документа с `requestId`      | Повтори исходный вид, автора, поля и ключ в том же проекте                      |
| Создание карточки задачи                                  | Проверь результат в списке/поиске; повтор автоматически не защищён от дубликата |
| Паспорт или контекст задачи                               | Перечитай стабильный ID `passport` / `task_T`                                   |
| Обновление, назначение, изменение статуса или зависимости | Перечитай объект и проверь, применились ли поля                                 |

`IDEMPOTENCY_CONFLICT` говорит о несовместимом использовании ключа. Сверь исходные аргументы, а не заменяй ключ на новый для той же неподтверждённой операции. Ключ содержит 1–128 символов `[A-Za-z0-9._:-]` и начинается с буквы или цифры.

## Ссылки, готовность и переходы

| Ошибка                                                                      | Что проверить                                                                       |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `TASK_NOT_FOUND`, `PROJECT_RECORD_NOT_FOUND`, `PROJECT_REFERENCE_NOT_FOUND` | Выбранный проект, реальный ID и наличие объекта нужного вида                        |
| `PROJECT_REFERENCE_MISMATCH`                                                | Соответствие задачи и попытки/проверки; этапы зависимостей принадлежат одному плану |
| `TASK_ASSIGNED`, `ASSIGNEE_MISMATCH`                                        | Назначение; решение о переназначении принимает оркестратор                          |
| `TASK_BLOCKED`, `TASK_NOT_READY`                                            | `blockedBy`, статусы зависимостей и конфигурацию ready-статусов                     |
| `DEPENDENCY_CYCLE`, `PARENT_CYCLE`, `PROJECT_CYCLE`                         | Связи образуют цикл; пересмотри граф                                                |
| `STAGE_BLOCKED`                                                             | Приняты ли зависимые этапы и закончены ли листовые задачи                           |
| `PLAN_INCOMPLETE`                                                           | Есть ли этапы и все ли приняты                                                      |
| `ACCEPTANCE_REQUIRED`                                                       | Есть ли содержательное основание приёмки/подтверждение установки                    |
| `CHECKS_INCOMPLETE`, `CHECK_COMMIT_MISMATCH`                                | Результаты выбранных проверок и соответствие проверяемому коммиту                   |
| `ANSWER_REQUIRED`                                                           | Сохранён ли ответ перед состоянием `answered`                                       |
| `RELEASE_COMMIT_REQUIRED`, `RELEASE_INCOMPLETE`                             | Коммит релиза и успешное завершение включённых задач                                |
| `RUN_FINISHED`                                                              | Для повторной работы создай новую попытку                                           |
| `CHECKPOINT_IMMUTABLE`                                                      | Для нового состояния создай новую контрольную точку                                 |
| `IMMUTABLE_FIELD`                                                           | Не меняй вид документа или задачу существующего исполнения                          |

Технически разрешённый переход не заменяет фактическую проверку результата. Подробная семантика — в [модели данных](DATA-MODEL.md).

## Слишком большой ответ

Используй `project_context` для обзора, `project_records` для списка метаданных и `project_record_get` для одного документа. Карточку читай через `task_get.fields`; логи и комментарии — отдельными страницами.

В MCP у списков есть `limit` и `cursor`. Передавай `meta.nextCursor` с прежними проектом и фильтрами, пока `hasMore` истинно. `project_context` ограничивает текст и число элементов, но сохраняет полные счётчики.

CLI `project records` не имеет пагинации. Для большого списка используй `--kind`, больший `--max-bytes` или MCP. `RESPONSE_TOO_LARGE` допускает увеличение бюджета вплоть до 16 МиБ, но предпочтительнее точечное чтение. Бюджет MCP учитывает и JSON-текст, и структурированную копию ответа.

## Отказ хранилища и аварийный доступ

При `INVALID_DATA`, `VALIDATION_FAILED`, `IO_ERROR` сохрани диагностику и сообщи владельцу базы. Используй `project_validate` / `validate` для проверки; изменения файлов и миграция требуют осознанного решения по восстановлению.

При `STORAGE_BUSY` дождись завершения операции. При `LOCK_LOST` сначала перечитай состояние. Работник не исправляет общую базу обходом блокировок или созданием своей копии.

Оркестратор может выбрать прямой доступ к **той же базе**:

```bash
relay-cli --local --config /work/app/.relay/config.json project context --format json
```

Сначала убедись, что это фактический проектный конфиг серверной базы. Workspace-конфиг для такого обхода не подходит. При повторе добавления сохрани исходные ключ, автора и содержание.

## Коды и результат команды

CLI: `0` — успех; `2` — ввод/настройки; `3` — объект не найден; `4` — конфликт; `5` — хранилище/транспорт. HTTP-статус и код CLI различаются.

MCP возвращает ошибку операции как `isError: true` и `{ ok: false, error: { code, message, details? } }` в `structuredContent`. При успехе используй `data`; при ошибке прекрати зависимые шаги и обработай причину.
