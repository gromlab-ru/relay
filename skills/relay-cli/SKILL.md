# Relay CLI

## Режимы и подключение

- `.relay/config.json` — **local**, один проект. База задач — `.relay/tasks`.
- `relay.workspace.json` — **workspace**, реестр независимых проектов и общий сервер.
- CLI и сервер ищут ближайший конфиг вверх от cwd. В одном каталоге workspace имеет
  приоритет. `--config` переопределяет `RELAY_CONFIG` и поиск.
- В local CLI использует Core без URL или HTTP при `server.url`. `--local` выбирает файлы.
- В workspace рабочие команды CLI всегда используют сервер и явный проект.
- MCP всегда подключается к запущенному Relay Server. Режим и проекты узнавай через
  `projects_list`; в workspace передавай `project`, даже если регистрация одна.

Сервер запускается отдельным пакетом:

```bash
npx @gromlab/relay-server
npx @gromlab/relay-mcp --server-url http://127.0.0.1:3000
```

MCP URL по умолчанию — `http://127.0.0.1:3010/mcp`. Файлы проекта находятся на стороне
Relay Server; MCP не запускает проектные API самостоятельно.

## Роли

Оркестратор ставит задачи, назначает исполнителей, управляет зависимостями и статусами,
проверяет результаты. Субагент получает конкретную задачу и записывает ход выполнения.
Человек наблюдает и уточняет работу через Web.

Субагент не выбирает следующую задачу самостоятельно и не вызывает `claim`, `assign`,
`release`, `status` или изменение зависимостей без поручения оркестратора.

## Чтение и запись

В local:

```bash
npx @gromlab/relay-cli get 12 --format json
npx @gromlab/relay-cli log add 12 --actor backend-agent --kind progress \
  --request-id step-1 --text "Контракт проверен, продолжаю реализацию" --format json
npx @gromlab/relay-cli update 12 --actor backend-agent --summary "Следующий шаг — проверка ошибок"
```

В workspace добавляй проект перед командой: `relay-cli backend get 12`.
Из произвольного каталога можно передать общий URL и проект через `--server-url` и
`--project`. Автор CLI — `--actor` или `RELAY_ACTOR`; он не задаёт адрес подключения.

Эквивалентные MCP-вызовы:

```text
task_get({ project: "backend", id: 12 })
log_add({ project: "backend", id: 12, actor: "backend-agent", requestId: "step-1", text: "Контракт проверен" })
```

В local поле `project` можно опустить. Точные схемы инструментов читай через tools/list.
В `comment_add` и `log_add` обязательны `actor` и `requestId`.

## Правила данных

- Полная ссылка на задачу в workspace — проект + ID. Номера разных баз могут совпадать.
- `parentId` задаёт декомпозицию, `dependsOn` — ожидание успешного завершения.
- `terminal` определяет конечность, `satisfiesDependencies` — успех. Отмена не удовлетворяет зависимости.
- `description` хранит требования, `summary` — актуальное состояние и следующий шаг,
  `comment` — обсуждение, `log` — историю действий и проверок.
- Записывай через CLI/MCP/API: Core проверяет схемы, граф и ревизии под блокировкой.
- Добавление отчёта меняет ревизию. Для `--if-revision` перечитывай актуальный документ.
- `ready: false` у назначенной задачи ожидаемо: это доступность для захвата, а не оценка поручения.

## Ошибки и восстановление

| Ошибка                      | Действие                                        |
| --------------------------- | ----------------------------------------------- |
| `PROJECT_REQUIRED`          | Укажи выданный проект из `projects_list`        |
| `PROJECT_NOT_FOUND`         | Сверь регистрацию и поручение                   |
| `WORKSPACE_REQUIRES_SERVER` | Используй общий сервер workspace                |
| `SERVER_UNAVAILABLE`        | Сохрани диагностику и сообщи оркестратору       |
| `REVISION_CONFLICT`         | Перечитай данные и согласуй своё изменение      |
| `IDEMPOTENCY_CONFLICT`      | Сверь автора, проект, ID и исходные поля записи |
| `RESPONSE_TOO_LARGE`        | Читай поля, страницы и отдельные записи         |

Потерянный ответ не доказывает отсутствие записи. Для комментария или отчёта повторяй
исходные поля и тот же `requestId`. Новый шаг получает новый ключ. Создание задачи и
прочие мутации автоматически не повторяются: сначала проверь фактическое состояние.

Если требуется аварийный прямой доступ, оркестратор выбирает точный **проектный**
конфиг: `relay-cli --local --config /work/A/.relay/config.json ...`. Workspace-конфиг
не используется для обхода HTTP. Не создавай отдельную базу в worktree вместо общей.

Подробности: [оркестратор](reference/ORCHESTRATOR.md), [субагент](reference/SUBAGENT.md).
Для неизвестной команды или параметра используй `relay-cli <команда> --help`.
