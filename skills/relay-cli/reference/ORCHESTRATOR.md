# Оркестратор

[Основной алгоритм](../SKILL.md)

## Подготовка

1. Определи local/workspace и конкретные проектные базы.
2. Для нового проекта выполни `relay-cli init` в его каталоге.
3. Для workspace создай `relay.workspace.json` с локальными путями к проектам.
4. Запусти `relay-server` с выбранным конфигом. При наличии общего сервера используй его.
5. Подключи MCP к его URL либо настрой `server.url` для CLI.
6. Проверь `projects_list`/`relay-cli projects list` для workspace и конфигурацию выбранного проекта.

Регистрации workspace изменяются через работающий сервер: `projects add/remove`
или MCP `project_register`/`project_unregister`. Сначала инициализируй проект, затем регистрируй.

## Планирование и назначение

Прочитай `overview`, существующие задачи и статусы. В описании задачи зафиксируй
результат, границы и критерии. Передай субагенту проект, ID, автора и каталог кода.

```bash
relay-cli backend create "API регистрации" --actor orchestrator --format json
relay-cli backend update 1 --assignee backend-agent --status in_progress --actor orchestrator
```

Используй ID из ответа, а статусы — из конфига. При необходимости добавь актуальную
`--if-revision`. Родительская связь не заменяет зависимость; переход на проверку
не равен успешному завершению блокера.

Рабочие копии кода могут быть независимыми. Агентам передавай подключение к нужной
общей базе: workspace-конфиг либо URL с ID проекта. Ближайший `.relay/config.json`
внутри worktree выбирает local, поэтому контекст подключения должен быть определён
до выдачи поручения.

## Приёмка и передача

Прочитай отчёт и проверь критерии. Сам переведи задачу на проверку, возврати на
доработку или заверши. Родитель завершается отдельно после проверки общего результата.
Перед сменой исполнителя сохрани актуальное summary, подтверждения и следующий шаг.

Управление агентскими процессами принадлежит используемой среде выполнения.
Статус задачи сам по себе не подтверждает, что агент сейчас работает.
