# Команды и ответы CLI

[К основному алгоритму](../SKILL.md)

Все команды ниже дополняют `npx @gromlab/tasks-cli`. `<id>` — ID из ответа,
`<comment-id>` и `<log-id>` — полные ID записей указанной задачи.
Для записи нужен `--actor` или `TASKS_ACTOR`, для чтения автор не требуется.

Назначения, статусы, связи и выбор работы принадлежат оркестратору.
Субагент использует чтение конкретного ID, комментарии, отчёты и обновление summary.
Наличие технической команды `claim` в CLI не означает самостоятельный выбор задач субагентом.
Подключение обычно определяется `server.url` в конфиге; параметры URL ниже — переопределения.

## Общие параметры

| Параметр                      | Назначение                                       |
| ----------------------------- | ------------------------------------------------ |
| `--config <path>`             | Конфиг выбранной базы                            |
| `--server-url <url>`          | HTTP(S) origin общего сервера                    |
| `--local`                     | Прямой Core с игнорированием HTTP-настроек       |
| `--actor <id>`                | Автор записи                                     |
| `--format json`               | Структурированный ответ для агента               |
| `--max-bytes <N>`             | Бюджет UTF-8 ответа: 1024–16777216, обычно 16384 |
| `--color auto\|always\|never` | Оформление текста; JSON не содержит ANSI         |
| `--help`, `--version`         | Справка и версия; ответ всегда текстовый         |

Опции можно передавать вместе с вложенной командой. Полная справка:

```bash
npx @gromlab/tasks-cli --help
npx @gromlab/tasks-cli create --help
npx @gromlab/tasks-cli log add --help
```

## Проект и чтение

| Команда            | Смысл и основные параметры                                    |
| ------------------ | ------------------------------------------------------------- |
| `init`             | Создать новую базу; `--storage <path>`, по умолчанию `.tasks` |
| `config get`       | Конфиг в `data`, фактические пути в `meta`                    |
| `validate`         | Проверить все документы, записи и граф                        |
| `migrate`          | Явная локальная миграция старой базы, нужен автор             |
| `server`           | UI/API/SSE на loopback; `--port <0–65535>`, `--open`          |
| `group list`       | Прогресс групп; `--limit`, `--cursor`, `--all`                |
| `list`             | Неконечные задачи, включая назначенные и заблокированные      |
| `get <id>`         | Карточка, описание, summary, связи и счётчики истории         |
| `description <id>` | Только описание                                               |
| `summary <id>`     | Только актуальное саммари                                     |
| `overview [id]`    | Сводка проекта или выбранного дерева                          |

Фильтры `list`: `--status`, `--group`, `--assignee`, `--parent`, `--tag`, `--search`,
`--ready`, `--all`. Фильтры объединяются через И. Поиск — по названию, описанию
и summary без учёта регистра. `--sort id` — обычный порядок; `--sort board` — порядок доски.

`get --fields id,status,assignee,summary,revision,blockedBy,ready` ограничивает ответ.
`get --full` включает все комментарии и отчёты. Описание и текст записей в JSON —
массивы строк; поля `comments`, `logs` полного документа — словари.

`overview` возвращает прогресс непосредственных детей, доступную работу, проверку
и основные блокеры. `--limit 1–100` — максимум строк каждого раздела (по умолчанию 5).
`--review-status qa,acceptance` задаёт неконечные статусы проверки; обычное значение — `review`.
Влияние блокера считается по прямым связям открытых листовых задач выбранной области;
внешние блокеры учитываются. Рейтинг не заменяет проверку результата работы.

## Постановка и изменения

| Команда                         | Смысл                                                                                     |
| ------------------------------- | ----------------------------------------------------------------------------------------- |
| `create [title]`                | Создать задачу; название позиционно или через `--title`                                   |
| `update <id>`                   | Изменить переданные поля, остальные сохранить                                             |
| `status <id> <status>`          | Сменить статус, сохранив исполнителя                                                      |
| `assign <id> <assignee>`        | Явно назначить/заменить исполнителя                                                       |
| `claim <id>`                    | Атомарно занять свободную доступную задачу; `--status` меняет статус вместе с назначением |
| `release <id>`                  | Снять исполнителя без смены статуса; `--force` позволяет снять чужое назначение           |
| `deps add <id> <dependency>`    | Добавить одну блокирующую зависимость                                                     |
| `deps remove <id> <dependency>` | Удалить одну зависимость, сохранив остальные                                              |
| `links <id>`                    | Родитель, дети, прямые и обратные зависимости, текущие блокеры                            |
| `tree <id>`                     | Дерево подзадач; `--depth 0–100`, по умолчанию 3                                          |

Поля `create`/`update`: `--title`, `--description`, `--summary`, `--status`, `--group`,
`--parent`, `--tags`, `--depends-on`, `--assignee`.
`--tags` и `--depends-on` заменяют весь набор и принимают значения через запятую.
Для одной зависимости используй `deps add/remove`.

`--clear-group` и `--clear-parent` снимают значения. Пустая строка очищает описание,
summary, теги и зависимости; неуказанное поле сохраняется. Исполнитель снимается через `release`.
Текст можно передать через `--description-file`, `--summary-file`; `--stdin` читает
описание, значение `-` у файлового параметра читает stdin. Для каждого поля выбери
один источник; общий stdin можно прочитать только один раз.

`update`, `status`, `assign`, `claim`, `release`, `deps add/remove` поддерживают
`--if-revision <N>`. После любого изменения, включая добавление записи, нужна новая
ревизия для следующей защищённой операции.
Успешная запись полей возвращает `{ id, revision }`. Изменение без фактической разницы
может сохранить ревизию. Создание задачи не поддерживает `--request-id`.

## Комментарии и отчёты

| Команда                          | Смысл                                                          |
| -------------------------------- | -------------------------------------------------------------- |
| `comment add <id>`               | Добавить комментарий: один из `--text`, `--stdin`, `--file`    |
| `comment list <id>`              | Краткая история; `--author`, параметры страниц                 |
| `comment get <id> <comment-id>`  | Полный комментарий                                             |
| `log add <id>`                   | Добавить отчёт: один источник тела и дополнительные метаданные |
| `log list <id>`                  | Краткие отчёты с фильтрами                                     |
| `log get <id> <log-id>`          | Полный отчёт                                                   |
| `log search <id> --query <text>` | Буквальный поиск в теле с учётом регистра                      |

Добавление требует непустого текста и возвращает `{ id, taskId }`.
`comment add` и `log add` поддерживают `--request-id` для повтора одной записи.
`--file -` читает stdin. У `log add` доступны:

- `--kind progress|decision|execution|error|summary`, по умолчанию `progress`.
- `--title` — однострочный заголовок; по умолчанию пуст.
- `--summary` — краткое содержание конкретного отчёта; по умолчанию пусто.
- `--session-id` — идентификатор сессии; по умолчанию `null`.

Фильтры `log list/search`: `--author`, `--kind`, `--session-id`, `--since`, `--until`.
Даты — `YYYY-MM-DD` или ISO 8601 с часовым поясом. Поиск возвращает ID, первую
подходящую строку, количество подходящих строк и фрагмент.

## JSON и страницы

Успех: `{ "ok": true, "data": ..., "meta": ... }`.
Ошибка: `{ "ok": false, "error": { "code": ..., "message": ..., "details": ... } }`.
`meta` и `details` необязательны. Проверяй также код завершения процесса:
`0` — успех, `2` — ввод/настройки, `3` — не найдено, `4` — конфликт, `5` — данные/IO/HTTP.

`data.items` содержит страницу; `meta.hasMore` и `meta.nextCursor` — продолжение.
Повторяй исходные фильтры с непрозрачным курсором. Параметры размера можно менять.

| Команда                                         | Размер по умолчанию                           | Значение `--all`                                            |
| ----------------------------------------------- | --------------------------------------------- | ----------------------------------------------------------- |
| `list`                                          | Ограничен байтовым бюджетом, а не количеством | Включить конечные статусы; совместим с `--limit`/`--cursor` |
| `group list`, `comment list`, `log list/search` | `output.defaultLimit`, обычно 20              | Полный ответ в бюджете; несовместим с `--limit`/`--cursor`  |
| `overview`                                      | 5 строк раздела                               | Флага и курсора нет                                         |

Явный `--limit`: 1–100. При `RESPONSE_TOO_LARGE` выбери меньшую страницу или поля,
прочитай конкретную запись отдельно либо увеличь `--max-bytes`.
Пагинация REST-доски отличается от CLI: смена снимка даёт `BOARD_CHANGED`.

Лимиты хранения: название/заголовок — 1024 байта UTF-8, описание/тело отчёта — 256 КиБ,
summary — 4096 байт, комментарий — 64 КиБ, весь JSON задачи — 16 МиБ.
Общий размер HTTP-тела запроса ограничен 1 МиБ.

См. [восстановление](RECOVERY.md) и [формы отчётов](WORK_CONTEXT.md).
