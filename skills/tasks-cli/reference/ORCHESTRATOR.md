# Оркестратор

[К основному алгоритму](../SKILL.md)

Сначала выбери интерфейс и проект. В MCP выполни `projects_list` и `project_config`.
Один общий MCP обслуживает всех агентов; без URL он сам запускает REST API проектов.
Реестр `tasks.orchestrator.json` ведёт оркестратор; регистрации и изменения доступны
без перезапуска. Для CLI с реестром добавляй имя перед каждой рабочей командой.
В поручении передавай пару проект + ID. [Сценарий MCP](MCP.md).
Ниже описана подготовка CLI/API; при MCP конфиг задач нужен на хосте сервера,
а в worktree субагента достаточно кода и подключения к общему MCP.

## Подготовить базу и сервер

Оркестратор управляет всем потоком: создаёт задачи, выбирает исполнителей,
настраивает зависимости, статусы, проверяет результаты и выдаёт следующую работу.
Субагенты получают уже назначенные ID.

Для нового проекта:

```bash
npx @gromlab/tasks-cli init
```

Для существующего проекта прочитай `tasks.config.json` или настройки напрямую:

```bash
npx @gromlab/tasks-cli --local config get --format json
```

Если нужна общая серверная база, настрой секцию существующего конфига:

```json
{ "server": { "port": 3000, "url": "http://127.0.0.1:3000" } }
```

Это фрагмент, остальные поля сохраняются. При наличии URL оркестратор обеспечивает
запуск сервера до обычных команд и делегирования. Если сервер нужного проекта уже
доступен, используй его; иначе запусти в отдельном управляемом процессе:

```bash
npx @gromlab/tasks-cli server --actor human
```

`server` всегда запускается локально с выбранным конфигом. `human` подписывает
возможные дополнения человека из UI. CLI оркестратора и агентов автоматически
использует `server.url`; отдельные переменные URL им не требуются.
Если URL отсутствует, команды выполняются локально через Core.

## Подготовить worktree

Все участники работают на одном хосте. Обеспечь наличие одинаковой настройки
`server.url` в рабочих копиях до запуска субагентов: например, сохрани конфиг в Git
перед созданием worktree. В существующие worktree настройку доставляет оркестратор.

В HTTP локальная копия `.tasks` агента не используется. Сервер сохраняет файлы
в базе своего конфига. При прямом доступе из нескольких каталогов оркестратор должен
обеспечить единый путь базы: отдельные `.tasks` разных worktree не являются общей очередью.

## Постановка

Сначала прочитай `overview` и `list --all`. Пример для новой базы, где ID будут `1–3`:

```bash
npx @gromlab/tasks-cli create "Регистрация пользователей" --assignee orchestrator \
  --group product --actor orchestrator --format json
npx @gromlab/tasks-cli create "API регистрации" --parent 1 --group backend \
  --actor orchestrator --format json --stdin <<'MD'
## Результат

POST /users создаёт пользователя и возвращает ошибку повторного email.

## Границы

Обработчик API и связанные проверки; форму выполняет другой агент.

## Критерии готовности

- Новый email: 201.
- Повторный email: 409 с code EMAIL_TAKEN.
- Команды и результаты проверок сохранены в отчёте.
MD
npx @gromlab/tasks-cli create "Форма регистрации" --parent 1 --depends-on 2 \
  --group frontend --actor orchestrator --description "Подключить API и показать ошибки" --format json
npx @gromlab/tasks-cli status 1 in_progress --actor orchestrator --format json
```

Используй реальные ID из ответов. `parent` — структура, `depends-on` — ожидание успеха.
Зависимая задача не становится готовой только от перехода блокера на проверку.

## Назначить и делегировать

Оркестратор сам выбирает готовые задачи по `overview`, `list --ready` и связям.
Перед запуском назначь исполнителя и рабочий статус:

```bash
npx @gromlab/tasks-cli update 2 --assignee backend-agent --status in_progress \
  --actor orchestrator --format json
```

Для конкурентной защиты добавь свежий `--if-revision`. Назначение и статус в одном
`update` сохраняются атомарно. Отдельная команда `assign` меняет только исполнителя.
Явное назначение не проверяет готовность так, как `claim`: блокеры и критерии выдачи
проверяет оркестратор перед делегированием.

Поручение содержит ID, имя автора, каталог кода, границы и ожидаемый результат.
Например: «Задача #2 назначена backend-agent. Выполни требования, запиши прогресс
и итог проверок, верни результат оркестратору. Статус и назначение не меняй».
URL уже находится в конфиге; подключение не является задачей субагента.

## Контролировать результат

```bash
npx @gromlab/tasks-cli get 2 --format json
npx @gromlab/tasks-cli log list 2 --kind summary --format json
npx @gromlab/tasks-cli status 2 review --actor orchestrator --format json
```

Прочитай итог и проверь критерии. При замечаниях добавь комментарий, верни рабочий
статус и выдай поручение на доработку тому же или другому агенту.
При приёмке переведи в успешный конечный статус. После завершения API назначь форму.

Родитель завершается отдельно после проверки общего результата. Передача незавершённой
работы также принадлежит оркестратору: сначала контекст, затем изменение назначения.
См. [WORK_CONTEXT.md](WORK_CONTEXT.md), [RECOVERY.md](RECOVERY.md).
