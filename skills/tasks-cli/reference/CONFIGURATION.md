# Конфигурация и автоматический выбор подключения

[К основному алгоритму](../SKILL.md)

## Основной режим

Подключение настраивает оркестратор в `tasks.config.json`:

```json
{ "server": { "port": 3000, "url": "http://127.0.0.1:3000" } }
```

Это секция существующего конфига. `server.url` включает обращение CLI к API,
`server.port` задаёт порт запуска сервера. Один порт без URL не включает HTTP.
Если URL отсутствует, CLI использует локальный Core.

Оркестратор запускает сервер по конфигу и обеспечивает этот конфиг в worktree агентов.
После этого субагенту достаточно обычного вызова:

```bash
npx @gromlab/tasks-cli get 12 --format json
npx @gromlab/tasks-cli log add 12 --actor backend-agent --text "Проверяю контракт" --format json
```

ID и автора задаёт поручение. URL и переменные подключения субагент не устанавливает.
При серверной ошибке он сообщает оркестратору; база не переключается молча.

## Кто выбирает транспорт

CLI читает настройки и выбирает адаптер до открытия локального хранилища:
HTTP через SDK либо локальные операции Core. Сервер сам вызывает Core.
Так оба входа используют одинаковые правила без рекурсивного обращения Core к API.

Конфиг ищется вверх от каталога вызова. `storageDir` разрешается относительно конфига.
В HTTP `config get` показывает серверный проект и пути в `meta`; локальная `.tasks`
worktree не открывается. Файлы из `--file` читает вызывающий агент, запись сохраняет сервер.

## Дополнительные переопределения

Для специальных запусков предусмотрены:

```text
Транспорт: --local → --server-url → TASKS_SERVER_URL → server.url → Core
Конфиг:    --config → TASKS_CONFIG → поиск вверх от текущего каталога
Порт:      --port → TASKS_PORT → server.port → 3000
Автор:     --actor → TASKS_ACTOR
```

Переменные URL и явные флаги удобны для диагностики, временных адресов и интеграций;
они не являются обязательной подготовкой субагента. В обычном процессе используется конфиг.
`--local` — явное восстановление, организуемое оркестратором с правильной центральной базой.

Автор подписывает изменение, `assignee` определяет исполнителя. Автор — метаданные,
не аутентификация. `--actor human` у сервера задаёт автора дополнений из UI.
Оркестратор и субагенты передают своих авторов в командах записи.

## Сервер и статусы

`server` запускается локально независимо от URL. Порт `0` выбирает ОС; первое
JSON-сообщение содержит `{ url, actor, pid }`. Для такого запуска оркестратор обновляет
URL в конфигурации клиентов до делегирования. Обычный постоянный порт упрощает worktree.

URL — HTTP(S) origin без `/api/v1`, query, hash и credentials. Сервер продукта слушает
`127.0.0.1`. В контейнере loopback указывает на сам контейнер; основной режим — один хост.

| Настройка                               | Значение                                                         |
| --------------------------------------- | ---------------------------------------------------------------- |
| `defaultStatus`                         | Начальный статус создаваемой задачи                              |
| `readyStatuses`                         | Статусы доступной свободной работы, которую выбирает оркестратор |
| `statuses.<ключ>.terminal`              | Конечная задача, скрытая из обычного `list`                      |
| `statuses.<ключ>.satisfiesDependencies` | Успешное завершение зависимости                                  |
| `output.defaultLimit`                   | Страница групп/комментариев/отчётов, обычно 20                   |
| `output.maxBytes`                       | Бюджет ответа CLI, обычно 16384 байта                            |

Статусы меняет оркестратор. Начальный `done` удовлетворяет зависимости, `cancelled` — нет.
`ready: false` у назначенной задачи ожидаемо; это не означает наличие блокера.

## Совместимость

HTTP требует Tasks 0.3.0+ с возможностью `cli-http-v1`. При обновлении оркестратор
перезапускает сервер: уже запущенный процесс продолжает использовать загруженный код.
CLI требует Node.js 22+, установщик Skills 1.5.26 — Node.js 22.20+; рекомендуется 24.

См. [CLI](CLI.md) и [восстановление](RECOVERY.md).
