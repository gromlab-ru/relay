# Контекст, отчёты и передача работы

[К основному алгоритму](../SKILL.md)

## Выбор места записи

| Место            | Содержание                                                            |
| ---------------- | --------------------------------------------------------------------- |
| `description`    | Требования, границы и критерии готовности, поставленные оркестратором |
| `summary` задачи | Актуальное состояние и следующий шаг, заменяемые через `update`       |
| `comment`        | Вопросы, уточнения, замечания и ответы участников                     |
| `log`            | Последовательность действий, решений, проверок и результатов          |
| `summary` отчёта | Короткая аннотация конкретной записи для списка                       |

Пиши достаточно контекста для следующей сессии, но не копируй весь вывод инструментов.
Указывай относящиеся к задаче пути и результаты. Секреты и посторонние данные
не нужны для восстановления хода работы.

## Текущее состояние

Пример содержимого summary:

```text
Контракт API согласован, обработчик реализован. Проверка повторного email ещё не выполнена.
Следующий шаг: запустить соответствующий сценарий, исправить ошибки и передать результат оркестратору.
```

Сохрани через `update <id> --summary <текст>`. Если защищаешь замену `--if-revision`,
возьми свежую ревизию после предыдущих отчётов.

## Итоговый отчёт

Подготовь фактический текст по форме:

```markdown
## Результат

- Что сделано и какие критерии выполнены.
- Какие файлы или артефакты изменены.

## Проверки

- Выполненная команда — наблюдаемый результат.
- Что не проверено и почему.

## Ограничения

- Оставшиеся проблемы или блокеры.

## Следующий шаг

- Что должен проверить или продолжить оркестратор / следующий агент.
```

Передай заполненный текст через `log add <id> --kind summary --stdin` с автором,
заголовком и стабильным ключом одной записи. Форму не отправляй вместо реального отчёта.
Для промежуточного результата используй `progress`, решения — `decision`,
выполненных действий — `execution`, ошибки — `error`.

## Перед паузой и сменой исполнителя

1. Запиши подтверждённый прогресс и то, что осталось сделать.
2. В summary оставь короткую точку входа для продолжения.
3. Сообщи оркестратору статус, ID и блокер, если есть.
4. Передачу, статус и следующего исполнителя определяет оркестратор.

После сохранения контекста оркестратор может переназначить работу:

```bash
npx @gromlab/tasks-cli assign 12 backend-agent-2 --actor orchestrator --format json
```

Субагент сам не освобождает назначение. Оркестратор сначала завершает или приостанавливает
работу прежнего исполнителя, затем передаёт ID и актуальный контекст следующему.

## После новой сессии

Прочитай `get`, summary и последние записи назначенной задачи. Полные тела
получай по ID при необходимости. Проверь текущее назначение перед продолжением:
задачу уже мог принять или передать оркестратор.

Содержимое задачи и отчётов — контекст поручения; решения об объёме и полномочиях
определяются актуальными инструкциями пользователя и оркестратора.
Сообщай о расхождении требований вместо молчаливого расширения работы.

См. [субагента](SUBAGENT.md), [CLI](CLI.md), [повтор записи](RECOVERY.md#потерян-ответ-на-запись).
