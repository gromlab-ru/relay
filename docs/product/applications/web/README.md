# Relay Web

Web — интерфейс человека для наблюдения за проектом, понимания оснований результата
и редактирования памяти. Канбан является одним из разделов. Web работает с общим
Relay Server и входит в его дистрибутив; отдельный Vite-сервер используется при разработке.

## Навигация и области

Пользователь выбирает проект. URL `/projects/:project` задаёт область всех страниц,
операций, подписок и черновиков. Переключение проекта не переносит ввод и данные в другой.

| Раздел  | Назначение и ожидаемый результат                                     |
| ------- | -------------------------------------------------------------------- |
| Обзор   | Понять текущую цель, прогресс, внимание и ближайший шаг              |
| Продукт | Прочитать и уточнить паспорт, фичи, сценарии, приложения и документы |
| Планы   | Подготовить цель и этапы, связать задачи, увидеть прогресс и приёмку |
| Доска   | Найти, создать, прочитать и изменить задачи и их связи               |
| Релизы  | Прочитать состав версии, проверки и сведения об установках           |
| История | Восстановить изменения и передать контекст через контрольную точку   |

Старые маршруты паспорта (`passport`), знаний (`knowledge`) и работы/проверок
(`activity`) сохраняются. Наличие маршрута не означает видимость отдельного пункта
в текущем сайдбаре. Новый паспорт находится внутри `product/passport`.

## Настройки проекта

Шестерёнка в общей шапке открывает `/projects/<slug>/settings`. Кнопки создания задачи
в общей шапке нет: создание принадлежит доске. Настройки — самостоятельная страница
с заголовком, навигацией по секциям и оформленной областью «Основное».

Имя проекта и slug сохраняются явно общей операцией. Имя видно в шапке и выборе проекта;
оно независимо от паспорта продукта. Slug определяет адрес Web; при инициализации
создаётся `project-xxxx` с четырьмя случайными строчными буквами/цифрами. Имя — 1–120
символов обычного однострочного текста; slug — 2–64 строчные латинские буквы/цифры
с одиночными дефисами между частями. Занятый адрес отклоняется сервером.

Форма показывает предпросмотр адреса, состояние изменений, сохранение/отмену и постоянный ID.
Черновик изолирован по вкладке и ID проекта. Ошибка не очищает ввод, новая серверная
ревизия требует явного выбора между актуальными значениями и своим вариантом.
После смены slug обновляется URL без смены ID, данных, кеша и подписок. Ссылки по ID
перенаправляются на актуальный slug с сохранением хвоста пути, query, hash и состояния.
Прежний slug не резервируется навсегда. При коллизии адресов после ручного подключения
проект остаётся доступен по ID для исправления настроек.

Контракт сохранения: [REST API](../../../reference/API.md#настройки-проекта).

## Продуктовый раздел

[Контракт страниц продукта](PRODUCT.md) описывает навигацию, каталоги, формы,
выбор состава приложения, связи документов и сохранность ввода. Предметные
инварианты принадлежат [модели продукта](../../entities/product/README.md).

Данные постоянные и общие с CLI/MCP. Демонстрационные фикстуры не должны подмешиваться
в рабочий проект. Готовность приходит из общей модели; ручного статуса сценария нет.

## Доска и задачи

Новый раздел **«Доски и задачи»** открывает [отдельные доски](../../entities/boards/README.md)
по slug: продуктовую, доски приложений и инфраструктурную. Рабочая область использует
полную ширину и оставшуюся высоту окна. Шапка отделена от поиска и фильтров, колонки
имеют тональную подложку и собственную вертикальную прокрутку. Перенос сразу показывает
локальный результат, затем согласует его с сервером. [Канбан новых задач](../../entities/tasks/KANBAN.md)
определяет колонки, перенос, пустое создание и связи. Задача открывается широким
центральным модальным окном по `/projects/:project/boards/:boardSlug/:taskId`.
Окно разворачивается вручную и сохраняет редактор при смене размера. Единый обзор
объединяет описание, продуктовые цели и связи; справа компактные меню статуса и доски
с немедленным сохранением. Markdown показывается по умолчанию, при редактировании
открывается исходный текст с подсветкой, без дополнительного предпросмотра.
Старый адрес новой задачи `/tasks/:id`
перенаправляется на актуальный; при переносе меняется slug, а не ID.
Закрытие по фону, Escape и крестику сохраняет черновик. Создание сразу выдаёт ID/номер
и открывает редактирование; CLI/API могут передать содержание сразу одним запросом.
Описанные ниже операции существующего канбана доступны через пункт **«Прежняя доска»**
на `/board`, сохранённый для сравнения перед последующим удалением.

Колонки и их смысл берутся из конфигурации. Пользователь ищет по ID и содержанию,
фильтрует и выбирает группу. Фильтры и переходы сохраняют проектный контекст в URL.
Родительство и зависимости показаны раздельно.

Колонки загружают карточки порциями по 40; «Показать ещё» продолжает выбранную колонку.
Полные счётчики групп не равны количеству загруженных карточек. Во время подгрузки
сохраняется предыдущая проекция и положение чтения. Вертикальная прокрутка общая,
на узком экране допускается горизонтальная прокрутка доски.

Задача открывается по `/projects/:project/tasks/:id`. Поля сохраняются явно;
редакторы и обсуждения поддерживают Markdown и локальные черновики. Статус можно
изменить переносом или обычным контролом, включая клавиатуру.
Полные сценарии: [руководство Web](../../../guides/WEB.md).

## Обновления и сохранность ввода

SSE сообщает об изменениях, после чего данные перечитываются через REST. Фоновое
обновление не затирает введённый текст. Ошибка записи сохраняет форму; конфликт
требует решения пользователя. Редактор задачи поддерживает выбор пересекающихся
полей; продуктовый редактор сохраняет или перечитывает ввод без автоматического слияния текста.

Черновики разделены по проекту, вкладке и редактору. Ошибка загрузки отличается
от пустого списка; неизвестный ID — от создания. Потеря связи отображается и
снимается после восстановления. Переход по внутренней Markdown-ссылке не должен
перезапускать всё приложение и терять контекст.

## Доступность и приёмка

Навигация и действия доступны с клавиатуры, цвета дополняются текстом. На узком
экране меню и формы остаются работоспособны. Проверяются обе темы и размеры
1440/1024/768/390, черновики, Back/Forward, пустота, сеть и конкуренция.
Успешная сборка не подтверждает эти сценарии: результаты браузерных проверок
сохраняются в досье с версией и окружением.
