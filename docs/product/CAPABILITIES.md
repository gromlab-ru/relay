# Карта возможностей Relay

Карта описывает состав продукта, а не очередь автоматического выполнения. Ожидаемое
поведение задают связанные спецификации; покрытие и ограничения — технические карточки.

| Возможность                   | Пользовательский результат                                                        | Приложения            | Спецификация и реализация                                                                                  |
| ----------------------------- | --------------------------------------------------------------------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------- |
| Продуктовая память            | Понять назначение, фичи, сценарии, приложения и связанные документы               | CLI, Server, Web, MCP | [Модель](entities/product/README.md), [реализация](../engineering/implementation/product.md)               |
| Изолированные проекты         | Работать с одной или несколькими базами, не смешивая данные                       | CLI, Server, Web, MCP | [Проекты](entities/projects/README.md), [реализация](../engineering/implementation/applications.md)        |
| Планы и этапы                 | Превратить цель в результаты и отслеживать их выполнение                          | CLI, Server, Web, MCP | [Работа](LIFECYCLE.md), [реализация](../engineering/implementation/lifecycle.md)                           |
| Задачи и зависимости          | Выдать выполнимое поручение, вести обсуждение, отчёт и статус                     | CLI, Server, Web, MCP | [Задачи](entities/tasks/README.md), [реализация](../engineering/implementation/lifecycle.md)               |
| Требования и знания           | Сохранить правила и контекст, необходимые исполнителю                             | CLI, Server, Web, MCP | [Работа](LIFECYCLE.md), [ограничения интеграции](../engineering/implementation/product.md)                 |
| Исполнение и приёмка          | Различать попытку, результат проверки и принятое выполнение                       | CLI, Server, Web, MCP | [Жизненный цикл](LIFECYCLE.md), [реализация](../engineering/implementation/lifecycle.md)                   |
| Восстановление контекста      | Продолжить работу по цели, предыдущим результатам и следующему шагу               | CLI, Server, Web, MCP | [Сквозной процесс](workflows/README.md), [реализация](../engineering/implementation/lifecycle.md)          |
| Релизы и окружения            | Сохранить состав версии, результат установки и ограничения                        | CLI, Server, Web, MCP | [Релизы](LIFECYCLE.md#релизы-и-окружения), [реализация](../engineering/implementation/lifecycle.md)        |
| Совместное чтение и изменение | Видеть внешние изменения и сохранять ввод при конфликте                           | CLI, Server, Web, MCP | [Правила продукта](entities/product/BEHAVIOR.md), [архитектура](../engineering/ARCHITECTURE.md)            |
| Демонстрационная среда        | Использовать текущий Relay на независимых примерах без автоматического наполнения | Playground            | [Контракт](applications/playground/README.md), [реализация](../engineering/implementation/applications.md) |

## Следующее развитие

Связи новых фич, сценариев и контрактов с планами, задачами, приёмками и релизами ещё
требуют проектирования. Отдельный раздел инфраструктуры обсуждается. Подробности и
статус согласования: [DIRECTION.md](DIRECTION.md). Эти пункты не объявляются готовыми
по наличию отдельных экранов или старых проверок.
