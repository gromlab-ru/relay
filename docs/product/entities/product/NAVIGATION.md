# Навигация и карта адресов

[Сущность «Продукт»](README.md) → Навигация

## Место в проекте

Раздел расположен в общем каркасе Relay: шапка, выбор проекта, боковая навигация и область
страницы. У него нет отдельного демонстрационного приложения или адреса `/demo/product`.

```text
Обзор
Продукт
├── Паспорт
├── Возможности
├── Приложения
└── Документы
Планы
Доска задач
Релизы
История
```

«Продукт» — раскрываемая группа. Вход в любой его адрес раскрывает и выделяет группу.
У паспорта, возможностей, приложений и документов выделяется соответствующий подраздел,
в том числе при открытии редактора или страницы записи. У `product/work/:workId` отдельного
пункта нет: активной остаётся группа продукта.
«Документы» — последний подраздел. На узком экране навигация открывается кнопкой в шапке
и закрывается после выбора ссылки, в том числе клавиатурой.

«Требования и знания» (`knowledge`) и «Работа и проверки» (`activity`) скрыты только в сайдбаре.
Их страницы и маршруты сохранены. «История» — краткое название пункта навигации;
оно не удаляет сценарий передачи контекста. Старая страница паспорта остаётся по адресу
`/projects/:project/passport`; совместимость с ней рассматривается в D-01.

## Маршруты

Во всей таблице префикс `P` означает `/projects/:project/product`, где `:project` — выбранный
проект Relay. Параметры ID не выводятся из названий записей.

| Адрес                                              | Экран / поведение                                          |
| -------------------------------------------------- | ---------------------------------------------------------- |
| `P`                                                | Перенаправление на `P/passport` с заменой записи истории   |
| `P/passport`                                       | [Паспорт](pages/passport.md)                               |
| `P/passport/edit`                                  | [Заполнение / редактор паспорта](pages/passport-editor.md) |
| `P/features`                                       | [Возможности](pages/features.md)                           |
| `P/features/new`                                   | [Создание фичи](pages/feature-editor.md)                   |
| `P/features/:featureId`                            | [Фича и сценарии](pages/feature.md)                        |
| `P/features/:featureId/edit`                       | [Редактирование фичи](pages/feature-editor.md)             |
| `P/features/:featureId/scenarios/new`              | [Создание сценария](pages/scenario-editor.md)              |
| `P/features/:featureId/scenarios/:scenarioId/edit` | [Редактирование сценария](pages/scenario-editor.md)        |
| `P/applications`                                   | [Приложения](pages/applications.md)                        |
| `P/applications/new`                               | [Создание приложения](pages/application-editor.md)         |
| `P/applications/:applicationId`                    | [Приложение](pages/application.md)                         |
| `P/applications/:applicationId/edit`               | [Редактирование приложения](pages/application-editor.md)   |
| `P/applications/:applicationId/scope`              | [Состав реализации](pages/application-scope.md)            |
| `P/documents`                                      | [Библиотека](pages/documents.md)                           |
| `P/documents/new`                                  | [Создание документа](pages/document-editor.md)             |
| `P/documents/:documentId`                          | [Чтение документа](pages/document.md)                      |
| `P/documents/:documentId/edit`                     | [Редактирование документа](pages/document-editor.md)       |
| `P/work/:workId`                                   | [План, этап или задача прототипа](pages/work.md)           |

В роутере редакторы фич и приложений покрываются общей веткой `:collection/:entityId/edit`.
Это техническое переиспользование, а не возможность редактировать произвольную коллекцию.
Редактор отвергает неизвестные виды записей.

## Параметры представления

| Страница            | Параметры                                                                                                     |
| ------------------- | ------------------------------------------------------------------------------------------------------------- |
| Возможности         | `q` — запрос; `status` — `none / partial / done`; `app` — приложение                                          |
| Дерево возможностей | Повторяемый `open` — раскрытые фичи без поиска; повторяемый `closed` — вручную закрытые совпадения при поиске |
| Приложение          | Повторяемый `open` — раскрытые фичи приложения                                                                |
| Состав реализации   | `feature`, необязательный `scenario` — начальная область редактирования                                       |
| Документы           | `q`, `kind`, `scope`, `sort` — запрос, тип, область и сортировка                                              |

Фильтры списка и раскрытие дерева входят в URL. Изменение поискового текста заменяет текущую
запись истории, а не создаёт запись на каждую букву. Фильтры должны переживать обновление
страницы и возврат из карточки. Поиск в редакторе состава и в модальном выборе связей локальный,
он не заменяет сохранённые значения формы.

## Якоря

| Якорь                                         | Назначение                           |
| --------------------------------------------- | ------------------------------------ |
| `#scenarios`                                  | Список сценариев фичи                |
| `#scenario-:scenarioId`                       | Конкретный сценарий на странице фичи |
| `#feature-work`                               | Связанная работа фичи                |
| `#application-features`                       | Дерево реализации приложения         |
| `#application-feature-:featureId`             | Общий вклад приложения в фичу        |
| `#application-feature-:featureId-:scenarioId` | Вклад приложения в сценарий          |

Ссылка на сценарий использует его постоянный ID, не Markdown-заголовок. Переход должен
показать и сфокусировать нужный раздел; фиксированная шапка не должна закрывать его.
Без существующей цели фокус остаётся на заголовке страницы. Выбор нового формата ID требует
проверить однозначность составных якорей и кодирование URL.

## Возврат к контексту

- Из каталога фич в карточку передаются фильтры и раскрытие; обратный переход восстанавливает их.
- Из фичи в приложение передаётся адрес фичи. Приложение открывается у нужного вклада
  с раскрытой веткой.
- Из дерева приложения название открывает редактор вклада, отдельная иконка — исходную
  фичу или сценарий. Оба перехода сохраняют адрес приложения с раскрытием и якорем.
- Из библиотеки в чтение, затем в редактор и обратно сохраняется адрес библиотеки с фильтрами.
- Связанная работа сохраняет исходный продуктовый контекст при переходах по плану, этапам
  и задачам; ссылки на фичи и приложения позволяют вернуться к работе.
- После успешной записи редактор открывает подтверждённый результат; новая запись не остаётся
  на адресе `new`. Точное направление описано у каждой формы.

Прототип переносит `returnTo` в состоянии React Router и принимает его только внутри `P`
текущего проекта. При прямом URL или отсутствии состояния используются осмысленные запасные
адреса: каталог, родительская фича, приложение или паспорт. Закладка не обязана содержать
историю предыдущей вкладки.

В моках контекст возврата сохраняется не по всем длинным цепочкам редакторов одинаково.
При интеграции проверять полный путь, а не только отдельный переход. Область `returnTo`
при подключении настоящих планов и задач требует [D-06](OPEN_QUESTIONS.md#d-06-связи-с-работой).
