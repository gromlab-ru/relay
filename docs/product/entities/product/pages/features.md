# Каталог «Возможности»

[Сущность «Продукт»](../README.md) → Возможности

**Адрес:** `/projects/:project/product/features`.

## Назначение и состав

Показать устойчивую декомпозицию продукта: фичи и конкретные сценарии каждой из них.
Заголовок страницы — «Возможности», действие создания — «Добавить фичу».

Основное представление — двухуровневое дерево. Строка фичи показывает название, краткий смысл,
вычисленный индикатор и число готовых сценариев. У фичи без сценариев есть пояснение
«Сценарии не описаны». Строка сценария показывает его название и собственный индикатор.
Линии и отступы связывают сценарий с родителем.

Над деревом находятся поиск, фильтры, «Фичи: N из M», легенда трёх состояний и одно действие
раскрытия. Произвольных подфич, папок и групп на этом экране нет.

## Действия дерева

- Изначально все фичи свёрнуты. Сохранённый `open` восстанавливает выбранные ветки.
- Клик по блоку фичи или стрелке переключает раскрытие.
- Клик по названию фичи открывает её страницу и не переключает ветку.
- Название сценария открывает страницу родителя на `#scenario-:scenarioId`.
- Если хотя бы одна видимая ветка раскрыта, общее действие — «Свернуть все»; иначе —
  «Раскрыть все». При отсутствии дочерних узлов оно недоступно.
- Enter на узле фичи переключает раскрытие; на узле сценария открывает его раздел.
  Доступные ссылки и кнопки сохраняют собственное клавиатурное действие.

## Поиск и фильтры

| Условие             | Точная семантика                                                                 |
| ------------------- | -------------------------------------------------------------------------------- |
| `q`                 | Без учёта регистра, с удалением внешних пробелов                                 |
| Совпадение фичи     | Название или краткий смысл; показывает всю фичу со всеми сценариями              |
| Совпадение сценария | Название или Markdown-описание; показывает совпавшие сценарии вместе с родителем |
| `status`            | Готовность фичи целиком по полному составу; не фильтр отдельных сценариев        |
| `app`               | Фича, участие в которой объявило выбранное приложение                            |

Полный Markdown фичи в текущий поиск не входит. Фильтр приложения отбирает фичи,
но не обрезает их до выбранных приложением сценариев: каталог остаётся общим продуктовым
контрактом. Все условия применяются совместно.

При непустом поиске совпавшие ветки раскрываются; вручную закрытые записываются в `closed`.
Изменение `q` сбрасывает исключения раскрытия. После очистки запроса дерево снова свёрнуто.
Сброс фильтров удаляет запрос, фильтры и параметры раскрытия.

Число N — число найденных **фич**, M — весь каталог. Готовность и «Готово N из M» внутри
фичи используют полный состав, даже если поиск оставил одного видимого ребёнка.
Порядок фич и сценариев следует данным; ручная сортировка в UI не реализована.

## Состояния и переходы

- Нет фич вообще: «Фич пока нет», пояснение и действие создания первой фичи.
- Фичи есть, но не подходят: «Фичи не найдены» и «Показать все фичи».
- Из карточки возврат восстанавливает query-параметры и раскрытие.
- «Добавить фичу» открывает `features/new`. Создать её можно без приложений и запланированной работы.

## Критерии приёмки

1. Поиск по тексту сценария сохраняет название родителя и не меняет его готовность.
2. Фильтры статуса и приложения комбинируются с поиском по описанным правилам.
3. Стрелка, блок и ссылка не вызывают два действия за один клик; возврат и reload сохраняют URL-состояние.
4. Пустой каталог, пустая выдача и фича без сценариев различаются.
