# Создание и редактирование фичи

[Сущность «Продукт»](../README.md) → Редактор фичи

**Создание:** `/projects/:project/product/features/new`.
**Изменение:** `/projects/:project/product/features/:featureId/edit`.

## Назначение и поля

Форма задаёт смысл устойчивой возможности. При создании заголовок — «Новая фича»,
при изменении — «Редактирование: название».

| Поле                | Ожидаемое содержание                                     | Обязательность |
| ------------------- | -------------------------------------------------------- | -------------- |
| Название            | Понятное имя возможности                                 | Да             |
| Краткий смысл       | Пользовательский результат, одна фраза для каталога      | Да             |
| Описание в Markdown | Назначение, общие правила, ожидаемое поведение и границы | Да             |

Готовность не редактируется: форма объясняет расчёт по сценариям. Сценарии добавляются
на странице фичи, а участие приложений — в редакторе состава приложения.

## Поведение

- Создание выдаёт новый стабильный ID и фичу без сценариев. Начальная вычисленная готовность —
  `none`, с пояснением об отсутствии сценариев.
- Изменение сохраняет ID, сценарии и все отношения. Оно не заменяет фичу новым объектом
  в предметном смысле и не переписывает тексты вкладов.
- Успех открывает страницу сохранённой фичи. При переданных query-параметрах сохраняется
  контекст каталога.
- Отмена создания возвращает в каталог, отмена изменения — к фиче. Ввод удаляется только
  по [общим правилам подтверждения](../COMMON_BEHAVIOR.md).
- Неизвестный ID при редактировании не открывает пустую форму создания.

## Требования перехода

В операции реального ядра обновление должно требовать существующую фичу и прочитанную ревизию.
Моковый helper способен добавить запись, если ID не найден; это не разрешение воссоздавать
исчезнувшую фичу после конкурентного изменения.

## Критерии приёмки

1. Новая фича видна в каталоге и доступна в выборе состава приложения без создания задач.
2. Редактирование имени/Markdown не меняет ID, сценарии, вклад и статус другого приложения.
3. Обязательные поля, предпросмотр, черновик, отмена и конфликт работают по общим правилам.
4. Неизвестная или исчезнувшая фича не создаётся повторно сохранением старого редактора.
