# Фича и её сценарии

[Сущность «Продукт»](../README.md) → Фича

**Адрес:** `/projects/:project/product/features/:featureId`.
**Сценарий:** тот же адрес с `#scenario-:scenarioId`.

## Назначение

Объяснить общий контракт возможности до открытия задач: назначение, ожидаемое поведение,
сценарии, участвующие приложения и историю работы. Фича остаётся одной и той же между планами.

## Состав страницы

1. Название, краткий смысл, «Редактировать» и возврат к исходному контексту.
2. Готовность по всем сценариям. Для пустого состава — «Сценарии не описаны».
3. Ссылка к работе: «Текущих задач нет» либо «Текущая работа · N».
4. Основной Markdown «Назначение и ожидаемое поведение».
5. «Сценарии фичи»: число готовых из полного состава, «Добавить сценарий», отдельные секции.
6. «Реализация по приложениям»: обратная проекция выбранного участия.
7. [Связанная работа](work.md), сгруппированная по планам и этапам.

N текущих задач в моках — число связанных задач, чей статус не `done`, включая запланированные.
Это не число запущенных агентов. Для настоящих задач нужна семантика их реальных статусов.

## Секция сценария

Каждый сценарий имеет собственные ID, название, Markdown и готовность; отображается полноценным
разделом страницы с заголовком, индикатором, постоянной ссылкой и действием редактирования.
Это не заголовок, вырезанный из общего Markdown фичи.

- Постоянная ссылка использует ID и остаётся прежней после переименования.
- «Редактировать сценарий» открывает его отдельный редактор.
- «Добавить сценарий» создаёт запись внутри текущей фичи.
- Нет сценариев: пояснение и доступное действие добавления; фича не считается готовой.
- При адресном входе секция получает фокус и прокрутку с учётом шапки.

## Реализация по приложениям

Для каждого участвующего приложения показываются имя, тип, **статус общего вклада**, число
выбранных сценариев и заголовок вклада. Полный Markdown вклада находится в редакторе состава
приложения; собственное описание фичи не заменяется текстом приложения.

Ссылка открывает приложение у нужной фичи с раскрытием ветки и обратным адресом.
Если участия нет, текст предлагает выбрать фичу на странице нужного приложения.
Прямого редактора состава всех приложений из этой панели нет.

## Возврат и состояния

- Из каталога — возврат к списку с прежними фильтрами и раскрытием.
- Из приложения — «Назад к приложению», из работы — «Назад к работе».
- Неизвестная фича — «Фича не найдена» и переход в каталог.
- Отсутствие работы или участников не скрывает описание и сценарии.

При переходе на реальные данные нужно сохранить различие общего контракта, вкладов и
подтверждений готовности. Обратные документы у фичи и сценариев — отдельная будущая
проекция, размещение которой определяется D-05.

## Критерии приёмки

1. Редактирование сценария меняет его секцию и вычисляемую готовность родителя.
2. Ссылка сценария работает после переименования и при прямом открытии.
3. Из приложения открывается общий контракт, затем пользователь возвращается к нужному вкладу.
4. На странице одновременно видны текущая работа и результаты прежних планов без смешивания статусов.
