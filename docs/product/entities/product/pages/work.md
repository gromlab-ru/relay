# Связанная работа: планы, этапы и задачи

[Сущность «Продукт»](../README.md) → Связанная работа

**Адрес чтения в прототипе:** `/projects/:project/product/work/:workId`.
Один экран показывает план, этап или задачу по виду найденной записи.

## Назначение

Показать, что меняется сейчас, откуда появился существующий результат и какие работы
разных циклов относятся к устойчивой фиче или приложению. Пользователь сначала читает
краткий результат, затем углубляется в постановку и подробности.

## Блок на странице фичи или приложения

«Связанная работа» показывает подходящие задачи с группировкой по этапам и планам.
В карточке задачи видны название, статус, краткий результат и ссылка на подробности.
У плана есть название и обозначение цикла, у этапа — ссылка на его описание.
Незавершённые планы показаны раньше завершённых.

В текущем моковом алгоритме:

- отбираются задачи со ссылкой на фичу или приложение текущей страницы;
- если заданы оба условия, задача должна соответствовать обоим;
- затем по `parentId` находятся их этапы и планы;
- записи планов/этапов без подходящих задач не образуют отдельную группу;
- при отсутствии подходящих задач показано «Работа ещё не запланирована».

Это описание исходной реализации. Оно не разрешает терять в реальной модели задачу без
этапа/плана или работу, привязанную к сценарию. Такие случаи нужно охватить при D-06.

## Страница работы

| Область           | Содержание                                         |
| ----------------- | -------------------------------------------------- |
| Заголовок         | Вид записи, название, краткий смысл и статус       |
| Родитель          | «В составе: …», если есть родительский этап/план   |
| Краткий результат | Читаемый итог или ближайший ожидаемый результат    |
| Подробности       | Полный Markdown постановки/результата              |
| Дети плана        | «Этапы плана» со ссылками и краткими результатами  |
| Дети этапа        | «Задачи этапа» со ссылками и краткими результатами |
| Контекст продукта | Ссылки на связанные фичи и приложения              |

Это страница чтения; редактора работы в новом продуктовом прототипе нет.
У задачи не создаётся фиктивная отдельная страница продукта или копия сценария.

## Навигация и состояния

- Из фичи, приложения или паспорта сохраняется адрес исходного контекста.
- Переходы по родителю и детям сохраняют возможность вернуться к нему.
- Ссылки на фичи/приложения передают обратный адрес текущей работы.
- Прямой вход без контекста возвращает к паспорту.
- Нет записи: «Работа не найдена» и предложение открыть фичи.

## Что в моках условно

`ProductWork` использует строковые ID, `parentId`, наборы `featureIds`/`applicationIds`,
Markdown, краткий результат и три статуса: `planned`, `active`, `done`.
Это демонстрация связи, не новая постоянная система задач.

В карточке плана мок помечает любой незавершённый план как «Текущий план», а паспорт берёт
первый активный. В реальной реализации нужно различать настоящий фокус, запланированное,
паузу, отмену и завершение по существующей модели.

## Требования перехода

- Использовать настоящие планы, этапы и задачи Relay и их существующие подробности.
  Не переносить `snapshot.work` в отдельную параллельную базу.
- Согласовать типизированные ссылки на фичи, сценарии и приложения. Обобщённая задача может
  относиться к фиче целиком; техническая работа может обходиться без искусственной фичи.
- Фича агрегирует связанную работу своих сценариев без дублирования одной задачи.
- Сохранять результаты прежних циклов и различать готовность поведения и состояние текущей задачи.
- Статусы настоящих задач учитывать через конфигурацию проекта, а не через моковые три значения.
- Определить адреса и возврат при переходе на существующие `/plans/:planId` и `/tasks/:id`.
  Наличие `product/work/:workId` сейчас не требует сохранить вторую сущность работы навсегда.

Схема связей, показ задач без плана и окончательная маршрутизация —
[D-06](../OPEN_QUESTIONS.md#d-06-связи-с-работой).

## Критерии приёмки

1. Из фичи и приложения доступны подходящие текущие задачи и результаты завершённых планов.
2. Переходы между планом, этапом, задачей и продуктом сохраняют понятный возврат.
3. Завершение работы не пересоздаёт фичу и не уничтожает её историю.
4. После реальной интеграции нет второй копии задач; задача без плана остаётся видимой.
