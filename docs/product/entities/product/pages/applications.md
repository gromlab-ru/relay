# Каталог приложений

[Сущность «Продукт»](../README.md) → Приложения

**Адрес:** `/projects/:project/product/applications`.

## Назначение

Показать логические программные части продукта по их ответственности и открыть нужное
приложение. Например, пользовательский веб, backend API и административное приложение.

## Состав страницы

Заголовок «Приложения», пояснение о выборе фич и сценариев, действие «Добавить приложение»
и сетка карточек. В карточке:

- название;
- тип приложения;
- краткое назначение;
- число выбранных фич;
- число выбранных сценариев;
- подсказка начать с выбора состава, если участия ещё нет.

Вся карточка открывает страницу приложения. Счётчик фич равен числу его общих вкладов,
сценариев — сумме выбранных сценарных вкладов. Не выбранные приложением сценарии
и общее число сценариев продукта в эти счётчики не входят.

Общего статуса готовности приложения на карточке нет. Поиск, сортировка и фильтр типов
для этого каталога в текущем UI не предусмотрены; порядок следует данным.

## Действия и состояния

- «Добавить приложение» открывает `applications/new`.
- После создания приложение допустимо без состава; следующий шаг — выбрать фичи и сценарии
  на его странице.
- Если приложений нет, показаны «Приложений пока нет», пояснение и создание первого приложения.
- Каталог доступен до создания фич и планов: отсутствие этих данных не блокирует создание приложения.

## Критерии приёмки

1. Новое приложение появляется с нулевыми счётчиками и подсказкой следующего действия.
2. Сохранённый состав немедленно отражается в обоих счётчиках.
3. Длинные названия и краткие описания читаются в карточках на узком экране.
4. Изменение приложения не меняет записи соседних приложений и регистраций проектов.
