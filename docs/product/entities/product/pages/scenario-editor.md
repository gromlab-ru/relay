# Создание и редактирование сценария

[Сущность «Продукт»](../README.md) → Редактор сценария

**Создание:** `/projects/:project/product/features/:featureId/scenarios/new`.
**Изменение:** `/projects/:project/product/features/:featureId/scenarios/:scenarioId/edit`.

## Назначение и контекст

Сценарий раскрывает одно конкретное поведение внутри фичи: действие, условия и наблюдаемый
результат. Форма показывает имя родительской фичи. Отдельного свободного сценария без родителя
или выбора другой фичи в редакторе нет.

## Поля

| Поле                | Правило                                                           |
| ------------------- | ----------------------------------------------------------------- |
| Название            | Обязательно; описывает конкретный сценарий                        |
| Готовность сценария | `none / partial / done`; при создании `none`                      |
| Описание в Markdown | Обязательно; поведение, результат, ограничения и условия проверки |

У сценария нет поля «Краткий смысл». Ручной выбор готовности — действующее поведение мока;
при переходе к агрегации по приложениям поле и операция пересматриваются только после
[D-02](../OPEN_QUESTIONS.md#d-02-основание-общей-готовности).

## Сохранение и возврат

- Создание добавляет сценарий в текущую фичу со стабильным ID. В существующие приложения
  он автоматически не включается.
- Изменение сохраняет ID и родителя, а также чужие описания и статусы реализаций.
- В ручном режиме сохранение статуса сразу отражается на рассчитанной готовности фичи,
  счётчиках и карте паспорта.
- Успех открывает страницу фичи на `#scenario-:scenarioId`; имеющиеся фильтры каталога
  сохраняются в адресе.
- Отмена нового сценария возвращает к `#scenarios`, изменение — к секции этого сценария.
- Черновик разделён по проекту, родительской фиче и сценарию/режиму создания.

Если родитель или редактируемый сценарий не существует, показывается отсутствие записи.
Сохранение не должно перемещать сценарий, создавать другую фичу или восстанавливать удалённый ID.

## Критерии приёмки

1. Создание двух сценариев разных фич не смешивает их черновики и принадлежность.
2. Новый незавершённый сценарий меняет готовую фичу на промежуточную по текущей формуле.
3. Переименование сохраняет прямую ссылку и участие приложений.
4. После записи нужная секция видна; ошибку родителя или версии можно исправить без потери ввода.
