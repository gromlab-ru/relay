# Редактор состава реализации приложения

[Сущность «Продукт»](../README.md) → Состав реализации

**Адрес:** `/projects/:project/product/applications/:applicationId/scope`.
**Начальная область:** `?feature=:featureId&scenario=:scenarioId`; `scenario` необязателен.

## Назначение

Объявить, что приложение берёт на себя, и описать реализацию каждого выбранного контракта.
Одна форма сохраняет **весь состав одного приложения**, а не только открытый справа вклад.

## Компоновка

На широком экране две области:

1. «Выберите состав»: дерево всех фич и сценариев, поиск, переключатель «Все фичи / Выбранные».
2. «Опишите вклад»: выбранный элемент, общий исходный контракт и поля собственного вклада.

На узком экране области показываются последовательно. Выбор элемента открывает его редактор;
«К выбору фич и сценариев» возвращает к дереву и восстанавливает фокус. Переключение не теряет ввод.

Внизу — количество выбранных фич и сценариев, состояние несохранённых изменений, «Отмена»
и «Сохранить состав». При прямом входе с `feature` открывается соответствующий редактор;
без него начальная цель берётся из текущего состава, затем из каталога.

## Три разных действия узла

- **Чекбокс** включает элемент в реализацию.
- **Название** открывает вклад для чтения/редактирования, не включая его само по себе.
- **Стрелка** раскрывает ветку. Enter на узле открывает описание.

У включённых элементов показываются индикаторы готовности. Если нет обязательного заголовка
или текста, дерево подсказывает «Нужно описание вклада».

## Правила выбора

| Действие                 | Эффект                                                     |
| ------------------------ | ---------------------------------------------------------- |
| Включить фичу            | Включить общий вклад; сценарии автоматически не выбираются |
| Включить сценарий        | Включить его и родительскую фичу                           |
| Снять сценарий           | Исключить только его; общий вклад остаётся                 |
| Снять фичу               | Исключить фичу и все её сценарии из отправляемого состава  |
| Выбрать все сценарии     | Включить фичу и все её сценарии, даже скрытые поиском      |
| Не выбрать ни одной фичи | Допустимый пустой состав приложения                        |

Временное снятие сохраняет заголовок, Markdown и статус в черновике. Повторное включение
в той же форме восстанавливает эти значения, но включение самой фичи не восстанавливает
автоматически снятые чекбоксы её сценариев. После успешного сохранения невыбранные элементы
не являются частью подтверждённого состава; хранение их истории определяется D-04.

## Поиск и переключение

Поиск без учёта регистра сопоставляет названия фич и сценариев. Совпадение фичи показывает её
доступных детей, совпадение сценария сохраняет родительский контекст. При вводе поиска ветки
раскрываются. «Выбранные» ограничивает дерево включёнными фичами и сценариями.

Фильтр не снимает выбор и не удаляет ввод. «Выбрать все сценарии» не ограничивается видимой
выдачей. Поиск, режим и текущий элемент — состояние редактора; query-параметры адреса задают
начальную цель, а не отдельные серверные записи.

## Поля вклада

| Поле                         | Правило                                                                |
| ---------------------------- | ---------------------------------------------------------------------- |
| Заголовок вклада             | Обязательная короткая фраза о реализации; видна под исходным названием |
| Готовность в этом приложении | `none / partial / done`, независимо от других вкладов                  |
| Описание вклада в Markdown   | Обязательный полный контракт части приложения                          |

Раскрываемое «Исходное описание в продукте» доступно рядом. Оно читается из общей фичи
или сценария и не редактируется здесь. Для невыбранного элемента поля вклада отключены,
но источник можно читать; «Включить в реализацию» включает его по тем же правилам.

Хорошее описание вклада объясняет цель, объём реализации, границы ответственности, данные
и взаимодействия, ошибки/повторы, способы проверки и критерии готовности. Это рекомендации
к качеству содержания, а не обязательные шаблонные заголовки или автоматическая генерация текста.

## Проверка и запись

- Заголовок и описание требуются у каждой включённой фичи и каждого включённого сценария.
  У скрытого поиском выбранного элемента требования те же.
- Первая ошибка открывает нужный вклад и фокусирует его поле; пользователь видит, что дополнить.
- Операция проверяет существование приложения, фич и сценариев, правильность родителя,
  отсутствие повторов и актуальность версии.
- Весь выбранный состав применяется атомарно. Общие сценарии и другие приложения не изменяются.
- Изменение статуса вклада в текущем режиме не изменяет общий продуктовый статус.
- После успеха открывается приложение у исходного дерева/вклада; после отказа сохраняется весь ввод.
- Отмена и конфликт действуют по [общим правилам](../COMMON_BEHAVIOR.md), включая сопоставление
  черновика с актуальным каталогом по ID.

При исчезновении цели в реальных данных нужно явно показать конфликт состава и сохранить текст
для разрешения. Простое отбрасывание неизвестных ID при восстановлении мока не задаёт правило
работы с пользовательскими данными.

## Состояния

Неизвестное приложение даёт сообщение и ссылку в каталог. Пустое дерево или отсутствие совпадений
объясняют отсутствие подходящих элементов. Без текущего элемента правая область предлагает
выбрать фичу или сценарий. Ошибка сохранения и конфликт версии не закрывают редактор.

## Критерии приёмки

1. Все действия таблицы выбора работают независимо от поиска и не смешиваются со сменой готовности.
2. Тексты и статусы сохраняются при переключении элемента, временном снятии, reload и уходе с черновиком.
3. Незаполненный выбранный вклад блокирует всю запись; отказ не оставляет частично сохранённого состава.
4. Успех обновляет каталог приложений, дерево и обратную панель фичи из одних отношений.
5. На мобильном можно выбрать, заполнить, вернуться к дереву и сохранить весь состав клавиатурой.
