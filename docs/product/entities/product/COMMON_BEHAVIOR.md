# Общее поведение страниц и редакторов

[Сущность «Продукт»](README.md) → Общее поведение

Эти требования применяются ко всем страницам далее. Специфичные поля, переходы и ограничения
описаны у соответствующего экрана.

## Чтение и состояния

| Состояние                          | Ожидаемое поведение                                                                         |
| ---------------------------------- | ------------------------------------------------------------------------------------------- |
| Первая загрузка                    | Понятное ожидание данных продукта; пустая библиотека не показывается до ответа              |
| Ошибка чтения                      | Сообщение о недоступности и повтор чтения; ошибка не трактуется как отсутствие записей      |
| Действительно пустой раздел        | Объяснение назначения и действие создания, если оно есть у страницы                         |
| Пустой результат поиска            | Данные существуют; предлагается изменить или сбросить фильтры                               |
| Неизвестная запись                 | Сообщение «не найдена» и путь к родителю или каталогу                                       |
| Повторная загрузка реальных данных | Подтверждённое содержимое не заменяет изменённый ввод и не сбрасывает контекст пользователя |

После перехода заголовок документа браузера отражает страницу: «Название · Продукт · Relay».
Фокус попадает на заголовок или адресованный якорем раздел. Возврат восстанавливает состояние
списка и позицию по правилам [навигации](NAVIGATION.md).

## Markdown

Описания паспорта, фич, сценариев, приложений и вкладов, а также тексты библиотеки используют
одинаковое чтение Markdown. В редакторе есть вкладки «Текст» и «Просмотр». Предпросмотр
показывает актуальный введённый текст и не означает его сохранение.

Нужно сохранять заголовки, списки, чек-листы, таблицы, ссылки, цитаты и блоки кода. Служебные
метаданные — ID, типы, статусы и отношения — не извлекаются из текста. Рекомендации к структуре
описания помогают автору, но отсутствие конкретного Markdown-заголовка не делает запись невалидной.

## Жизненный цикл редактора

1. По ID загружается актуальная запись; новая форма получает определённые пустые значения
   и значения по умолчанию. Поздний ответ не должен перезаписывать уже начатый ввод.
2. Если для этой записи и проекта есть корректный локальный черновик, форма восстанавливает
   его и явно сообщает об этом. Черновик содержит исходную ревизию.
3. Ввод меняет форму и черновик, но не подтверждённую модель продукта.
4. Обязательность проверяется при потере фокуса и отправке. Пробельное значение не считается
   заполненным. Первая ошибка получает фокус; скрытое поле Markdown должно стать доступным
   во вкладке текста.
5. «Сохранить» или `Ctrl/⌘ + Enter` выполняет явную запись. Во время отправки поля и повторная
   отправка блокируются. Сочетание не должно обходить открытый диалог подтверждения.
6. После успеха удаляется соответствующий черновик, появляется краткое уведомление и открывается
   подтверждённая запись или контекст. В прототипе уведомление находится сверху по центру
   и автоматически закрывается через 2,5 секунды.
7. После отказа форма, выбранные связи, Markdown и исходная ревизия остаются доступными.
   Ошибка показывается рядом с действием сохранения, повтор разрешён.

Для реальной записи уведомление об успехе допускается только после подтверждения операции.
Локальное сохранение черновика и отправка запроса не являются успехом сохранения сущности.

## Черновики и уход

Черновики изолированы по проекту, виду редактора и записи; у сценария учитывается родительская
фича, у состава реализации — приложение. Несохранённое создание одной сущности не становится
черновиком другой. В текущем UI они живут в `sessionStorage` этой вкладки и переживают её reload.

- Индикатор различает «Изменений нет» и «Есть несохранённые изменения».
- Переход на другую страницу с вводом открывает диалог: «Остаться» либо «Перейти с черновиком».
  Во втором случае пользователь может вернуться и продолжить ввод.
- «Отмена» без изменений возвращает к просмотру. При изменениях требуется подтверждение
  удаления ввода; только оно удаляет черновик и возвращает подтверждённое состояние.
- Ошибка доступа к браузерному хранилищу отображается явно. Переход с черновиком недоступен,
  если его не удалось сохранить; при закрытии/перезагрузке включается предупреждение браузера.
- Сохранённые предметные данные после перехода на сервер должны быть общими для вкладок.
  Изоляция **черновиков** не означает отдельную базу продукта в каждой вкладке.

Восстановление уже закрытой вкладки и перенос черновиков между устройствами не гарантированы
текущим прототипом. Ключи и версии черновиков при переходе на реальные ID требуют согласованной
миграции или явного разделения; нельзя случайно применить моковый черновик к серверной записи.

## Конкурентное изменение

Форма запоминает прочитанную ревизию. Если подтверждённая модель изменилась, UI не заменяет
ввод автоматически и предлагает:

- **«Оставить мой ввод»** — явно продолжить с собственными значениями относительно новой версии;
  это не автоматическая запись. Для состава приложения ввод сопоставляется с текущим каталогом
  по ID.
- **«Загрузить актуальную версию»** — заменить форму подтверждёнными данными и удалить черновик.

Последующее сохранение снова проверяет ревизию. Повторный конфликт остаётся конфликтом;
нажатие «Оставить мой ввод» не разрешает безусловно перезаписывать будущие изменения.
Автоматическое построчное слияние Markdown в данном UI не предусмотрено.

В моках ревизия одна на весь снимок продукта. Требование к реальным данным — защита от потерянных
обновлений; гранулярность версии является [D-03](OPEN_QUESTIONS.md#d-03-ревизии-и-атомарность).
При удалении/изменении доступных целей связи нужно сохранить ввод, объяснить конфликт и
предложить исправление; молчаливое отбрасывание содержимого из формы не является разрешением.

## Доступность и размеры

- Поддерживаются светлая и тёмная темы, ширины 1440 / 1024 / 768 / 390 px.
- Заголовки и длинные названия переносятся, действия доступны на узком экране.
  Таблицы и код не создают горизонтальную прокрутку всей страницы.
- В деревьях раскрытие, переход, включение в состав и статус — отдельные действия.
  Ссылки не переключают раскрытие побочным эффектом.
- Кнопки-иконки имеют доступное имя, у раскрытия указан `aria-expanded`, у фильтров виден выбор.
- Модальные окна удерживают фокус, закрываются по Escape и возвращают фокус вызвавшему действию.
- У закреплённой панели сохранения остаётся место для последнего поля и сообщения об ошибке;
  шапка не перекрывает цель якоря.
- Редактор состава приложения на узком экране последовательно показывает выбор и выбранный
  вклад, сохраняя тексты при переключении.

## Служебные состояния мока

Панель прототипа позволяет включить заполненный/пустой набор, отсутствие результатов,
загрузку, ошибку чтения и однократную ошибку сохранения. Это инструмент воспроизведения
состояний, не настройка продукта.

Сброс после подтверждения восстанавливает исходные данные и меняет `epoch`, делая прежние
черновики неактуальными. У заполненного и пустого наборов отдельное содержимое. Неисправный
моковый снимок может заменяться примером «Напрокат»; для настоящей базы такое поведение
недопустимо: ошибка данных должна оставаться диагностируемой, пользовательские данные сохраняются.

После подключения реального источника служебную панель и сообщения «только в этой вкладке»
нужно убрать из рабочего раздела. Состояния загрузки, ошибки, пустой выдачи и повторения
должны возникать по реальному состоянию операции.
