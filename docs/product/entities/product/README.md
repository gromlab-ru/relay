# Сущность «Продукт»

Продукт описывает, что создают в выбранном проекте Relay, для кого, из каких возможностей
и приложений это состоит и как должно работать. Его описание сохраняется между планами
изменения и служит постоянной основой для человека и агентов.

## Состав спецификации

- [Модель](MODEL.md): паспорт, фичи, сценарии, приложения, контракты и документы.
- [Поведение](BEHAVIOR.md): готовность, изменение состава, связи, конкуренция и чтение.
- [Критерии приёмки](ACCEPTANCE.md): наблюдаемый результат общих сценариев.
- [Web](../../applications/web/PRODUCT.md): страницы, переходы, редакторы и сохранность ввода.
- [Реализация](../../../engineering/implementation/product.md): код, контракты и ограничения.

Предметные правила едины для CLI, REST, MCP и Web. Точный формат операций — в
[справочнике продукта](../../../reference/PRODUCT.md). Прежний прототип сохранён
в [архиве](../../../archive/entities/product/README.md) и не задаёт текущую готовность.

## Основной сценарий

### Идентичность и адресация

ID — постоянная идентичность сущности, все сохранённые связи используют ID. Фичи имеют
ключ FEATURE-N, сценарии SCENARIO-N; приложение первоначально получает свой префикс,
реализации — PREFIX-FI-N и PREFIX-SI-N. Номер реализации первоначально наследуется от
требования, затем ключ хранится независимо. Публичные интерфейсы принимают ключ или ID
в выбранном проекте. Ключ в интерфейсе дополняет название и служит адресом, но не заменяет
внутреннюю идентичность. Коллизия ключа не объединяет записи; доступ по ID остаётся.

Реализация — самостоятельная запись приложения со своей ревизией. Состав приложения
объединяет её с соседними реализациями для редактирования и обзора готовности по задачам. Задачи
и планы ссылаются на ID цели; для выбора загружают краткие сведения, Markdown — по запросу.
Снятие участия сохраняет запись и прежние связи. Требование родительского вклада фичи
для активного сценарного вклада сохраняется.

Оркестратор выбирает проект, читает обзор продукта, уточняет паспорт и возможности,
описывает сценарии, приложения и их вклады, связывает необходимые документы.
Человек и исполнители читают те же сведения через свои интерфейсы.

Для нового проекта допустим пустой продукт. Обзор объясняет отсутствие данных;
система не подмешивает демонстрационные записи и не объявляет пустой продукт готовым.
Дальнейшая связь с планами и задачами описана в [направлении развития](../../DIRECTION.md).
