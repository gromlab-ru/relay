# Готовность: смысл, отображение и расчёт

[Сущность «Продукт»](README.md) → Готовность

## Три отображаемых состояния

| Значение  | Подпись   | Отображение                                              |
| --------- | --------- | -------------------------------------------------------- |
| `none`    | Не готово | Пустой круг с серым контуром                             |
| `partial` | В работе  | Круг с галочкой, приглушённая золотисто-охристая заливка |
| `done`    | Готово    | Круг с галочкой, приглушённая зелёная заливка            |

Это индикаторы, не чекбоксы и не действия смены состояния. Их смысл доступен текстом
или доступным именем, а не только цветом. Обозначения едины в каталоге, на странице фичи,
в дереве приложения и редакторе состава; цвета адаптируются к обеим темам.

«В работе» здесь означает промежуточную готовность. Этот индикатор не доказывает,
что сейчас запущен агент, существует активная задача или открыт план.

## Действующий расчёт прототипа

Сценарий хранит собственный `status`; в моках он задаётся вручную в редакторе сценария.
Новый сценарий получает `none`.

Фича не имеет независимо редактируемого статуса. Её состояние вычисляется по **всем**
текущим сценариям, независимо от фильтра каталога, приложения и раскрытия дерева:

| Набор сценариев                             | Состояние фичи                          |
| ------------------------------------------- | --------------------------------------- |
| Пустой                                      | `none`, пояснение «Сценарии не описаны» |
| Все `done`                                  | `done`                                  |
| Есть `done` или `partial`, но не все `done` | `partial`                               |
| Все `none`                                  | `none`                                  |

Счётчик «Готово N из M» учитывает только `done` в числителе и полный состав сценариев
в знаменателе. В карточке приложения это другой набор: только выбранные **вклады** в сценарии.

Примеры:

- `[done, done]` → фича готова.
- `[done, none]`, `[partial]`, `[partial, none]` → фича в работе.
- `[none, none]`, `[]` → не готова; для пустого состава показывается отдельное пояснение.
- Добавление нового `none` к готовой фиче меняет её на `partial`.
- Поиск, оставивший видимым единственный готовый сценарий, не меняет статус всей фичи.

## Готовность приложения

У приложения нет общего индикатора готовности в текущем UI. Отдельный статус хранится
у каждого его вклада в фичу и каждого вклада в сценарий. При включении нового вклада
начальное состояние — `none`.

Статус общего вклада в фичу сейчас не вычисляется из дочерних вкладов: это самостоятельная
отметка приложения. Поэтому в дереве рядом могут быть статус общего вклада и счётчик готовых
сценариев, описывающие разные факты.

Изменение статуса вклада в моках **не меняет** общий сценарий и рассчитанный статус фичи.
Две области оценки намеренно разделены, пока не согласован следующий расчёт.

## Целевое направление: учёт всех приложений

Зафиксировано направление развития: общий сценарий выполнен на уровне вкладов, когда все
приложения, объявившие участие в нём, завершили свои реализации. Для общего вклада в фичу
также учитываются все участвующие приложения, а фича должна учитывать свои сценарии.

Для непустого набора вкладов ожидается:

- все `done` — выполнено на уровне заявленных вкладов;
- часть выполнена или есть `partial` — промежуточное состояние;
- все `none` — не готово;
- нет участников — отсутствие подтверждения, а не готовность по пустому множеству.

Это ещё не полная формула итоговой готовности продукта. Перед её включением нужно разрешить
[D-02](OPEN_QUESTIONS.md#d-02-основание-общей-готовности): совместный учёт общего вклада и
сценариев, изменение состава участников, новые редакции контрактов, сквозные проверки
и возможность ручной отметки при отсутствии приложений.

Агент не должен одновременно сохранять независимый ручной статус общего сценария и показывать
его как автоматически подтверждённый по приложениям. До решения следует явно сохранять
режим прототипа; после решения — обновить эту спецификацию, операции и все отображения вместе.

## Работа и подтверждения

Закрытая задача, готовый API, завершённый план и проверенный сквозной сценарий — разные факты.
Текущая работа отображается отдельно от готовности. Новый план доработки не обнуляет
существующий результат, но расширение самого описанного состава сценариев влияет на расчёт.

В целевой модели подтверждения связываются с проверенной редакцией, кодом и окружением.
Задачи и поставки не должны автоматически давать `done` без определённого правила проверки
контракта. Конкретный механизм подтверждений остаётся частью D-02.
