# Задачи и поручения

Новая модель: [канбан задач на отдельных досках](KANBAN.md). Далее описаны правила
прежних числовых задач и их интеграции с жизненным циклом.

Задача описывает конкретную работу: цель, содержание, исполнителя, состояние,
связи, обсуждения, результаты и следующий шаг. Это единица исполнения, а не
долговременное описание возможности продукта.

## Правила

- Родительство задаёт декомпозицию; зависимости задают необходимый порядок результатов.
- Статусы и их семантика берутся из конфигурации проекта.
- Отмена не является успешным выполнением зависимости.
- Завершение подзадач само по себе не закрывает родителя.
- Связь с планом задаётся через этап; наследование контекста не заменяет зависимости.
- Отчёт о попытке, готовность задачи и её приёмка различаются.

Подробная каноническая [модель задач](../../../concepts/TASKS.md) сохраняет правила
существующей реализации. [Жизненный цикл](../../LIFECYCLE.md) описывает планы,
проверки и передачу; [руководство](../../../guides/WORKFLOW.md) показывает операции.

## Приёмка сценария

Новый исполнитель должен получить достаточное поручение, увидеть блокеры, сохранить
прогресс и результат, а следующая сессия — восстановить работу. Конфликт записи не
теряет чужие изменения. Невыполненная зависимость препятствует выдаче готовой работы.
Техническое покрытие и границы: [реализация жизненного цикла](../../../engineering/implementation/lifecycle.md).
