# Доски проекта

Доска — область работы внутри одного проекта Relay со своим адресом и контейнером задач.
Она существует и в пустом проекте. Пользователь выбирает её в разделе «Доски и задачи».

## Состав и порядок

1. **Продукт** — общепродуктовые инициативы и работа над продуктом в целом.
2. **Приложения** — по одной доске на каждое приложение, в порядке его создания.
3. **Инфраструктура** — CI/CD, окружения, развёртывание и сопровождение.

Системные доски создаются при инициализации проекта. Создание приложения создаёт его
доску общей операцией ядра, независимо от интерфейса записи. Пустое приложение имеет
полноценную доску. Переименование приложения меняет отображаемое название доски.

## Адрес и идентичность

Доска имеет постоянный ID и уникальный в проекте slug. Web использует
`/projects/:project/boards/:boardSlug`. В текущем Web `:project` — UUID проекта.
Внутренние связи используют ID, а не название или slug.

Slug приложения одновременно задаёт slug его доски. Разрешены строчные латинские
буквы, цифры и разделяющие дефисы, длина 1–64. `product`, `infrastructure`, `new`
зарезервированы. Slug задаётся явно при создании и не меняется при редактировании.
Название может изменяться независимо от адреса.

Неверный slug, повтор занятого адреса и конфликт ревизии дают отказ с сохранением
ввода. Повтор успешного создания с тем же ключом возвращает прежний результат.
Неизвестный адрес доски показывает ошибку, не пустую новую доску.

## Интерфейс и текущая граница

Навигация доступна в постоянном сайдбаре и мобильном меню. Каталог загружается
страницами по 50; «Показать ещё доски» продолжает чтение. Внешние изменения и
восстановление соединения перечитывают каталог. При смене версии продолжение
перезапускается с первой страницы. Ошибка чтения не объявляется отсутствием досок.

На первом этапе экран показывает назначение и пустые колонки из конфигурации проекта.
Создание, карточки, фильтры, перенос и редактор новой модели задач ещё не подключены.
Прежняя доска остаётся отдельным пунктом **«Прежняя доска»** на `/board` для сравнения.
Её удаление требует отдельного подтверждения после сверки функционала.

Новая модель задач разрабатывается следующим этапом. Эпики, их типы и междосочные связи
ещё не определены. Старая общепроектная выборка не подмешивается в новые доски.

## Хранение и приёмка

Каждая доска имеет `.relay/boards/<slug>/board.json` и собственный `tasks/`.
Миграция прежних данных в этом этапе не требуется по решению пользователя.
Точный контракт: [доски: хранение и REST](../../../reference/BOARDS.md).

Проверяются две системные доски при init, создание приложения и доски, повторы,
конкуренция slug, сохранение адреса при переименовании, порядок, прямые ссылки,
Back/Forward, независимость проектов, ошибки, мобильное меню и обе темы.
Результаты: [досье](../../../work/multiple-boards/README.md).
