# Терминальный вывод

По умолчанию CLI выводит оформленный текст. Все представления используют одну
тему: цвет статуса, значок, номер задачи, жирный заголовок и приглушённые метаданные.

## Цвета

| Элемент                              | Вид                                     |
| ------------------------------------ | --------------------------------------- |
| `todo`                               | Голубой `○ К работе`                    |
| `in_progress`                        | Жёлтый `● В работе`                     |
| `review`                             | Фиолетовый `◇ На проверке`              |
| Успешный конечный статус             | Зелёный `✓`; для `done` — `Выполнена`   |
| Остальные конечные статусы           | Серый `−`; для `cancelled` — `Отменена` |
| Блокеры                              | Красный `!` с количеством или номерами  |
| Номера, автор, время, служебные поля | Приглушённый текст                      |

Для произвольных статусов сохраняются их имена; свойства конечного статуса
и удовлетворения зависимостей берутся из конфигурации. Блокеры показываются
отдельно от статуса. Значки и подписи позволяют читать результат без цвета.
У заблокированной задачи `todo` подпись меняется на `Ожидает`, рядом указывается
количество блокеров; сохранённое значение статуса не меняется.

`--color auto` — режим по умолчанию. Автоматический цвет включается для TTY,
отключается при `TERM=dumb`, непустом `NO_COLOR` и `FORCE_COLOR=0`.
Другое заданное значение `FORCE_COLOR` включает автоматический цвет, если его
не запретили `NO_COLOR` или `TERM=dumb`. Явный флаг `always`/`never` имеет приоритет.
JSON никогда не содержит ANSI-кодов, в том числе в сообщениях об ошибках.

## Представления

```bash
tasks-cli list
tasks-cli list --ready
tasks-cli list --group backend
tasks-cli get 3
tasks-cli get 3 --full
tasks-cli tree 1
tasks-cli links 6
tasks-cli comment list 3
tasks-cli log list 3
tasks-cli log search 3 --query "проверка"
tasks-cli group list
```

- Список: таблица с номерами, названиями, статусами и исполнителями.
  Счётчики относятся к текущей странице; заголовок указывает общее число по фильтру.
- Узкий терминал: компактные карточки с переносами вместо тесной таблицы.
- Карточка: рамка с основными полями, описание, результат и счётчики контекста.
  `--full` включает комментарии, отчёты и технический UUID.
- Связи: названия и номера родителей, детей, зависимостей и блокеров.
- Дерево: ветви с номерами и цветными статусами, подзадачи по порядку номеров.
- Отчёты: цвет по типу, заголовок, автор, местное время и краткое саммари.
  `log get` открывает весь отчёт по его ID.
- Markdown: подсветка заголовков, выделений, ссылок и кода. Базовая лексическая
  подсветка поддерживает JSON, JS/TS, shell и HTTP. Исходные маркеры Markdown,
  пустые строки и отступы сохраняются; длинные строки переносятся.

Ширина берётся из терминала; для перенаправленного вывода можно задать `COLUMNS`.
Диапазон оформления — 24–160 колонок, по умолчанию 100. ANSI-последовательности
не занимают колонки, emoji и широкие символы учитываются по экранной ширине.
Курсор продолжения выводится одной копируемой строкой.

## Постоянные номера

Новые задачи получают `1`, `2`, `3` и далее в пределах общего хранилища.
Номер выделяется под той же блокировкой, что и создание задачи, и сохраняется
в поле `number`. Он не зависит от фильтра, сортировки, страницы или статуса.

```bash
tasks-cli create --title "Первая задача" --actor human
tasks-cli get 1
tasks-cli status 1 in_progress --actor human
```

Для хранилища версии 0.1 назначьте номера командой `number --actor human`.
UUID в именах файлов и ссылках обеспечивает сохранность независимых записей
при Git-слиянии; номер служит короткой ссылкой в командах и текстовом выводе.
Старый CLI 0.1 не поддерживает добавленное поле `number`; после назначения
номеров используйте CLI 0.2 или новее.
