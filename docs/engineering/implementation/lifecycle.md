# Реализация жизненного цикла

**Документальная сверка: 19 сентября 2026 года.** Источники — существующие контракты,
руководство жизненного цикла и карта владельцев; свежая сквозная приёмка не выполнялась.

## Устройство и покрытие

Задачи сохраняются в `.relay/tasks`; проектные документы — в `.relay/project`.
Они используют общую блокировку базы. Владелец проектных операций:
[application/project](../../../packages/core/src/application/project/),
схемы — [domain/project.ts](../../../packages/core/src/domain/project.ts).

Модель содержит паспорт жизненного цикла, планы, этапы, требования, знания, контекст
задачи, исполнения, проверки, приёмки, вопросы, релизы, установки и контрольные точки.
Контекст задачи связывает её с этапом, требованиями и знаниями; поручение собирает
эти данные для исполнителя. Прогресс учитывает листовые задачи и отмену отдельно.

Попытка исполнения не запускает агента и не закрывает задачу автоматически. Проверки
сохраняют основания, приёмка использует результаты. Контрольная точка неизменяема и
содержит снимок ревизий; сравнение показывает изменения после передачи.
Релиз и установка сохраняют факты, а не выполняют команды развёртывания.

## Действующие контракты и ограничения

- [Жизненный цикл](../../product/LIFECYCLE.md) — предметные правила и граница реализации.
- [Руководство](../../guides/LIFECYCLE.md) — операции, конкурентность и повтор.
- [Задачи](../../concepts/TASKS.md), [формат](../../reference/FORMAT.md) — существующая модель задач.
- [CLI](../../reference/CLI.md), [MCP](../../reference/MCP.md), [REST](../../reference/API.md) — точный интерфейс.

Задачи без плана пока допустимы. Новые продуктовые записи не входят автоматически
в контекст поручений, контрольные точки и релизы. Старый паспорт и новый паспорт
продукта различаются. Принцип обязательного плана для самостоятельной цели и связи
с новым продуктом описаны как [развитие](../../product/DIRECTION.md).

## Основания проверок

Релевантные наборы проверок: `pnpm run test:core`, `pnpm run test:cli`,
`pnpm run test:server`, `pnpm run test:mcp`; пользовательские сценарии Web проверяются
по [инструкциям](../../../apps/web/AGENTS.md). Это команды для будущего изменения,
а не запись об их запуске. Исторические отчёты Web доступны в
[VERIFICATION.md](../../../apps/web/VERIFICATION.md). Новые результаты принадлежат
досье конкретной работы в [work](../../work/README.md).
