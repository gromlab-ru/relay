### Канбан отдельных досок: 19 сентября 2026

Реализованы короткие ID, префиксы, пустое либо заполненное создание, Markdown,
перенос с сохранением ID, зависимости и обратное чтение. Есть REST/SDK, CLI `task`
и MCP `board_task_*`. Web переработан после отклонения первой UI-версии: полноширинная
доска, постоянный маршрут задачи, центральный просмотр/редактор, сортировка и подгрузка
по механике прежнего канбана. Измеренная подгрузка 40→44 сохранила DOM первой карточки
и scrollY 3311; после local CLI/SSE — 45 без сброса объёма. При создании зафиксирован
один pushState, неизменный DOM доски и отсутствие skeleton редактора.
Полный перечень проверок и оставшиеся ограничения: [досье](../../work/board-kanban/README.md).

Последующая UI-итерация меняет только существующий `project-board`: отдельная шапка,
колонки по высоте окна, стабильный scrollbar gutter, компактные карточки. `task-kanban`
владеет локальным снимком порядка на время DnD и записи; подтверждённые данные по-прежнему
приходят через `domains/board-tasks`. Overlay использует измеренную геометрию, а дополнительная
невидимая запись задаёт точный beforeId на границе загруженной страницы. REST не изменён.
Проверены мышь/клавиатура, задержка записи 4 секунды, отказ с восстановлением положения,
подгрузка 40→44 с сохранением DOM и scrollTop 3353. Проверки этой итерации — в досье;
приёмка пользователем и новая страница задачи ещё впереди.

Следующее уточнение пользователя сохраняет модальное окно вместо отдельной страницы.
`task-modal` управляет размером; `task-editor` — единым обзором и черновиком; вложенный
`task-context` — постоянными продуктовыми связями и чтением контекста. Новый маршрут
`boards/:boardSlug/:taskId` сохраняет pathless-владельца экрана; `/tasks/:id` совместим
для старых ссылок, смена доски канонизирует URL без закрытия окна. Поиск связей имеет
описание по запросу; межзадачные и продуктовые записи постоянные. Выбор подзадачи —
два компактных селектора без выбора типа; dropdown задач ищет по названию/ключу,
исключая done/cancelled через серверный completion=unfinished до пагинации.
Глобальная тема не добавляет внешний контур текстовым полям/селекторам: фокус меняет
цвет существующей рамки. CodeMirror подсвечивает рамку владельца при focus-within.
Закрытая карточка после DnD обновляется через адресный GET/mutate, обычное открытие
перечитывает кеш. Это исправляет старый статус при revalidation без SWR-подписчика.
Статус/доска выбираются
через компактные меню без формы и блока «Детали». Типа эпика нет. MarkdownField
лениво загружает CodeMirror; внутри ввода нет вкладки предпросмотра.

В Web сохранились внутренние имена прототипа; маршрут `product/work/:workId` удалён.
Граница продуктовой интеграции описана в
[реализации продукта](product.md). Скрытые страницы прежнего жизненного цикла удалены.

Playground не содержит реализации продуктов из ТЗ. Его init сохраняет существующие
конфигурации и валидирует проекты. Текущее содержимое локальных `.relay` не
инвентаризировалось и не очищалось. Правило ignore не снимает отслеживание уже
закоммиченных конфигураций; состав Git и политика данных учитываются отдельно.

Старые инструкции и отчёты у владельцев читаются с учётом даты. При расхождении
с продуктовым контрактом агент фиксирует проблему в досье, а не выбирает молча удобную версию.
