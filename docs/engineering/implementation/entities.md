# Реализация движка сущностей

Сверка 20 сентября 2026. [Продукт](../../product/ENTITIES.md), [контракт](../../reference/ENTITIES.md),
[досье и проверки](../../work/entity-engine/README.md).

## Владельцы

- `packages/contracts/src/entities.ts` — девять определений, read models, запросы и действия;
  `entities/*` и `primitives.ts` — единственные переносимые схемы полей и текста.
- `packages/core/src/domain/*` — совместимые пути экспорта схем. Contracts не зависит от Core.
- `application/entities/catalog.ts` — согласованный каталог источников, карточки и адреса.
- `application/entities/resolver.ts` — единое разрешение ключа, алиаса, ID или kind:ID;
  тот же механизм использует граф, включая его расширяемые виды.
- `application/entities/service.ts` — общие выборки, фильтры, версии и конвейер операций;
  `handlers.ts` — регистрация предметных обработчиков девяти видов.
- Сервер `modules/entities` вызывает движок; local/HTTP backend сохраняет одинаковый контракт.
- CLI `commands/entities` и `presentation/entities` — действия и человеческий вывод;
  MCP `entity-tools.ts` выводит аргументы предметных инструментов из общих схем.
- Web `domains/entities` владеет каталогом и SWR; существующий EntityPicker использует его
  вместо обхода графа для поиска. Формат связей Web также проверяется общей схемой contracts.

## Гарантии и границы

Ключ разрешается под общей блокировкой; зарегистрированный обработчик получает ID.
Вложенные операции разделяют владение блокировкой через AsyncLocalStorage; внешний
параллельный запрос получает отдельную блокировку. Запись использует транзакцию владельца.
Ключи и квитанции настроек/досок сохраняются одним JSON; алиасы не передаются другой записи.

Виды определены в коде. Добавление поля начинается со схемы; изменение предметного смысла
также требует обработчика, кодека/миграции и приёмки интерфейсов. Реестровая архитектура
не генерирует полноценный пользовательский сценарий из названия поля.

Физические владельцы продукта, задач, досок и настроек сохранены. Продуктовые линки
остаются в их данных. Domain-проекции удалены из [движка связей](relations.md): граф
читает только явные записи. Подключение всех предметных операций к записи/разрыву Core
и перенос старых линков в отдельные связи выполняются следующим этапом.
Каталог собирает согласованный снимок источников; общий индекс адресного чтения всех записей
и новые нагрузочные гарантии этим этапом не заявлены. История показывает только сохранённые события.

Core-сценарии, OpenAPI, HTTP backend, CLI text/JSON и MCP discovery/вызовы проверяются в досье.
Браузерная приёмка и итоговые команды фиксируются там по мере выполнения.
