# Библиотека документов

> Архив прототипа. Действующий [контракт Web](../../../../product/applications/web/PRODUCT.md).

[Сущность «Продукт»](../README.md) → Документы

**Адрес:** `/projects/:project/product/documents`.

## Назначение и карточки

Единое место чтения и ведения самостоятельных Markdown-материалов: ТЗ, описаний ожидаемого
поведения, правил и решений. Материал может относиться к нескольким областям продукта
или пока не иметь связей.

Страница показывает заголовок «Документы», действие «Создать документ», поиск, фильтр типа,
кнопки областей со счётчиками, сортировку, размер выдачи и сетку карточек.

Карточка содержит тип, отметку MD, название, краткое описание, до двух меток областей,
`+N` оставшихся связей и дату обновления. Без областей показано «Без связей».
Вся карточка открывает чтение материала; пустое необязательное краткое описание допустимо.

## Поиск, фильтры и сортировка

| Параметр            | Правило                                                                                                               |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `q`                 | Поиск без учёта регистра и внешних пробелов по названию, краткому описанию, полному Markdown, именам и путям областей |
| `kind`              | Все типы либо `specification / description / rules / decision`                                                        |
| `scope=all`         | Все документы                                                                                                         |
| `scope=product`     | Хотя бы одна связь с продуктом, общей фичей или общим сценарием                                                       |
| `scope=application` | Хотя бы одна связь с приложением или его реализацией фичи/сценария                                                    |
| `scope=unlinked`    | Ни одной связи                                                                                                        |
| `sort=updated`      | Сначала обновлённые, значение по умолчанию                                                                            |
| `sort=name`         | По названию с русской локалью                                                                                         |

Фильтры применяются совместно. Один документ с областями обеих веток присутствует и в группе
«Продукт», и в группе «Приложения». Поэтому сумма счётчиков групп может быть больше общего числа.

Счётчики групп считаются по **всей библиотеке**, независимо от запроса и типа.
«Показано N из M» отражает итоговую выдачу и общий размер библиотеки.
Неизвестные `kind`/`scope` трактуются как «все», неизвестная сортировка — как `updated`.

«Сбросить фильтры» очищает параметры, включая сортировку. Само изменение сортировки без
других фильтров не считается фильтрацией и не показывает эту кнопку. Каждый ввод заменяет
текущую запись URL, сохраняя возможность вернуться к выдаче из документа.

## Действия и состояния

- «Создать документ» открывает `documents/new`, сохранив адрес библиотеки для возврата.
- Карточка открывает `documents/:documentId`; чтение и последующее редактирование возвращаются
  к той же выдаче.
- Нет документов вообще: «Начните с первого документа» и действие создания.
- Ничего не подошло под фильтры: «Ничего не нашлось» и сброс фильтров.
- Ошибка чтения — отдельное состояние, не пустая библиотека.

## Требования перехода

Моковые области участвуют в фильтрации через независимый справочник, а не реальные отношения.
После подключения данных поиск и счётчики должны использовать настоящие типизированные связи
и актуальные имена целей из [модели](../MODEL.md). Неизвестная/утраченная цель не должна
молчаливо превращаться в «Без связей»; её жизненный цикл определяется D-04/D-05.

`updatedAt` в моках задаёт браузер. Для постоянных записей дата берётся из подтверждённой
операции сервера. Пагинация не должна ограничивать поиск только загруженными карточками.

## Критерии приёмки

1. Поиск находит слово только в тексте документа и слово только в контексте его области.
2. Счётчики групп не меняются от фильтра типа, пересечение групп учитывается корректно.
3. После редактирования материал корректно сортируется по обновлению; возврат сохраняет фильтры.
4. Пустой документный каталог и пустая выдача различаются, обе ветки имеют понятное продолжение.
