# Проектная библиотека знаний

## Цель и статус

Спроектировать универсальную библиотеку знаний проекта: понятный каталог, создание
и чтение документов, связи с задачами, фичами, сценариями, приложениями и реализациями.
Основание — запрос пользователя от 22 сентября 2026 с изображением текущего каталога.
Приоритет — лаконичный UI/UX, согласованный с дизайном Relay.

Статус: библиотека и линковка документов реализованы и проверены в описанных ниже границах.
Уточнение пользователя: просмотр контекста и путей графа не входит в задачу.
UI прикрепляет документ к сущностям; бекенд сохраняет продуктовые линки и явно
устанавливает, меняет или снимает соответствующие связи Core.
Актуальный [план завершения и транзакционный контракт](IMPLEMENTATION.md).
[Предложение](PROPOSAL.md) задаёт целевой сценарий; фактическое покрытие фиксируется отдельно.

## Границы и владельцы

Работа включает Web, общие контракты, постоянное хранение и интерфейсы агента.
Просмотр документа должен сразу объяснять назначение, состояние и связи материала.

Исследованы экраны `product-documents`, `product-document`, `product-document-editor`,
их адаптер `domains/product-demo`, общий граф и выбор сущностей в `project-relations`.
Владельцы реализации и границы интеграции описаны в IMPLEMENTATION.md.

Основания проектирования: протокол Relay, правила библиотеки, интерфейсный стандарт,
профиль из `apps/web/README.md`, skills Unit Architecture и React Reference,
правила слоёв/зависимостей, UI и разбора макета.

## Выполненный план

Уточнение после разбора пользователем прикрепления документа: по
[обязательному стандарту](../../development/LINKS-AND-CONTEXT.md) после продуктовой
записи бекенд должен явно устанавливать/разрывать отдельно сохраняемые связи Core.
Проекционное решение прежнего этапа не является целевым контрактом.
В [работе над движком](../explicit-relation-engine/README.md) вычисление этих рёбер уже удалено:
линки библиотеки остаются в продуктовых данных. Интеграция обоих шагов с восстановлением
реализована и проверена, включая сбои между стадиями. Основание —
[исправление стандарта](../links-and-context-standard/README.md).

1. Сохранять продуктовый линк у документа, после продуктовой записи явно вызывать
   движок Core для отдельного сохранения связи. Бекенд обеспечивает восстановление
   составной операции; прежний проекционный подход заменён.
2. Разделы принадлежат настройкам проекта, с постоянными ID и общей ревизией. Каталог
   документов — серверная выборка компактных карточек; полное содержание читается адресно.
3. `domains/documents` предоставляет данные и операции; экраны каталога, чтения и редактора
   координируют UI. Общие виджеты выбора связей и документов сущности используют публичные
   фасеты доменов. Обратных зависимостей от entities/relations к documents не вводим.
4. Сначала собрать и визуально проверить новые экранные проекции; подключить постоянные
   сценарии, черновики, обратное прикрепление, ошибки и SSE. Новый TSX — через генератор.
5. Проверить Core/контракты, REST/CLI/MCP, lint/typecheck/build Web, обе темы и ширины
   1440/1024/768/390 в собственной headless-сессии на временных данных; актуализировать документы.

## Результат и точка продолжения

Реализованы разделы, независимые типы и состояния, компактный каталог, Markdown-читатель,
редактор с локальным восстановлением, прямые прикрепления и обратный выбор из сущности.
«Проект решения» в состоянии «Черновик» отличается от принятого решения.
Бекенд сохраняет продуктовые линки и отдельные связи Core с безопасным восстановлением.
Просмотр графа и путей исключён по уточнению пользователя.

Проверки: Core 91/91 (включая 8 профильных), CLI 35/35, MCP 9/9, Server Runtime 33/33;
Web lint/typecheck/build, docs:check и актуальность собранного скилла — успешно.
В браузере проверены прикрепление/снятие, создание, сеть/повтор, конфликт и SSE,
локальный ввод, вложенный диалог задачи, адаптивность и доступность. Подробности — в журнале.

Ограничение общего `test:server`: два теста dev-перезагрузки меняют первое совпадение
`title: command.title` в методе комментариев вместо создания задачи. Их исправление —
отдельный следующий шаг для владельца серверных тестов. Полностью зелёный общий suite
не заявляется; ручная оценка контраста затемнённой фоновой задачи отмечена в журнале.

Ветка `refactor/application-rebuild`, изменения не закоммичены, рядом остаётся работа
пользователя. Сессия `tasks-web-library-final` закрыта; свои API 4898 и Vite 5188
остановлены. Локальные артефакты проверки находятся в `.artifacts` и каталоге снимков
agent-browser. Дальнейшие изменения библиотеки — по результатам пользовательской приёмки.
