## Цель и границы

По поручению пользователя уточнить устройство карточки задачи на досках Relay.
Типы карточек отложены. Текущий сценарий: продуктовая задача объединяет реализацию
сценария, а задачи на досках приложений выполняют отдельные части; завершение
продуктовой задачи зависит от результатов этих задач.

Связанная предыдущая работа: [канбан задач](../board-kanban/README.md).

## Согласованный результат

Пользователь поручил переделать существующий раздел «Связи с задачами» в «Подзадачи»:
убрать выбор типа связи и группы, оставить плоский список и выбор доски/задачи.
Подзадача сама является блокером: родителя нельзя перевести в `done`, пока её статус
отличается от `done`. Отмена не считается выполнением. Родитель завершается явно.

Используется существующее родительство `parentId`; дополнительная копия связи
в `dependencies` не создаётся. Старые дочерние задачи сразу получают тот же смысл.
Остальные существующие отношения сохраняются в общем графе, доступном из карточки.
В разделе подзадач отображаются только прямые дети, включая готовых и отменённых.
Добавление незавершённого ребёнка к готовому родителю требует сначала вернуть родителя
из готовых. Повторное открытие ребёнка пересчитывает блокеры без автоматической смены
статуса родителя, как и повторное открытие обычной зависимости.

## План и совместимость

1. Contracts/Core: включить прямых детей в вычисляемые блокеры; защищать завершение,
   добавление ребёнка к готовому родителю и циклы совместного графа детей/зависимостей.
   Добавить серверный фильтр `parentId` и проверки правил, повторов, конфликтов и страниц.
2. Обновить SDK закреплённым генератором по актуальному OpenAPI. Формат хранения v3
   сохраняется: новые поля на диске не нужны. ID, ревизии и старые квитанции сохраняются.
   Чтение старого графа остаётся доступным; новые циклические рёбра отклоняются, старые
   конфликтующие рёбра можно удалить.
3. Web: ближайший владелец — существующий вложенный `task-relations` внутри редактора;
   форма и список остаются в композиции. `domains/board-tasks` публикует фильтр и
   использует прежние операции/кеш. Новых юнитов и TSX не требуется. Импорты через
   фасеты; направление `task-editor → task-relations → domains → infra` сохраняется.
4. Обновить канонические документы и выполнить Core/API, typecheck, Web lint/build,
   браузерные проверки на временном проекте, docs:check и форматирование.

Дополнительное поручение пользователя: после реализации подзадач удалить хлебные
крошки из окна карточки. Владелец — существующий `task-modal`; удаляется подключение
`ProjectBreadcrumbs embedded`, навигация самого проекта остаётся у каркаса страниц.

Основания плана: профиль `apps/web/README.md`, skills Unit Architecture (слои,
зависимости), React Reference (формы, данные, UI/Mantine, TS/TSX/CSS), REST API Codegen
(генерация существующего SDK). Для Web применяется строгий режим правил кода.
