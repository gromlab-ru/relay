# Удаление сущностей

Статус: реализовано и проверено.

## Цель и границы

По запросу пользователя реализовать удаление задач, фич, сценариев, приложений,
реализаций и документов из Web. Последнее уточнение пользователя заменяет первоначальный
выбор запрета удаления: нужен каскад и очистка связей с сохранением внешних записей.
Удаление проекта, паспорта и самостоятельное удаление системных досок не входят в работу.

## Сценарии и контракт

- Фича удаляется вместе со сценариями и всеми реализациями этих требований.
- Сценарий удаляется вместе со своими реализациями.
- Приложение удаляется вместе со своими реализациями, доской и её задачами.
- Реализация фичи удаляется вместе с реализациями её сценариев в том же приложении.
- Отдельная задача удаляется без внешних подзадач: они теряют родителя.
- Документ удаляется без сущностей, к которым он прикреплён.
- Внешние задачи и документы сохраняются; предметные ссылки и активные связи графа
  с удаляемыми сущностями снимаются. Исторические события не переписываются.
- Перед удалением показывается состав и последствия; запись проверяет версию предпросмотра.
  Повтор после неопределённого ответа использует ту же постоянную квитанцию.

## Владельцы и план

1. Contracts и Core/entities: предпросмотр, предметный каскад, очистка ссылок.
   Storage: долговечная восстанавливаемая составная операция под общей блокировкой;
   совместимое чтение существующих записей, без переписывания их схем ради удаления.
2. Server/entities и сгенерированный SDK: проектные операции предпросмотра и удаления.
3. Web/domains/entities: адаптеры и обновление кеша; compositions/widgets — общий
   продуктовый диалог, экраны продукта и окно задачи — точки подключения и переходы.
   Слои и фасеты определены профилем apps/web/README.md, Unit Architecture
   (layers, dependencies) и React Reference (data-fetching, ui, строгий styleguide).
   Новые границы не создают обратных импортов доменов к композициям.
4. Проверки: Core/REST — каскады, сохранение внешних сущностей, конкуренция,
   повторы и восстановление; Web — собственный agent-browser на временной базе,
   обе темы и адаптивность, ошибки; lint/typecheck/build, docs:check, форматирование, diff.

## Точка продолжения

Реализованы шесть сценариев Core/REST/SDK/Web, общий восстанавливаемый WAL,
очистка предметных и графовых ссылок, сохранение внешних сущностей, резервирование
удалённых ключей, отдельные квитанции и проверка версии предпросмотра.
Диалог подключён к страницам сущностей и шапке окна задачи. Документация актуализирована.

Финальные проверки: Core 73/73, Server Runtime 33/33, CLI 35/35, MCP 9/9;
typecheck затронутых backend-пакетов; Web lint/typecheck/build; docs:check и diff --check.
Браузер: все шесть сценариев, конфликты, сеть/повтор, черновик и вложенный Escape,
обе темы и 1440/1024/768/390. Локальное удаление через Core подтверждено в Web по SSE.
axe не нашёл нарушений, но оставил одну группу контрастности для ручной оценки;
снимки просмотрены, автоматический результат не объявляется исчерпывающим аудитом.

Все изменения находятся в рабочей копии, коммит не создавался. Исходно дерево было чистым.
Артефакты и временная база находятся в gitignored `.artifacts/entity-deletion`.
Собственная сессия `tasks-web-deletion-0921`, сервер 4796 и Vite 5196 остановлены.
Следующий шаг — пользовательская приёмка интерфейса; блокеров нет. Ограничения:
не более 1000 записей в каждой группе предпросмотра, legacy-граф требует явной миграции;
CLI/MCP-команды удаления не добавлялись в рамках Web-задачи.
