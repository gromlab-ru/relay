# Журнал стандарта линков, связей и контекста

**Поправка к ранним записям:** первоначальная трактовка агентом связи как производной
проекции была ошибочной. Действующее решение и исправление описаны в записи
«Уточнение пользователя и исправление трактовки» ниже и в актуальном стандарте.

## 22 сентября 2026 — основание и начало записи

- Пользователь согласовал предметные линки как источник факта, внутренние связи как
  представление для обхода и публичный контекст как чтение. Потребовал обязательное
  чтение стандарта перед любой задачей. После режима планирования разрешена запись.
- Прочитаны протокол, правила библиотеки, концепция продукта, стандарт интерфейсов,
  документы графа/сущностей/канбана, исходники скилла и досье связей и библиотеки.
- Статически исследованы `application/graph/{catalog,context,service}.ts`,
  `application/product/queries.ts`, предметные обработчики и удаление сущностей,
  схемы графа и документов, операции CLI/MCP, тесты графа. Это чтение, не запуск сценариев.
- Обнаружено расхождение прежнего предложения о едином хранилище всех рёбер с принятым
  сейчас направлением. Его необходимо обозначить, не переписывая историю решения.
- `git status --short --branch` подтвердил ветку и существующие параллельные правки.
  Документационная работа не изменяет их реализацию и не мигрирует данные.

## 22 сентября 2026 — стандарт и обязательное чтение

- Создан `docs/development/LINKS-AND-CONTEXT.md`: определения, единственный владелец
  линка, предметные операции, снятие, динамический контекст, диаграммы, контракт новой
  функциональности и проверяемые результаты. Отдельно описаны расхождения с кодом.
- Корневой `AGENTS.md` и `PROTOCOL.md` требуют чтение перед любой задачей. Стандарт
  интерфейсов и индекс разработки ведут к тому же каноническому документу.
- Обновлены продуктовый словарь и `RELATIONS.md`, техническая карточка графа.
  В прежнее предложение добавлена отметка о новом решении; исторические рассуждения сохранены.
- Проверены справочники `GRAPH.md`, `ENTITIES.md` и `KANBAN.md`: описания существующих
  графовых операций сохраняются как технический контракт; API и данные эта работа не меняет.
  Источники и сборка продуктового скилла не затронуты: поручение относится к обязательному
  протоколу разработки Relay. Отдельный переход клиентских сценариев остаётся последующей работой.
- Следующий шаг — проверка локальных ссылок, форматирования и diff. До завершения проверок
  документирование не объявляется завершённым.

## 22 сентября 2026 — проверка результата

- `pnpm run docs:check` — успешно: 211 файлов документации, 1058 ссылок, ошибок нет;
  проверка также сообщила 17 файлов скилла и 64 внутренних ссылки без ошибок.
- `git diff --check` — успешно для всего текущего рабочего дерева.
- Выполнено адресное форматирование Prettier двенадцати изменённых Markdown-файлов этой
  работы; `pnpm exec prettier --check` того же списка — успешно: все файлы соответствуют
  стилю. Заключительный `git diff --check` также прошёл без ошибок.
- Ручная проверка: маршруты AGENTS → стандарт и протокол → стандарт, определения в словаре,
  продуктовые правила → стандарт → техническое покрытие и досье согласованы. Diff существующих
  документов просмотрен; новая инструкция отделяет требования от переходного состояния.
- Проверки относятся к текущему незакоммиченному дереву ветки `refactor/application-rebuild`.
  Runtime-тесты не запускались: работа меняет документацию, а не поведение приложения.
  Реализация стандарта остаётся частичной, её расхождения перечислены явно.

## 22 сентября 2026 — уточнение пользователя и исправление трактовки

- На кейсе прикрепления документа пользователь выявил ошибку агента: связь должна
  явно создаваться и сохраняться движком Core после продуктовой операции, а не
  вычисляться из полей документа при чтении. Продуктовый линк при этом сохраняется
  в продуктовой базе для UI и бизнес-функций. Это два разных механизма и места хранения.
- Пользователь подтвердил порядок: продуктовая запись → вызов функций Core → запись
  связи; при откреплении — продуктовая операция → разрыв связи. Контекст читает граф.
- Ранние формулировки этого журнала об одобрении производной модели не подтверждают
  намерение пользователя; это ошибка интерпретации, исправляемая новой записью.
- Работа возобновлена в том же досье. Переписываются стандарт, протоколы, определения,
  техническое покрытие и пометка старого предложения; причина решения сохраняется
  в инженерном разделе. Код, база, существующие API и параллельные изменения не меняются.
- Повторно прочитаны обязательные документы и `git status --short --branch`.
  Проверки предыдущего этапа не подтверждают исправленное содержание; проверки будут повторены.

## 22 сентября 2026 — переписан контракт двух механизмов

- Стандарт теперь требует последовательность продуктовая запись → явный вызов Core →
  отдельное сохранение/разрыв связи. Добавлены пример документа и псевдокод, замена цели,
  ответственность за две записи и проверка отказа между шагами. Производная проекция
  прямо обозначена как неверная замена интеграции.
- Исправлены корневые инструкции, протокол и стандарт интерфейсов, добавлены обязательные
  правила в `packages/core/AGENTS.md`. Для каждого сценария требуется определить связи
  до реализации; отсутствие необходимости обосновывается.
- Обновлены словарь, концепция продукта, продуктовые правила связей и техническое
  покрытие. Причина решения сохранена в `engineering/decisions/product-links-and-core-relations.md`.
- В спецификации Web-документов исправлен конфликтующий целевой контракт; в досье
  параллельной работы библиотеки добавлено явное уточнение прежнего проекционного плана.
  Остальные правки этой работы сохранены. Старое предложение помечено с учётом исправления.
- Проверены описания текущих domain-проекций в инженерной документации и справочнике
  графа: они остаются фактами существующей реализации, не нормой для новой интеграции.
  API/код не менялись; исторический журнал не переписан задним числом.

## 22 сентября 2026 — проверки исправленной редакции

- `pnpm run docs:check` — успешно: 212 файлов и 1069 ссылок документации; 17 файлов
  и 64 ссылки скилла; ошибок нет.
- `git diff --check` — успешно для рабочего дерева.
- Prettier применён адресно к 17 Markdown-файлам исправления; заключительный
  `pnpm exec prettier --check` того же списка — успешно, как и повторный `git diff --check`.
  Остальные файлы не форматировались.
- Повторно прочитан итоговый стандарт; проверены определения, пример документа,
  обязательные вызовы после продуктовой записи, обратный сценарий и критерии двух записей.
  Поиск конфликтующих формулировок выявил спецификацию документов и прежний план библиотеки:
