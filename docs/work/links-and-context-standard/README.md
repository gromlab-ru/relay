# Обязательный стандарт линков, связей и контекста

## Цель и основание

По согласованию с пользователем 22 сентября 2026 зарезервировать термины «линк»,
«связь» и «контекст», описать предметную запись и внутренний граф и сделать стандарт
обязательным чтением перед любой задачей Relay.

Статус: документация исправлена по уточнению пользователя и проверена. Связь отдельно
сохраняется движком Core по вызову бекенда после продуктового действия, а не вычисляется
как проекция линка при чтении. Прежняя формулировка была ошибкой агента.
Предшествующее исследование —
[механизм связей](../entity-relations/README.md); смежная незавершённая работа —
библиотека документов (незакоммиченная параллельная работа `docs/work/project-knowledge-library`).

## Границы, владельцы и план

Владелец — документация разработки; продуктовые определения и техническое покрытие
согласуются с ней. Меняются только документы и корневые инструкции. Изменения Core,
REST, клиентов, данных и распространяемого скилла в эту работу не входят.

1. Зафиксировать принятые определения, жизненный цикл линка, контекст и правила расширения.
2. Подключить стандарт к обязательному протоколу, навигации и каноническим описаниям.
3. Проверить ссылки, форматирование, diff и записать фактический результат.

Основной результат: [стандарт](../../development/LINKS-AND-CONTEXT.md).
Принятый контракт отделяется от фактического покрытия: существующие самостоятельные
рёбра не объявляются производными и не удаляются в рамках документационной работы.

## Проверки и точка продолжения

Проверки: `pnpm run docs:check`, Prettier для затронутых Markdown, `git diff --check`;
ручная сверка навигации и соответствия ограничений прочитанному коду.

Ветка `refactor/application-rebuild`. На старте есть многочисленные чужие изменения
CLI/MCP/Web, контрактов, Core, SDK и документов, включая индекс работ. Они сохраняются.
Собственные изменения: это досье и перечисленные в журнале документы стандарта.
Обязательное чтение подключено в корневом `AGENTS.md` и протоколе. Исправлены определения,
порядок продуктовой записи/вызова Core, примеры и проверки; согласованы связанные документы
и инструкции Core. Проверка ссылок и diff пройдена, форматирование приведено к Prettier.
Точные результаты, причина исправления и ограничения — в журнале. Блокеров документов нет.

Последующая реализация по отдельному поручению: явные вызовы движка из продуктовых операций,
согласованность двух записей, переход от domain-проекций, диагностика и контексты. Стандарт сам
не меняет API или хранилище. Серверные и браузерные процессы не запускались, коммит не создавался.

Продолжение по новому поручению: [единственный механизм явных связей](../explicit-relation-engine/README.md).
В этой последующей работе domain-проекции уже удалены, контекст читает только сохранённые
связи без скрытого отсечения видов. Интеграция продуктовых сценариев оставлена следующей задаче.
