# Канбан задач на досках

**Статус: обсуждение, реализация не начата.**

## Цель и основание

После [этапа досок](../multiple-boards/README.md) пользователь запросил полноценный
канбан, создание задач через Web/CLI/MCP и междосочные связи. Затем уточнил порядок:
сначала обсудить внешний вид, колонки, анимации, идентификаторы и минимальную карточку
«заголовок + Markdown». Ниже — предложения, а не согласованный контракт.

## Предлагаемая модель для обсуждения

- Сохранить постоянный ID доски для связей и slug для URL и команд.
- Задача имеет постоянный ID и человекочитаемый ключ из кода доски и номера.
  Отдельный код доски, его выбор и поведение ключа при переносе требуют решения.
- Обязателен заголовок; описание — Markdown, допустимость пустого описания обсуждается.
  Доска, колонка, порядок, ревизия и даты — системные поля.
- Начальные колонки: «Входящие», «К выполнению», «В работе», «На проверке», «Готово».
  Блокировка показывается отдельно от этапа; отмена не выполняет зависимость.
- Компактная карточка открывает боковую панель с полным Markdown и связями;
  прямая ссылка восстанавливает открытую задачу. На телефоне — полноэкранный редактор.
- Перетаскивание меняет колонку и порядок: предварительное место вставки,
  плавное смещение соседей, сохранение с обработкой конфликтов. Альтернатива — меню
  перемещения; клавиатура и reduced motion входят в сценарии приёмки.
- Между задачами одного проекта: обычная связь, направленная зависимость,
  родительство. Обратные представления строятся по одной записи связи.
  Междосочные связи не требуют отдельной зависимости досок целиком.
- CLI и MCP имеют предметные операции создания, чтения, изменения, перемещения
  и связывания; общий Core проверяет правила, ревизии и ключи повторов.

## Границы, владельцы и проверки

Сейчас меняется только досье обсуждения. Владельцы ожидаемого поведения:
[доски](../../product/entities/boards/README.md),
[задачи](../../product/entities/tasks/README.md),
[направление](../../product/DIRECTION.md). После согласования обновить их требования.
Реализация затронет Core, Server, SDK, Web, CLI, MCP и справочники.

До реализации решить: набор и настройку колонок, коды досок, перенос задач между
досками, правила блокировки, необходимость родительства в первом этапе,
совместимость со старой моделью планов и задач, границы списков и продолжение.
Ранее согласованное отсутствие миграции относилось к этапу досок; перенос старых
задач не предполагается без отдельного решения.

Будущая приёмка: создание из трёх интерфейсов, Markdown без потерь, порядок и DnD,
клавиатура, мобильный экран, ошибки и конфликты, конкурирующее создание номеров,
повторы записи, междосочные зависимости и циклы, пагинация и внешние обновления.
Человеческий результат и JSON проверяются отдельно.

## Точка продолжения

Обсудить предложение с пользователем, затем закрепить решения у владельцев.
Код не изменён. Ветка `refactor/application-rebuild`; незакоммиченные изменения
предыдущего этапа сохранены. Собственные процессы не запускались.
Ход и проверки — в [журнале](JOURNAL.md).
