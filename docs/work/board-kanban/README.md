Последние решения: «Создать» одним запросом сохраняет пустую задачу и сразу открывает

изменения геометрии, keepPreviousData, сохранение загруженного объёма и scroll anchoring.

Обновлённый план Web: общий pathless-маршрут сохраняет экран доски при открытии
`tasks/:id`; прежние числовые задачи выбираются по формату ID. Новый случайный ID
обязательно содержит хотя бы одну букву и не конфликтует с числовыми адресами.
Технические DnD helpers выделяются в `ui/kanban-dnd`
для обоих канбанов, без зависимости UI от доменов. Слой domains/board-tasks владеет
согласованной подгрузкой и заполнением кеша создания. Редактор по умолчанию показывает
Markdown, формы связей и перемещения открываются по явному действию.

## Решения и план реализации

Пользователь подтвердил ключи задач с префиксом доски: префикс задаётся при создании
приложения, системный продуктовый префикс — `PRODUCT`. Перенос меняет ключ, но сохраняет
ID задачи. Редактор — широкое центральное модальное окно. Граф связей должен давать
оркестратору зависимости, обратные связи и текущие блокеры.

Новые генерируемые ID сущностей — 8 символов; существующие ID читаются без переименования
и разрыва ссылок. Ключи повторов, хеши версий и временные имена не являются ID сущностей.
Старые числовые задачи остаются в прежней модели. Семантические адреса `passport`
и контекст старой задачи сохраняются как совместимые адреса.

1. Core владеет генератором ID, префиксами, новой моделью задач, графом зависимостей
   и атомарной записью под общей блокировкой. Перенос между файлами возобновляется
   из долговечного намерения; номера не переиспользуются после переноса.
2. Server описывает операции через OpenAPI; SDK генерируется закреплённой командой.
   Project runtime подключает общий Core для локального CLI и SDK для HTTP.
   CLI/MCP предоставляют предметные действия и ограниченные списки с продолжением.
3. Web: `domains/boards` сохраняет каталог; новый `domains/board-tasks` владеет
   адаптацией, операциями и SWR/SSE. `compositions/screens/project-board` собирает
