# Переработка UX канбана

**Актуальное направление: пользователь согласовал отдельную UI-итерацию доски.
Предыдущие предложения ниже сохранены как история.**

## Согласованная UI-итерация

Следующее принятое решение: сохранить модалку с ручным разворачиванием, вкладками
описания/контекста/связей и внутренней прокруткой. Страница задачи не создаётся.
Адрес уточнён пользователем: `/projects/:project/boards/:boardSlug/:taskId`.
Продуктовый выбор пока локален вкладке и явно помечен, содержание читается из API.

- Заголовок и назначение отделяются от поиска и фильтров; больше воздуха сверху.
- Тональные колонки занимают оставшуюся высоту окна; вертикальная прокрутка внутри
  колонок, горизонтальная у доски. Скроллбар не меняет ширину карточки.
- Карточка: вторичный ключ, выразительный заголовок до трёх строк, блокеры и связи.
  Метаданные продукта не выдумываются: API пока не предоставляет такие привязки.
- DnD: измеренная копия, место в целевой колонке, локальный результат до ответа сети,
  сверка и понятный отказ. Внешние данные не подменяют видимый порядок во время жеста.
- Рабочее окно задачи получает разворачивание, продуктовый контекст и поиск связей
  с просмотром; отдельная страница отклонена последующим уточнением пользователя.
- Контекст должен различать фичу/сценарий и контракт приложения; найденные документы
  получают причины включения. Основой служит существующий `ProductQueries.context`.

## Наблюдаемые проблемы

- Канбан помещён в документный `ProjectPage`: max-width 88rem, центрирование,
  горизонтальный отступ до 2rem, крупная шапка и вертикальные промежутки.
  Дополнительные строки метаданных отнимают пространство у основной работы.
- После создания `task=new` заменяется ID, из-за React key размонтируется модальное окно;
  новая задача читается GET до показа редактора. Это конкретный источник смены состояний.
  Синхронизация также сочетает явный refresh с SSE и сбросом страниц колонок.
- Редактор одновременно показывает текстовые поля, перенос и развёрнутую форму связей.
  Первичное чтение задачи не отделено от редактирования.
- Открытая сущность представлена параметром фильтра доски; пользователь это отверг.

## Предлагаемое направление

1. Отдельный полноширинный layout рабочей доски: компактный toolbar, горизонтальные
   отступы 16–20px, без max-width документной страницы. Колонки 260–300px, промежуток
   12px. На узкой ширине горизонтальная прокрутка, без сжатия текста до нечитаемости.
2. Название, поиск, фильтры и создание в одном компактном блоке. Назначение доски и
   технические метаданные доступны по необходимости, а не занимают постоянные строки.
3. По уточнению пользователя «Создать» сразу сохраняет пустую задачу и открывает её
   редактор с номером. Один переход на постоянный URL после ответа создания, без `/new`,
   query-параметра задачи и возврата на доску после сохранения полей. CLI/API передают
   содержание сразу одним запросом. Пустые поля разрешены, закрытие оставляет задачу.
4. Задача открывается в широком центральном окне в режиме чтения: крупный заголовок,
   Markdown и компактные свойства. Редактирование включается явно; связи показываются
   списками «Зависит от», «Блокирует», «Связанные», родитель/подзадачи.
   Поиск для добавления связи открывается по действию, а не постоянно виден в окне.
5. Канонический маршрут задачи `/projects/:project/tasks/:id`; совместимость с прежними
   числовыми задачами определяется различимым форматом ID. Ключ виден в заголовке.
   Маршрут не зависит от доски. Открытие из доски сохраняет её фон, фильтры и прокрутку.
   Прямой вход/reload загружает текущую доску задачи и то же модальное окно.
6. DnD: фиксированное место вставки и плавное смещение без изменения геометрии цели
   под указателем. Быстрый локальный отклик, подтверждение сервером, понятный отказ.
   События синхронизации не перемонтируют редактор, не сбрасывают фокус или позицию.
   По прямому указанию пользователя эталон — прежний канбан на dnd-kit. Коллизии и
   клавиатурные координаты вынесены в общий UI-механизм, сортировка и подгрузка повторяют
   его поведение (keepPreviousData, count и overflow-anchor:none).
7. Клик по фону, Escape и крестик закрывают окно одинаково. Несохранённое содержание
   сохраняется в черновике; закрытие не является удалением введённого текста.

## Источники и адаптация

- [Linear: Board layout](https://linear.app/docs/board-layout): компактные карточки
  без полного описания, создание в колонке, клавиатурные действия, горизонтальная навигация.
- [Linear: Create issues](https://linear.app/docs/creating-issues): отдельный сценарий
  создания, минимум обязательных полей, сохранение черновика.

Размеры, адреса и компоновка выше — проектное предложение для Relay, а не якобы
универсальные нормы или точная копия внешнего продукта.

## Как проверять следующую итерацию

Сначала согласовать два состояния: заполненная доска и просмотр открытой задачи.
Затем создание, редактирование, поиск связи и DnD. На 1440/1024/768/390 проверять
плотность и доступность; при задержке и сетевом отказе — непрерывность формы и черновика.
Приёмка включает стабильные размеры/фокус при создании, Back/Forward/reload, прямую
ссылку после переноса, клавиатуру, обе темы и reduced motion.
