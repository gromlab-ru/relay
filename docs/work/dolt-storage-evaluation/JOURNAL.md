## 22 сентября 2026 — результаты сопоставления

- Через GitHub MCP получены README, релиз v2.3.5 и исходники транзакций/Git remote на этом теге.
  Официальная документация подтверждает SQL-транзакции, JSON, индексы, ветки, конфликты,
  автоматический GC, работу CLI без сервера и MySQL-клиентов через server.
- Важное уточнение: Git remotes уже поддерживаются, включая GitHub и `refs/dolt/data`.
  Поэтому зависимость от DoltHub не объявляется препятствием. Разделение историй кода/данных,
  координация worktree и предметный diff всё равно требуют реализации в Relay.
- Отсутствие блокировки `SELECT ... FOR UPDATE` подтверждено документацией и кодом
  `go-mysql-server/sql/planbuilder/select.go`. Из объяснения авторов и кода merge следует,
  что одинаковые записи и изменения разных ячеек способны слиться: числовая ревизия сама
  по себе не доказывает эксклюзивность предметного действия.
- Обнаружено расхождение страниц Dolt о Read Committed/REPEATABLE_READ; оно записано
  как ограничение источников. Статическое чтение v2.3.5 подтверждает исходный снимок
  корней и слияние при фиксации, но не заменяет приёмочный конкурентный сценарий.
- Уточнена поддержка JSON: структурное слияние разных ключей существует. Отдельно выделены
  массивы и Markdown, SQL COMMIT против Dolt commit, квитанции повторов, коллизии ключей,
  циклы зависимостей и согласование линков/связей после merge.
- Рекомендован сквозной прототип до продолжения разработки физической СУБД. Его критерии
  и проверенные первичные источники сохранены в README. Ускорение полного графа не обещается:
  внешние SQL-benchmark не измеряют контракт Relay, Dolt локально не запускался.
- Проверены `docs/product/README.md`, `docs/development/LINKS-AND-CONTEXT.md`,
  `docs/engineering/entity-storage.md`, `docs/guides/GIT.md` и `STORAGE-REFACTORING.md`.
  Их требования и статус не меняются: предложение Dolt не является решением о переходе.
  Найденные внешние сведения относятся к этой оценке, а не к текущей реализации.
