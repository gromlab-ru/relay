# Реализация предметного прогресса

## Цель и границы

Статус: реализовано и проверено 24 сентября 2026 по поручению пользователя «Приступайте
к реализации прогресса». Основание — [ТЗ](../../../PROGRESS-SPEC.md), подготовленное в
[обсуждении планирования](../planning/README.md).

Реализовать фактическое выполнение задач и отдельные прогрессы задачи, реализации,
сценария, фичи, приложения и продукта. Владельцы: Core — правила и согласованное чтение;
Contracts — отдельные схемы; Server Runtime/SDK — доставка; CLI/MCP/Web — представления.
Планы подключаются позднее. Оптимизация и изменение формата хранения не требуются.

## Контракты и проверки

Человек раскрывает продукт до конкретной невыполненной задачи и её обязательств.
REST получает отдельный контроллер `progress` в существующей области проекта. Каждый
вид имеет собственный ответ. Списки: offset/limit (20/100), полные итоги, nextOffset,
версия снимка; продолжение требует той же версии. Чтение выполняется под блокировкой
Workspace на существующих репозиториях. Миграция не нужна.

Прогресс не пишет продуктовые данные/линки, не создаёт связи и не читает контекст.
Изменение проверок завершения сохраняет существующие вызовы согласования связей Core
после записи задачи. Расчёт использует критерии, детей и зависимости, включая чужие доски.
Колонка остаётся сохранённым фактом, отдельным от фактического выполнения.

Проверки: критерии и транзитивные обязательства, повторное открытие инфраструктурной
зависимости, пустые реализации, уникальные итоги, снятие участия, циклы/повреждения,
продолжение и конфликт версии; REST и изоляция; human/JSON CLI, MCP, Web; типизация,
OpenAPI/SDK, документация и форматирование.

## Результат

- Шесть самостоятельных контрактов/обработчиков: TaskProgress, ImplementationProgress,
  ScenarioProgress, FeatureProgress, ApplicationProgress, ProductProgress.
- Рекурсивное выполнение через общий расчёт задач; прежние блокеры и продуктовый каскад
  согласованы. Старые смешанные циклы доступны для ремонта, новый прогресс диагностирует ошибку.
- Отдельный контроллер `progress`, local/scoped REST, OpenAPI и SDK, local/HTTP Backend.
- CLI `progress <вид> <ref>` / `progress product`, машинный и человеческий вывод;
  шесть MCP-инструментов `<вид>_progress` с предметными аргументами.
- Web: серверные счётчики приложений, задачи/готовность/причины продуктовых целей,
  отдельное фактическое выполнение в редакторе задачи, раскрытие причин и версионные страницы.
- Формат хранения и продуктовые записи не менялись; расчёт не использует контекст.

Точный интерфейс: [справочник прогресса](../../reference/PROGRESS.md).
