# Настройки проекта

**Статус: реализовано и проверено; готово к пользовательской оценке оформления.**

## Цель и контракт

По поручению пользователя добавить в Web полноценную оформленную страницу настроек
с кнопкой в шапке. Первая секция — имя и slug текущего проекта, далее раздел расширяется.
Пользователь подтвердил постоянное сохранение и URL `/projects/<slug>/settings`.
При инициализации slug имеет вид `project-xxxx`: четыре случайных буквы/цифры.
Имя — непустой однострочный текст. Slug — строчные латинские буквы, цифры и дефисы.
Постоянный ID, данные проекта и ссылки по ID сохраняются. Прежний изменённый slug
не резервируется навсегда; копируемые постоянные ссылки могут использовать ID.

## Владельцы и план

- Core: настройки проекта, совместимость прежних конфигураций, атомарная запись
  под общей блокировкой и проверка ревизии. Новое версионированное поле конфигурации;
  старые конфигурации читаются без записи, первая явная запись сохраняет настройки.
- Server ProjectCatalog: разрешение slug/ID/ключа регистрации, проверка занятости
  адреса среди подключённых проектов под общей блокировкой каталога.
- REST/OpenAPI и существующий SDK: чтение и сохранение настроек; SDK только генератором.
- Web `domains/project`: предметный контракт, адаптер и SWR; `domains/workspace` — реестр.
- `compositions/screens/project-settings`: страница и вложенная форма «Основное».
  Mantine/useForm, CSS Modules, состояния сохранения, ошибки, отмена и конфликт.
- `compositions/layouts/project`: кнопка настроек и актуальное имя.
  `relay` разрешает адрес, ProjectScope сохраняет ID независимо от slug.
  `app/router` только подключает экран через lazy-фасет.

Прочитаны протокол, библиотека, продукт, стандарт интерфейсов и AGENTS владельцев;
skills Unit Architecture, React Reference, Template Generation, REST API Codegen.
Применяется профиль React Reference из apps/web/README.md (screens/route-boundaries),
а не иллюстративный профиль pages из Unit Architecture. Изучены слои и зависимости,
страницы, формы, генерация TSX, routing, data fetching, styling и строгие правила TS/JSX/CSS.
Граф: app → композиции → домены → infra, вложенная форма не импортирует родителя.
Новые TSX создаются локальным ui-unit через закреплённый генератор.

## Приёмка

Core/HTTP: новые и старые проекты, сохранение после перезапуска, неверный/занятый slug,
конкуренция и повтор, изоляция проектов, актуальный контекст и SSE.
Web: прямая ссылка, кнопка шапки, смена URL без потери проекта, ввод/сброс/ошибка/конфликт,
две темы, 1440/1024/768/390, клавиатура, a11y, console/errors и визуальные снимки.
Lint/typecheck/build Web, проверки затронутых серверных пакетов, docs:check,
форматирование и git diff --check. Фронтенд-автотесты не добавляются.
