# Группировка досок в навигации Web

**Статус: принято пользователем, 21 сентября 2026 года. Проверки остановлены по его поручению.**

## Цель и границы

По поручению пользователя визуально отделить две системные доски «Продукт» и
«Инфраструктура» от динамических досок приложений в сайдбаре и мобильном меню.
Основание модели — [множественные доски](../multiple-boards/README.md).

## План и контракты

1. У существующего владельца `compositions/layouts/project/ui/project-navigation`
   отделить группы загруженных досок по `kind`: продукт → приложения → инфраструктура.
   Между группами — Mantine Divider без текста (последнее уточнение пользователя).
   Название и slug не определяют тип.
2. Сохранить ссылки, активную доску, раскрытие меню, ошибки и постраничную подгрузку
   по 50 через публичный `domains/boards`. Порядок внутри группы сохраняется.
   Разделитель появляется только между группами. Новых юнитов и TSX нет.
3. Проверить Web lint/typecheck/build, человеческий интерфейс в отдельной headless-сессии
   agent-browser на временной базе и отдельно JSON каталога; актуализировать документы,
   выполнить docs:check, форматирование и git diff --check.

Прочитаны обязательный протокол, стандарт интерфейсов, инструкции Web, skills
Unit Architecture и React Reference; профиль в `apps/web/README.md`, правила юнитов,
зависимостей, UI, стилизации, Mantine, TypeScript и JSX. Разделитель остаётся внутренней
разметкой владельца навигации. Зависимости композиции проходят через фасеты доменов;
обратных импортов и новых публичных API не требуется.

Хранение и REST уже предоставляют `kind` и `applicationId`. Миграция не требуется.
REST-порядок «продукт → приложения → инфраструктура» сохраняется и в навигации.
При большом каталоге инфраструктура и линия перед ней появляются после загрузки
содержащей её страницы. Продолжение списка приложений не добавляет лишних линий.
