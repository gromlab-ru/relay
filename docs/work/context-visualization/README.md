# Визуализация контекста в связях проекта

## Цель и статус

Реализовано и проверено после пользовательской приёмки, 23 сентября 2026. Пользователь поручил реализовать
[предложение просмотра контекста](../../../CONTEXT-UI.md) в `apps/web`, ограничив
точку входа просмотром выбранной сущности в разделе «Связи проекта».
Основание: [стандарт связей](../../development/LINKS-AND-CONTEXT.md).
Предыдущий этап: [предметная интеграция](../product-relation-integration/README.md).

## Границы и архитектура

- Кнопка «Смотреть визуализацию связей» принадлежит `project-relations`.
- Новый ленивый экран `compositions/screens/relation-context` подключается в
  `app/router` по `/projects/:project/relations/context?root=kind:id`.
- Экран координирует URL, выбор и вложенную самостоятельную область диаграммы.
  React Flow и ELK загружаются при открытии визуализации; раскладка работает в Worker.
- `domains/relations` владеет согласованным чтением страниц через существующий SDK,
  объединением по `{kind,id}` и ID связи, продолжением, ошибками снимка и общим поиском
  направленных кратчайших путей для дерева и текстового объяснения.
- `domains/entities` предоставляет адресное чтение полного содержания.
- Фасеты `index.ts`/`lazy.ts`, внутренние компоненты без фасетов, зависимости
  compositions → domains/infra/ui/shared; дети не импортируют родителя или соседей.

Прочитаны профиль `apps/web/README.md`, Unit Architecture (профиль, юниты, слои,
зависимости), React Reference (страницы, компоненты/генерация, данные, SWR,
маршрутизация, состояние, UI, стили, проверки и строгий styleguide), локальные шаблоны
и skill генерации. План зафиксирован до реализации.

## Контракт и критерии

1. Вход только из выбранной сущности «Связей проекта»; отдельный URL и Back/Forward.
2. Начально глубина 1, оба направления; глубина, направление, тип и режим чтения в URL.
3. Используется ограниченный `GET /graph` из предложения. Это исследователь с явными
   границами, а не замена полного `GET /graph/context` с `complete=true`.
4. Страницы по 50, максимум 8 страниц за просмотр; расширение и продолжение используют
   одну `version`. При смене снимка требуется явное обновление всех раскрытых областей.
5. Узлы и все полученные рёбра сохраняют идентичность, направления, петли и параллельные
   связи. `paths` не заменяют рёбра. Путь подсвечивается только по загруженным связям.
6. Выбор показывает сведения и Markdown, действия раскрытия, смены корня и перехода.
   Режим списка предоставляет последовательное клавиатурное чтение.
7. Камера открывается у корня; общая перераскладка сохраняет позицию выбранного узла.
   Доступны масштаб, возврат к корню и вписывание всей области.
8. Пустота, загрузка, ошибка, непрочитанные страницы и граница глубины различимы.
9. По умолчанию дерево показывает один реальный путь к каждой сущности. Дополнительные
   отношения и петли обозначены счётчиками; все загруженные связи узла доступны в сведениях
   по восемь с продолжением. Граф и список остаются отдельными режимами того же снимка.

Сценарий только читает отдельно сохранённые связи Core. Продуктовых записей/линков,
установки или разрыва отношений нет; создание, переподключение и Delete отключены.
Формат хранения и API совместимы, миграция не требуется.

## Точка продолжения

Дерево, граф и список реализованы. Проверена область API-FI-2 глубины 3: 35 узлов,
34 основных линии и 65 дополнительных отношений; граф сохраняет все 99 линий.
Маршруты ELK не проходят через карточки в проверенной области. Дерево использует
общие точки ветвления, не дублирует сущности и не утверждает продуктовое родительство.
Список изолирован от Canvas; его камера сохраняется. Раскрытие FEATURE-7 добавило
три узла и три ребра, сохранив координаты выбранной карточки.

Проверены петли, параллельные и обратные отношения, клавиатура, входящее/исходящее
дерево, прежний `mode=diagram`, ошибки сети, пустое окружение, обе темы и четыре ширины.
Исправлен контраст счётчика дополнительных связей. Typecheck, lint и production build
прошли; [результаты текущего и предыдущего срезов](VERIFICATION.md).
Полное вписывание большого дерева служит обзору: для чтения предусмотрен фокус
у корня или выбранного узла. Проверки не являются гарантией отсутствия пересечений
для любого графа; ручной перенос в графе использует локальный SmoothStep.

Ветка `refactor/application-rebuild`, исходный HEAD продолжения `68124da`, рабочее дерево
до него чистое. Новые незакоммиченные правки — экран `relation-context`, общий поиск
путей в `domains/relations` и перечисленные документы. Предыдущий черновик сохранён.
Core, REST и формат хранения не менялись. Общий docs:check имеет известные пять
битых ссылок на отсутствующий `STORAGE-REFACTORING.md`; итог проверки фиксируется в журнале.

Собственные процессы завершены: сессия `tasks-web-context-layout-20260923` закрыта,
последний сервер 1325956 остановлен. Временные копии `.artifacts/context-layout-wi4Bx1`
и `.artifacts/context-visualization-YR7OJJ`, снимки экрана остаются локальными артефактами.
Следующий шаг при новом замечании — воспроизвести конкретный путь на временной копии,
используя эту реализацию дерева; прежнее закрепление всех координат не возвращать.
