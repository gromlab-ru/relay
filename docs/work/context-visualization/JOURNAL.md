## Реализация первого среза

Добавлены `@xyflow/react` 12.11.6 и ELK.js. Генератором из `apps/web` созданы
`relation-context` (ui-unit), `context-canvas` (вложенный ui-unit), внутренние
`context-explorer`, `context-inspector`, `context-list`, `context-node`, `context-edge`.
Команда каждого запуска: `pnpm run create <ui-unit|ui-component> <имя> <каталог владельца>`.
Начальные файлы адаптированы, экран использует только lazy-фасет.

Домен связей объединяет по ID только страницы одной версии, читает исходный узел
отдельно для случая его отсутствия на первой странице. Все области перечитываются
как один согласованный результат; неудачная подгрузка не публикует половину нового
графа. Лимит — восемь страниц по 50; сведения рёбер не заменяются кратчайшими путями.

Кнопка и отдельный URL подключены. Раскладка ELK работает в Worker; первоначальная
камера у корня, последующие добавления сохраняют старые позиции и избегают наложения
новых карточек. У параллельных отношений разные порты, петля проходит вокруг карточки.
Подключены последовательный список и панель полного содержания.

Первый `pnpm run lint:web` прошёл. `pnpm run typecheck:web` выявил пять локальных
ошибок строгой индексации массива/CSS Module; они исправлены без ослабления типов.
Браузерная приёмка и повторная сборка ещё впереди.

## Замечание пользователя: наложение списка и нечитаемость глубины 3

Пользователь прислал снимок: при активном «Список» поверх строки остаётся крупная
карточка Canvas. Предыдущая проверка клавиатуры/axe не обнаружила дефект визуального
скрытия. `visibility:hidden` родителя допускает `visibility:visible` у дочернего узла;
нужна изоляция всей отрисованной области, сохраняющая отдельно состояние камеры.

Исследование раскладки: ELK получает только размеры и концы рёбер. Порты назначаются
позже, маршруты ELK отбрасываются и заменяются SmoothStep, а при раскрытии новые
координаты смешиваются с прежними вручную. Это разрушает совместную геометрию графа
и ведёт линии через карточки и друг через друга. Плотные подписи усугубляют картину.

Read-only запросы к работающему Playground подтвердили состав API-FI-2:
глубина 1 — 3/2, глубина 2 — 22/30, глубина 3 — 35/99. Данные не изменялись.
Продолжение сохраняет владельцев Canvas/экрана и стандарт чтения сохранённых связей.
План и критерии новой проверки зафиксированы в README до изменений.
