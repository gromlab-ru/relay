# Исследователь связей Web

## Цель и границы

По запросу пользователя от 22 сентября 2026 заменить визуально перегруженную страницу
рабочим местом для поиска сущности, понимания её отношений и добавления недостающих связей.
Визуальный язык — существующие Mantine, Lucide, нейтральные поверхности и токены Relay.
Хранилище и семантика предметных операций сохраняются; миграция не требуется.

## Архитектурный допуск и план

Прочитаны протокол, стандарт интерфейсов, профиль `apps/web/README.md`, оба обязательных
skills; главы Unit Architecture о слоях, зависимостях и колокации; React Reference о
вёрстке, UI, стилях, формах, иконках, генерации TSX, TypeScript и JSX/CSS.

Владелец интерфейса — `compositions/screens/project-relations`: URL, выбор, каталог,
режим просмотра, форма и раскрытие подробностей. Внутренние компоненты без фасетов
не образуют новых архитектурных границ. Данные и SSE поступают через существующие
фасеты `domains/entities` и `domains/relations`. Зависимости направлены в домены/UI/shared;
обратных импортов к экрану нет. REST DTO и предметные правила в экран не переносятся.

1. Каталог с серверным поиском, фильтром вида и независимым продолжением по 40.
2. Выбранная сущность закреплена в URL; связи читаются по 30 в согласованном снимке.
   По умолчанию глубина 1 и все типы. Контракт графа включает также связи между соседями:
   их нельзя выдавать за прямые связи выбранной сущности или считать её степенью.
3. Компактные группы отношений, русские направленные подписи, раскрываемые метаданные
   и Markdown; переход к соседу меняет root и сохраняет историю браузера.
4. Создание в модальном окне с выбранным началом, понятным направлением и сохранением
   ввода при сворачивании/ошибке. Удаление доступно в подробностях явной связи.
5. Светлая/тёмная тема, адаптивность 1440/1024/768/390, доступные названия и клавиатура.

## Критерии и проверки

- При входе нет списка всех рёбер проекта: есть выбор сущности и объяснение сценария.
- В просмотре различаются прямые отношения и расширенная цепочка, направления и источники.
- Большие выборки не маскируются под полные: показаны границы страницы и продолжение.
- Ошибка отличается от пустоты; обновление и конфликт не теряют открытую форму.
- Генерация новых TSX закреплённым CLI; lint/typecheck/build Web, docs:check,
  форматирование изменённых документов и git diff --check.
- Человеческий интерфейс проверяется отдельной headless-сессией agent-browser на
  временных данных; машинный ответ сверяется отдельно. Фактические результаты — в журнале.

## Точка продолжения

Реализованы каталог, группы направленных отношений, раскрытие подробностей и форма.
Человеческая и машинная проверки выполнены на временных данных; результаты в журнале.
Следующий шаг — оценка дизайна пользователем. Общие API и хранилище не изменены.
