с явно обозначенными примерами, изолированный от постоянных данных проекта.

## Границы исходного обсуждения и предметного этапа

- Изучить действующую модель продукта, задач, связей и раздела «Планы».
- Сопоставить согласованное направление с фактическими исходниками.
- Зафиксировать вопросы и предложения для обсуждения; предложение не становится требованием
  без решения пользователя.
- Реализация функционала начинается после согласования сценария и контрактов.

Затронутые владельцы: документация продукта; Core — предметные правила и хранение;
Contracts — виды сущностей и DTO; server-runtime/SDK — REST; CLI/MCP — интерфейсы агентов;
Web — экран «Планы» и взаимодействие с существующими задачами.
Точные границы будущих модулей определяются при проектировании.

## Результат и вопросы обсуждения

Текущее покрытие сверено по коду и сохранено у
[инженерного владельца](../../engineering/implementation/README.md#планирование-сверка-24-сентября-2026).
Согласованный пользователем сценарий «продукт → задачи → план с этапами» добавлен в
[направление развития](../../product/DIRECTION.md#связь-продукта-с-работой) и
[сквозной процесс](../../product/workflows/README.md). Планов в проекте может быть несколько.
Дополнительно пользователь определил план как обоснование начала работы: существования
задачи недостаточно для начала исполнения. Будущий релиз объединяет планы, задачи,
выполненные результаты и необходимые описания; работа по выпуску тоже требует плана.
Требования и граница предложения сохранены в
[направлении](../../product/DIRECTION.md#состав-релиза-и-работа-по-выпуску).

Прежнее предложение релизного типа плана отменено последующим уточнением пользователя.
План — только работа. Релиз создаётся отдельно: при создании выбираются планы состава
и собственный статус выпуска. История прежнего варианта сохранена в журнале.

Действующие документы в корне:

- [PROGRESS-SPEC.md](../../../PROGRESS-SPEC.md) — предметные ответы API по видам,
  отдельные обработчики, расширяемые контракты, актуальная готовность и раскрытие составляющих.
  Прежнее предложение обязательного универсального механизма сводок заменено по уточнению
  пользователя; оптимизация и смена хранения отложены. URL выбирается по реальному API.
- [PLANS-SPEC.md](../../../PLANS-SPEC.md) — только планы работ, этапы, основание выполнения и задачи.
- [RELEASES-SPEC.md](../../../RELEASES-SPEC.md) — самостоятельный релиз, состав из планов,
  собственный статус, планирование выпуска и сохранённый результат.

Полные перечни открытых решений находятся в самих ТЗ. Основные вопросы: переход начала,
кардинальность участия задачи, параллельность, повторное открытие, частичный/повторный выпуск,
состав снимка, точные DTO, лимиты, хранение и миграция. Автоматическая смена колонок задач
не объявлена согласованной. Овервью остаётся будущим потребителем данных.

В ТЗ определены владельцы, человеческие сценарии, будущие машинные контракты,
границы списков и критерии приёмки. Планирование сохраняет продуктовые линки и отдельно
согласует связи Core; прогресс читает эти сведения и не устанавливает отношения при чтении.
