# Очистка удалённых разделов Web

## Цель и границы

По поручению пользователя от 20 сентября 2026 удалить функционал устаревших разделов
сквозным изменением Web, Core, REST/SDK, CLI/MCP и документации. Ориентир — фактические
маршруты и навигация Web, а не отсутствие интерфейса у самостоятельной механики.

- «Обзор», «Планы», «Релизы», «История»: только страницы «В разработке».
- «Прежняя доска»: удалить экран, навигацию, числовые задачи и специализированные данные.
- Скрытые `passport`, `knowledge`, `activity`: удалить страницы и прежний функционал.
- Сохранить «Продукт», «Доски и задачи», «Связи», настройки, общие механизмы хранения,
  ревизий, идемпотентности, блокировок, событий и миграции действующих данных.
- Workspace, local/workspace, выбор проекта, конфигурация подключения и транспорты
  не являются предметом очистки. Случайное имя `legacy` само по себе не основание удаления.

## Контракты и приёмка

Удалённые операции отсутствуют в HTTP/OpenAPI/SDK, справке CLI и discovery MCP.
Удалённый URL не открывает прежнюю доску через catch-all. Заглушки не загружают прежние
агрегаты. Сохранённые разделы читают и изменяют прежние действующие данные.
Схемы новых задач, продукта и графа сохраняют ID, ключи, ревизии, Markdown и квитанции.
Очистка файлов данных ограничивается данными удалённых владельцев; нельзя удалять
каталог блокировки или общую конфигурацию вместе с прежними задачами.

Проверки: типизация всех потребителей, применимые Core/HTTP/CLI/MCP-тесты,
Web lint/typecheck/build и собственная headless-сессия agent-browser на временном проекте.
Человеческие страницы/справка проверяются отдельно от JSON/OpenAPI/MCP.
Документация: `docs:check`, форматирование изменённых файлов, `skills:build/check`, diff-check.
