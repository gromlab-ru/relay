# План очистки

1. Сопоставить Web-маршруты со специализированными службами и фактическими потребителями.
   Проверить отдельно продуктовый прототип, общий граф и синхронизацию проекта.
2. В существующих экранах обзора, планов, релизов и истории оставить `StatePanel`.
   Удалить прежнюю доску и скрытые экраны, их виджеты/домены без оставшихся потребителей.
   Убрать catch-all на прежнюю доску. Сохранить маршруты и операции нового канбана.
3. Удалить специализированные контракты и службы старых страниц из backend/Core,
   REST, CLI и MCP. Общий граф продолжает обслуживать действующие сущности;
   общие механизмы сохраняются у своих владельцев, межюнитные импорты — через фасеты.
4. Определить и проверить очистку прежних данных без изменения режимов и workspace.
   Генерировать SDK из актуального OpenAPI закреплённым генератором.
5. Удалить действующие описания и примеры удалённых возможностей; актуализировать
   техническую архитектуру, справочники, скилл и ссылки. Исторические записи не выдавать
   за действующий контракт; причины изменения сохранить в текущем журнале.
6. Выполнить применимые автоматические и человеческие проверки, обновить досье и индекс.

Браузерный axe обнаружил отсутствие h1 у заглушек. Владелец уровня заголовка —
существующий `ui/state-panel`: добавить узкий параметр h1/h2, страницы явно выбирают h1.
Новых TSX/юнитов не требуется; обычные состояния панелей сохраняют h2. Проверка —
повтор axe и сборка Web.

Архитектурное основание: `apps/web/README.md` и прочитанные references Unit Architecture
(layers, units, dependencies), React Reference (routing, UI, styleguide, TypeScript, JSX).
Для нового TSX сначала прочитать инструкцию генерации и запустить локальный шаблон.
Для SDK сначала прочитать инструкции закреплённого генератора. Новые уровни и универсальные
API ради удаления не вводятся; сохранённая инфраструктура не зависит от удаляемых доменов.
