## 21 сентября 2026 — исправление UI по скриншотам пользователя

Пользователь не принял таймлайн и вид комментариев; форму считает относительно приемлемой.
Предыдущая визуальная проверка не обеспечила качество на коротких сообщениях и частых
однородных событиях. На скриншотах подтверждены разрывы линии между элементами, большие
пустые интервалы, растянутые карточки коротких сообщений и сырые ID критериев в обзоре.

Причина в коде: общий ActivityEntry использовал одну вертикальную композицию для разных
сценариев; отдельный border-left каждого события разрывался внешним Stack gap. Markdown
добавлял собственные внешние отступы поверх отступов карточки.

План зафиксирован в README: отдельное представление сообщений, общий Mantine Timeline,
раскрываемая строка события без технических подробностей в обзоре, компактный Markdown.
Форма и машинные контракты остаются действующими. Исходная база та же a89d923, рабочее
дерево содержит изменения предыдущего этапа; они сохраняются.

Дополнение пользователя: история должна быть существенно плотнее, так как событий много.
Принят формат журнала: одна строка «действие / автор / время / раскрытие» на широком экране,
два ряда на телефоне. Даты группируются по дням. Длинный заголовок в обзоре занимает максимум
две строки, полностью доступен по раскрытию; полный Markdown не обрезается.

Пользователь положительно оценил плотность истории и указал большие боковые поля.
Установлена причина: общий контейнер max-width 880px с автоматическими боковыми отступами,
а не сайдбар задачи. Для истории ограничение снято; журнал использует ширину таба с
обычными внутренними отступами 32px на широком экране и 16px на телефоне.

Реализованы внутренние ActivityFeed и DiscussionMessage штатным генератором; ActivityEntry
переработан в раскрываемую строку. Общий Timeline связывает маркеры без внешнего gap,
завершает линию у последнего события дня и растягивает её вместе с раскрытием. Группируются
только соседние записи дня — порядок sequence сохраняется даже при немонотонном времени.
Обычные значения до/после показываются компактно, Markdown остаётся полным.

Временная база `.artifacts/activity-layout-gKzI3P`, API 4797/Vite 5178 и отдельная сессия
`tasks-web-activity-layout-0921`. Пример повторяет пользовательский: задача без названия,
два коротких комментария и повторяющиеся изменения критерия. Второй пример — 23 сообщения,
длинные заголовки, списки, таблица, код и цитата. Несколько старых событий временной базы
датированы вчера для проверки границы дня при подгрузке; рабочие данные пользователя не менялись.

последнего события группы и остаётся непрерывной при раскрытии. Проверены Enter для раскрытия,
отсутствие ID критерия в обзоре/подписях подробностей, даты сегодня/вчера, подгрузка 20→23,
загрузка длинного Markdown, отказ адресной загрузки сообщения и успешный повтор, публикация
нового сообщения и сохранение черновика между табами. Горизонтального переполнения диалога нет.
Просмотрены обе темы на 1440/1024/768/390. Новые снимки — `.artifacts/activity-layout-*.png`.
Axe раскрытой истории и обсуждения на 1440 — 0 violations/0 incomplete. На 390 dark —
0 violations и прежнее 1 incomplete контраста многострочного заголовка задачи; визуально

Contracts/Core/REST/CLI/MCP, пагинация и правила публикации в этой визуальной итерации не менялись.
