# Дизайн карточки на доске

## Цель и статус

Предложение по запросу пользователя от 21 сентября 2026: современное компактное
отображение задачи на доске и при перетаскивании. Пользователь согласовал предложение
сообщением «давайте»; реализовано и проверено 22 сентября 2026. Окно содержимого
задачи вне границ работы.

## Владельцы и план

- Представление принадлежит композиции `project-board`, координация переноса —
  `task-kanban`, чтение предметных сводок — `domains/board-tasks`.
- Основания: профиль `apps/web/README.md`, Unit Architecture (колокация),
  React Reference (вёрстка), единый стандарт интерфейсов.
- План исследования: сверить карточку, overlay и данные; предложить визуальную
  иерархию и стабильную геометрию; сохранить ограничения и критерии приёмки.
- План реализации после отдельного поручения: единое представление карточки;
  согласованные метрики drag/placeholder; компактные показатели; браузерная приёмка.
  При изменении границы юнитов дополнительно прочитать правила фасетов и зависимостей.

## Предлагаемый дизайн

### План принятой реализации

1. Сохранить существующие границы: `task-card` предоставляет единое визуальное
   представление для sortable-карточки и превью, `task-column` публикует превью как
   часть контракта колонки. Новые TSX и новые юниты не нужны: перерабатываются два
   существующих компонента. CSS принадлежит `task-card`.
2. `domains/product` предоставляет пакетный хук кратких целей по ID: дедупликация,
   запросы порциями по 100 через существующий адаптер, кеш SWR и обновление по SSE.
   Колонка запрашивает только первую отображаемую цель каждой загруженной задачи;
   остальное показывает точным числом `+N`. Никаких новых REST/дисковых контрактов.
3. Передавать подготовленную цель в карточку и снимок drag; сохранять точные размеры
   placeholder, убрать масштабирование sortable и overlay, сохранить анимацию drop.
   Во время жеста карточки используют снимок данных; клавиатурный фокус восстанавливается.
4. Проверить исходный и новый drag на временной базе, затем обе темы и четыре ширины,
   клавиатуру, сеть/SSE/конфликт, машинные ответы, lint/typecheck/build и документацию.

Дополнительно прочитаны профиль Web, правила зависимостей и фасетов Unit Architecture,
React Reference: данные/SWR, UI/Mantine, стили, строгие правила TS/TSX/CSS.
Граф остаётся направленным: композиции → домены → infra, колонка → карточка;
общая разметка остаётся внутри владельца, обратных импортов не добавляется.

Карточка с нейтральной поверхностью, рамкой 1px, скруглением 12px, отступами 14–16px,
небольшой тенью. Использовать Mantine, Inter, Lucide и существующие токены темы.
Заголовок 14px/20px, вес 600; метаданные 12px/16px. Цвет служит предметным сигналам.
Статус уже задан колонкой: повторяющий цветной бейдж каждой карточке не нужен.

1. Шапка: ключ задачи и ручка переноса в постоянно зарезервированной области.
2. Заголовок: до трёх визуальных строк, полный текст доступен при наведении и фокусе.
   В данных заголовок остаётся однострочным обычным текстом.
3. Контекст: одна цель с названием и индикатором `+N` оставшихся целей.
   Фича — Puzzle/фиолетовый, сценарий — Route/бирюзовый; для implementation
   конкретный вид требуется разрешить по данным, а не по ключу.
4. Приёмка: подпись «Критерии 3/5» и тонкая полоса прогресса 3px.
   Ноль критериев не означает готовность; 5/5 не означает завершение всей задачи.
5. Нижняя зона: отдельный тональный сигнал «Ожидает 2 задачи» при наличии блокеров;
   нейтральные предметные показатели зависимостей/связанных задач при наличии места.
   Не смешивать родителя, зависимости и прочие связи одним общим числом.

Простой задаче достаточно ключа и названия. Не резервировать пустые строки всех
возможных метаданных; высота зависит от содержания. Ориентир заполненной карточки —
170–220px, но не фиксированная высота для любых данных. Длинные ключи, счётчики и
цели должны обрезаться или компактно сворачиваться без горизонтального переполнения.
Нижняя зона может занимать две строки, но её состав и переносы замораживаются на время drag.

Hover меняет рамку и тень, не размер и не положение. Фокус обозначает всю карточку.
На touch ручка постоянно видима с зоной нажатия не менее 44px без увеличения
геометрии при начале жеста. Клик открывает задачу; drag после порога движения
не должен вызывать открытие. Метрики по умолчанию информационные, не чекбоксы.
Блокировка завершения не означает запрет любого перемещения между колонками.

## Перетаскивание

- Одна общая визуальная разметка для карточки и превью; sortable — только у оригинала.
  В overlay нет фокусируемых интерактивных элементов и повторного sortable ID.
- Геометрия border-box измеряется перед переносом: ширина, высота и точка захвата.
  Эти значения сохраняются до завершения drop-анимации вместе со снимком данных.
- Превью использует те же шрифт, line-height, padding, border и области иконок.
  Фиксация только внешней высоты не гарантирует совпадения внутренней разметки.
- Перенос — только translate; scaleX/scaleY не должны растягивать карточку.
  Не применять декоративные scale/rotate. Эффект подъёма создаётся тенью.
- В месте вставки один placeholder с сохранённой геометрией; фон тонирован,
  граница пунктирная, содержимое скрыто без схлопывания. Полупрозрачная копия текста
  под превью не нужна. Подсветка колонки и placeholder объясняют цель переноса.
- Drop 150–180ms, при reduced motion без анимации; отмена возвращает прежний порядок.
  Локальная вставка немедленная, серверная ошибка возвращает подтверждённое состояние.

## Данные и совместимость

Текущий TaskSummary уже содержит acceptance, productLinks, blockers, dependencies,
related и parentId. Первый вариант возможен без изменения API: «Реализует · N»,
«Критерии · X/Y», «Ожидает N задач», раздельные счётчики отношений.

Для окончательного дизайна нужны читаемые названия целей. Сводка списка либо
пакетное разрешение на уровне страницы должны давать ограниченный preview и total,
без отдельного запроса каждой карточки и без загрузки всего каталога продукта.
Прогресс прямых подзадач, если будет добавлен, требует полного серверного агрегата;
его нельзя выводить из blockers или загруженных 40 задач.
Незагруженное/ошибочное значение не заменяется нулём. Обновления не меняют overlay
посреди жеста; после него отображаются актуальные значения.
Хранение менять не требуется; расширение API потребует отдельной проверки контрактов
и совместимости потребителей. Пагинация доски остаётся по 40 с продолжением.

## Критерии будущей приёмки

- Два состояния одной карточки совпадают по внешним размерам с допуском 1 CSS px;
  внутренние строки, шрифты и иконки не смещаются. Проверить подъём, переход колонки,
  автопрокрутку, отмену и отпускание между карточками разной высоты.
- Простая/заполненная/заблокированная задача, длинные названия и ключи, 0/часть/все
  критерии, много целей и связей читаются в обеих темах на 1440/1024/768/390.
- Клавиатура: поднять, выбрать место, отпустить, отменить, восстановить фокус;
  touch: прокрутка не конфликтует с захватом ручки. Цвет дублируется текстом.
- SSE, сетевой отказ и конфликт ревизий не дают скачков во время жеста и не теряют
  подтверждённый порядок. Не выводить серверную блокировку как общий запрет drag.
- Человеческий результат проверять отдельно от JSON; расширенные агрегаты сверять
  на задачах за границей первой страницы. Не добавлять Web-автотесты; использовать
  изолированную agent-browser-сессию на временной базе, lint/typecheck/build.

## Результат и точка продолжения

Реализованы единое представление оригинала и превью, цель с названием и числом
остальных целей, прогресс приёмки и раздельные отношения. В компактных колонках
метаданные используют 11px/16px, заголовок — 14px/20px; отступы 12/14px. Заполненная
карточка с двумя рядами отношений может превышать первоначальный ориентир 220px:
измеренный пример — 247px, с трёхстрочным заголовком — 267px. Высота не фиксирована.

Исправлена подтверждённая причина скачка: незаполненный initial rect заменял
фактическую геометрию запасными 288×100. Теперь исходный DOM измеряется перед
локальным переносом; размеры и данные сохраняются в overlay. Placeholder резервирует
те же размеры. Запись 30 кадров подтвердила стабильность до конца drop-анимации.
Фокус восстанавливается после окончания записи, когда ручка снова доступна.

Прошли lint:web, typecheck:web и build:web; обе темы и четыре ширины, мышь,
клавиатура/отмена, автопрокрутка, ошибки сети и конфликт во время drag. Названия
101 отдельной цели прочитаны при продолжении 40 → 80 → 101. Axe обеих тем:
0 violations/0 incomplete. На физическом сенсорном устройстве проверка не проводилась;
эмуляция подтверждает размеры ручки и обработку синтетического удержания/отмены.
