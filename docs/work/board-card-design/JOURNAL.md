# Журнал дизайна карточки доски

## 21 сентября 2026 — исследование и предложение

Запрос: спроектировать внешний вид карточки на доске и при переносе с учётом
реализаций, зависимостей и критериев; пользователь сообщает о небольшом изменении
размеров при drag. Реализация приложения в этой работе не выполняется.

Прочитаны обязательный протокол, правила документации, продуктовый контекст,
стандарт интерфейсов, Web AGENTS/README, навыки Unit Architecture и React Reference,
колокация и вёрстка. Сверены связанная работа task-card-mechanics, Web-контракт,
состояние реализации, компоненты доски, стили, доменная схема и Contracts.
Исходная ветка `refactor/application-rebuild`, HEAD `4c306b0`, дерево чистое.

Подтверждено статическим чтением:

- TaskCard и TaskCardPreview дублируют содержимое, но используют разные элементы:
  UnstyledButton/div для заголовка и ActionIcon/span для ручки.
- TaskKanban уже измеряет width/height initial rect и передаёт их обёртке preview.
  Preview получает height:100%; это не доказывает совпадение внутренних метрик.
- Карточка использует CSS.Transform.toString, который может включать масштабирование.
  Фактическое ненулевое масштабирование в пользовательском сценарии не проверялось.
- Placeholder вычисляет естественную высоту заново; его размеры не передаются
  из active. Содержимое остаётся видимым с opacity:0.25.
- Карточка уже показывает критерии, блокеры и смешанный счётчик отношений;
  productLinks в списке есть, но карточка их не отображает.
- Названий/конкретного типа реализации и сводки всех подзадач в TaskSummary нет.

Причина искажений остаётся гипотезой до браузерных замеров. Предложены общая
визуальная разметка, фиксация border-box и снимка данных на весь жест, перенос
без масштаба, placeholder тех же размеров и тональные предметные показатели.
Размеры и цвета в предложении — дизайн-ориентиры, не результат визуальной приёмки.

Проверены документы `docs/product/applications/web/README.md`,
`docs/engineering/implementation/applications.md` и `apps/web/README.md`:
они описывают действующий продукт; менять их требования и состояние из-за ещё
непринятого предложения не требуется. Предложение сохранено отдельно от требований.

Браузер, JSON-сценарии и Web lint/typecheck/build не запускались: код и контракты
не менялись, задача — проектирование. Проверки документов фиксируются ниже.

Проверки завершены: `pnpm run docs:check` — 193 документа, 984 ссылки, ошибок нет;
проверка скилла в этой команде — 17 файлов, 64 ссылки, ошибок нет.
`pnpm exec prettier --check` для двух файлов досье и индекса работ успешен;
`git diff --check` успешен. Навигация: индекс работ → предложение → журнал.
Точка продолжения обновлена; приложение не реализовано, браузерных артефактов нет.

## 21 сентября 2026 — начало реализации

Пользователь согласовал предложение. Сверены HEAD `4c306b0` и дерево: только документы
этой работы. План реализации и владельцы уточнены в README. Найден существующий
пакетный REST-запрос продуктовых целей по refs: имена можно показать без расширения API.
Планируется читать только первую цель каждой загруженной карточки, порциями по 100;
общий каталог продукта не загружается. Новый TSX не требуется: существующее превью
становится общей визуальной реализацией, sortable остаётся отдельной обвязкой.

Браузерная диагностика на временном проекте juYsYUeT, API 4798/Vite 5178,
сессия `tasks-web-card-0921`: исходная карточка 256×168,796875; после Space overlay
288×100. Подтверждён fallback из-за null initial rect в onDragStart. Исправление
измеряет DOM до обновления локальной проекции; запасные размеры удалены.

Реализованы общее представление, тональные цели, прогресс, раздельные показатели,
пакетное чтение названий по 100, сохранённые размеры placeholder и translate-only.
Первый проход проверок обнаружил слишком широкий тип обработчика dnd-kit и
кликабельный article; исправлены типизированной обвязкой и семантической кнопкой
открытия с расширенной зоной. Повторные lint:web, typecheck:web, build:web успешны.
Первый запуск временной фикстуры отклонён из-за type:web; исправлен на frontend.

## 22 сентября 2026 — браузерная приёмка

Проверки на API 4798/Vite 5178, временная база board-card-check-GnlGYy:

- Мышь и клавиатура: оригинал, overlay и placeholder 256×247, внутренние top/height
  всех пяти блоков совпали. После перемещения размеры сохранены; случайного открытия
  модального окна нет. Снимок `board-card-drag-light.png` просмотрен.
- Возврат фокуса сначала не срабатывал: ручка была disabled во время сохранения.
  Исправлен эффектом после окончания записи; подтверждено «Перенести WEB-2» после
  успешного переноса, отмены и серверной ошибки.
- API-отметки критериев видны через SSE: 3/5 у заблокированной задачи и 1/1 у задачи
  на проверке. JSON подтверждает acceptance и blocked независимо друг от друга.
- Сетевая ошибка POST move: сообщение, возврат подтверждённой колонки inbox,
  отсутствие зависшего placeholder. Конкурентный update во время drag не меняет
  текст и метрики overlay; отпускание показывает конфликт, затем новое название.
- Ошибка чтения целей: «Цель недоступна» и кнопка повтора. После восстановления
  запросов данные восстановились через SWR раньше попытки нажать кнопку; явный
  ручной повтор в этом проходе не подтверждён. Устаревший ref отклонён браузером.
- Полное название и название цели видны в подсказке при фокусе; Enter открывает
  окно задачи, Escape закрывает. Перенос и открытие используют отдельные кнопки.
- Сняты восемь кадров 1440/1024/768/390 в обеих темах. Просмотрены 1440 dark,
  1024 light, 768 dark и 390 light; горизонтальная прокрутка принадлежит доске.
- Axe dark: 0 violations, 0 incomplete, 20 passes. Первый проход выявил неоднозначный
  aria-label у обычного span `+N`; атрибут удалён, сохраняется обычный текст и title.
- Эмуляция iPhone 15: ручка 24px и расширенная область по 10px (44px), opacity 0.6,

- Временная продуктовая доска: 101 задача с разными целями. Реально пройдены

- Автопрокрутка длинной колонки при drag: scrollTop изменился на 650px;
