# Удобство CLI и MCP для агента

## Цель и границы

По поручению пользователя от 22 сентября 2026 изучить возможности Relay и начать
проверку агентских интерфейсов на существующих данных `p2p-rental` в Playground.
Первый этап — обнаружение проекта, обзор продукта, поиск задачи и восстановление
требований через команды чтения. Оценивать обнаруживаемость, полноту, объём ответа,
пагинацию и возможность продолжить после ошибки.

Владельцы: CLI, MCP, общие контракты сущностей и графа. Исходники и данные продукта
на этом этапе не изменяются. После сообщения пользователя о восстановлении MCP
выполнены реальные вызовы чтения через подключённые инструменты.

## Состояние и продолжение

Статус: первичные чтения CLI и MCP проверены; аудит продолжается.

Прочитаны протокол, устройство продукта, инструкции Playground, ТЗ аренды и контракты
CLI/MCP. Проверены выбор workspace-проекта, обзор, доски, задачи, связи, адресное
чтение документа, критерии, обсуждения, первая страница истории, пустой поиск и ошибка.
Результаты и воспроизведение — в [журнале](JOURNAL.md).

Подтверждены: перехват `--version` глобальным флагом CLI вместо версии снимка,
непомещающийся в стандартный бюджет обзор и неполные команды продолжения.
Для задачи два интерфейса чтения дают взаимодополняющие сведения; граф позволяет
восстановить связи, но требует дополнительных адресных чтений.

В MCP прочитаны проекты, четыре доски двумя страницами с версией снимка, WEB-4,
связи задачи и DOC-2. `entity_get` показывает агенту только краткий текст со ссылкой
на structuredContent; `product_get` возвращает видимое полное содержание документа.
Пользователь сообщил о текущей доработке раздела документов: его проверка отложена,
наблюдение DOC-2 не считается окончательным дефектом.
На FEATURE-2 проверена полнота агентского ответа: product_get содержит требования,
product_context — сценарии, реализации и готовность, но оба не содержат задач.
Отдельный board_tasks_list с productTarget возвращает три задачи и их ключи.
Следующий шаг: обсудить компактную сводку связей и задач в ответе чтения фичи,
чтобы агент не собирал её несколькими запросами.
Проверки записи, повторов и конфликтов ещё не проводились.

Рабочая копия: ветка `refactor/application-rebuild`, исходный HEAD `f8615e9`.
Уже имеются параллельные изменения Web, Core, contracts и документации; они не относятся
к этому аудиту. Собственные изменения — это досье и ссылка из индекса работ.
Собственные серверные процессы не запускаются.
