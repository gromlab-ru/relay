# Реализации приложений: страницы и готовность по задачам

**Статус: реализовано, проверено и принято пользователем.** Основание — поручение пользователя 21 сентября 2026.

## Цель и границы

Первый этап: страницы реализаций фич и сценариев приложения и его дерево.
Полное требование, собственный вклад, зависимости и реализующие задачи должны быть
удобны для чтения. Общие проектные фичи/сценарии — отдельный следующий этап.

Готовность сценарной реализации вычисляется по всем задачам с явной ссылкой на её ID:
нет задач — `none`, все в `done` — `done`, иначе — `partial` («В работе»).
Отменённая задача с сохранённой ссылкой не подтверждает выполнение. Удаление ссылки,
задачи и возврат из done меняют результат следующего чтения/SSE. По последующему
уточнению FI агрегирует выбранные SI и существующие собственные задачи; полный
каскад исправлен и проверен в [досье проектных требований](../project-requirement-progress/README.md).

  доменов и UI; обратных импортов и новых доменных границ не требуется.

## Проект UI/UX до реализации

1. Шапка: тип требования, его название, ключ реализации, приложение и статус.
2. Основная колонка: полный Markdown исходного требования, затем собственный вклад.
   Текст не прячется за вкладкой или раскрытием и не заменяется кратким описанием.
3. Задачи — открытый оформленный список с ключом, названием, статусом и переходом
   на доску; прогресс по полному набору, порции по 40, явное продолжение.
4. Боковая область: исходная фича/сценарий, приложение, адресные зависимости.
   На узком экране области последовательно переходят в одну колонку.
5. Пустота объясняет отсутствие реализации и действие на доске. Ошибка загрузки
   отличается от отсутствия задач, есть повтор. Отозванное участие явно отмечено.
6. В дереве сохраняются отдельные раскрытие сценариев и переход в реализацию;
   повторные скрытые списки задач убираются. Статусы соответствуют странице.
7. Ручная готовность убирается из редактора реализации; черновики описания сохраняются.
