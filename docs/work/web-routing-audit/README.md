# Карта страниц и аудит роутинга Web

**Статус: аудит завершён, 20 сентября 2026 года. Исправления не выполнялись.**

## Цель и границы

По поручению пользователя составить карту страниц фронтенда: URL, назначение,
вложенность, переходы и нестыковки роутинга. Основание — текущий код и действующие
продуктовые контракты. Исправление поведения требует следующего поручения.

Уточнение пользователя: особо выделить нарушения последовательности, когда дочерний
сценарий вместо логического продолжения родительского адреса открывается в новой ветке.
Сопоставить иерархию сущностей, URL, меню, редактирование и возврат.

Владелец результата — `docs/engineering`: фактическая карта маршрутов и ограничения.
Исследуемые владельцы: `apps/web/src/app/router` (дерево URL), композиции `relay`,
`project`, `product` и экраны (навигация и состояния), `domains/project` (ID/slug),
продуктовые и задачные домены (ссылки на записи).

## План и проверки

1. Сверить дерево маршрутов, фасеты экранов и назначение страниц с контрактами Web.
2. Проследить меню, построение ссылок, канонизацию, query/hash, возвраты и неизвестные URL.
   Отдельно разобрать цепочки приложения/реализации, фичи/сценария и доски/задачи.
3. Сохранить фактическую карту у инженерного владельца; отделить подтверждённые
   расхождения от вопросов продуктового решения. Добавить ссылки из навигации библиотеки.
4. Выполнить доступные адресные проверки, Web lint/typecheck/build, `docs:check`,
   форматирование изменённых документов и `git diff --check`. Отметить ограничения проверки.

Прочитаны обязательный протокол, правила библиотеки, стандарт интерфейсов, инструкции
Web, skills Unit Architecture и React Reference, профиль React SPA и главы о слоях
и маршрутизации. Работа описывает существующие границы; новые юниты, фасеты и зависимости
не проектируются. Основные контракты: [Web](../../product/applications/web/README.md),
[продуктовые страницы](../../product/applications/web/PRODUCT.md),
[состояние приложений](../../engineering/implementation/applications.md).
