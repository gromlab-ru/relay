# Компактные поля Web

**Статус: реализовано и проверено.**

Во время [приёмки критериев задачи](../task-acceptance-criteria/README.md) пользователь
указал на чрезмерно крупные поля во всём приложении и поручил уменьшить их через Mantine.

Владелец стандартных размеров — ui/themes. Текущий defaultProps задаёт md (42px)
для Input, TextInput, Textarea и Select. Меняем на sm (36px), согласуем используемые
InputBase, NativeSelect, NumberInput и Autocomplete. Убираем локальный md у полей настроек.
Кнопки и остальные компоненты сохраняют свои отдельные контракты размеров.

MarkdownField принадлежит ui/markdown-field: уменьшаем отступы, используем шрифт sm
темы и начальную высоту 4 строки; явно заданные размеры больших описаний сохраняются.
Форма критерия использует компактное значение по умолчанию.

Прочитаны профиль Web, React Reference UI/forms/styleguide, Mantine configuration/usage;
архитектурные границы не меняются. Проверки: фактические размеры полей критериев,
настроек и выбора связей; обе темы и мобильная ширина, ввод и Markdown, адресный lint,
typecheck и сборка (общие проверки имеют известный исходный блокер product-page.tsx).

Проверены фактические размеры: TextInput/Select/InputBase 36px, шрифт 13px;
краткое описание в две строки 53px; Markdown около 103px. Проверены форма критерия,
оба поля настроек и селекторы подзадач. Обе темы и 1440/1024/768/390 просмотрены,
аудит диалога не выявил нарушений. Обновлён контраст ошибки и Markdown-подсказки.

Адресный lint и отдельная Vite-сборка успешны. Строгий общий typecheck блокируется
прежними unused в product-page.tsx; проверка без unused-флагов прошла.
Документация Web и состояние реализации актуальны, журнал содержит основания.
Следующий шаг — пользовательская оценка. Изменения без коммита на базе abbdb7e;
собственные процессы и браузер закрыты вместе с проверкой критериев.
