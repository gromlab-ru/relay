# Цели реализации карточки по типу доски

**Статус: реализовано и проверено; общие lint/typecheck ограничены исходными ошибками.**
Основание — поручение пользователя 21 сентября 2026:
сохранить текущий дизайн и UX карточки, технически ограничить цели типом её доски.

## Контракт и границы

- Продуктовая доска: только общие фичи и сценарии.
- Доска приложения: только объявленные активные реализации этого `applicationId`,
  отдельно фичи и сценарии. Выбор другого приложения отсутствует.
- Инфраструктурная доска: блок реализации отсутствует, новые цели запрещены.
- По дополнительному поручению пользователя ссылка «Все связи и контекст задачи»
  удаляется из карточки: UI общего контекста отложен. Пустой раздел на инфраструктуре не остаётся.
- Второе уточнение: сохранённые цели различаются иконками и цветами — фича (пазл,
  фиолетовый), сценарий (маршрут, бирюзовый), включая имплементации приложения.
  По последнему уточнению толстый боковой бордер убирается: остаются цветные иконки,
  лёгкая заливка и обычная равномерная рамка. Правка принадлежит CSS task-context;
  проверка — обе темы и реальные сохранённые цели.
- В выборе только «Фичи» / «Сценарии»; поиск, предпросмотр, множественный выбор
  и текущая компоновка сохраняются. Вид цели определяется доской, не ключом поиска.
- Серверный фильтр `implementationTarget=feature|scenario` применяется до пагинации.
  Web читает по 20 целей, существующие связи показывает по 5 с продолжением.
- Core проверяет новые связи при создании/обновлении и совместимость при смене доски.
  Несовместимый перенос отклоняется с предложением снять связи; автоматической потери нет.
- Хранение v3 не меняется. Прежние связи читаются без миграции и могут быть удалены;
  редактирование содержания не перепроверяет прежние связи, явная замена проверяет
  весь переданный набор. Снятая
  имплементация остаётся исторической ссылкой, но заново не выбирается.

## Владельцы и план

1. Contracts/Core: дополнить каталог целей фильтром; правила принадлежности связей —
   в существующем `BoardTasksService`, под общей блокировкой.
2. SDK: генерация закреплённой версией из актуального OpenAPI, без ручных правок.
3. Web: `task-editor` читает доску самой задачи адресно через `domains/boards`,
   передаёт её вложенному `task-context`. При смене доски выбор перемонтируется.
   `task-context` сохраняет представление; `domains/product` публикует фильтр.
   Новых юнитов и TSX нет. Зависимости композиция → домены → infra, фасеты `index.ts`.
   Для цветовых/иконных акцентов `domains/product` передаёт вид требования отдельно
   от вида записи implementation; визуальная проекция и CSS остаются у task-context.
   Дополнительно прочитаны React Reference (иконки, стилизация, CSS); используем
   существующие Lucide и токены Mantine. Проверка: оба типа прямых целей и имплементаций,
   светлая/тёмная тема и узкий экран, без зависимости от ключей или названий.
4. Core/API-проверки матрицы, чужого приложения, переноса, совместимости и пагинации;
   Web lint/typecheck/build; собственная agent-browser-сессия на временных данных,
   обе темы, четыре ширины, клавиатура, сеть, конфликт и черновик.
5. Актуализировать канонические документы и журнал; docs:check, форматирование, diff-check.

Прочитаны протокол, стандарт интерфейсов, профиль `apps/web/README.md`, инструкции
Web/Core/Contracts/SDK/Server Runtime, Unit Architecture (слои и зависимости),
React Reference (формы, данные, UI/Mantine, общий стиль, TS/TSX), REST API Codegen (CLI).
Ближайшие владельцы установлены; новых границ и обратных импортов не требуется.
