# Прогресс в каталоге приложений

Статус: реализовано и проверено. Основание — поручение пользователя 22 сентября 2026.

## Цель и контракт

На карточке приложения показать бизнес-прогресс и общий прогресс: процент и число
выполненных задач относительно полного количества. Область — собственная доска приложения
(её slug совпадает со slug приложения). Бизнес-задача имеет хотя бы одну productLink
на фичу, сценарий или их реализацию; несколько ссылок не умножают задачу. Выполнено —
только done; cancelled остаётся в знаменателе. Подзадачи считаются самостоятельными задачами.
Пустота не означает 100%: показывать «Нет связанных задач» или «На доске пока нет задач».

## Владельцы и план до реализации

Прочитаны протокол, стандарт интерфейсов, Web AGENTS/README, React Reference
(данные, UI, стили, SWR, Mantine, TSX-генерация и правила TS/JSX/CSS), Unit Architecture
(слои и зависимости), локальные шаблоны и template-generation.

1. `domains/board-tasks`: согласованный обход сводок доски порциями по 100 на одной
   версии, накопление только четырёх счётчиков; ограниченный повтор BOARD_CHANGED.
   Публичный SWR-хук, существующая синхронизация SSE, изоляция по проекту и slug.
   REST/SDK и хранение не меняются, миграция не требуется.
2. `compositions/screens/product-applications`: внутренний сгенерированный компонент
   двух индикаторов, без нового фасета. Бизнес-показатель — акцентный, общий — спокойный;
   подписи, процент и закрыто/всего видны без наведения. Mantine Progress, доступные
   подписи, skeleton и ошибка с повтором. Карточка сохраняет переход в приложение.
3. Проверки: lint/typecheck/build Web; временная база, независимая agent-browser-сессия,
   обе темы и 1440/1024/768/390; пустота, 0/часть/100%, дубли ссылок, >100 задач,
   SSE, сетевой отказ и повтор; отдельно сверка JSON. docs:check, prettier, diff --check.

Документы владельцев: [Web](../../product/applications/web/PRODUCT.md),
