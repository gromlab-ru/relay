# Общие разделы навигации проекта

## Цель и границы

По поручению пользователя вынести документы из меню продукта в общую библиотеку проекта.
После релизов показать разделитель и пункты «Документы», «Инфраструктура»,
«Связи проекта», «История».
«Продукт» и «Доски и задачи» первоначально свёрнуты, раскрываются только пользователем.
Инфраструктура на этом этапе — самостоятельная страница «В разработке».

Статус: реализовано и проверено. Изменены Web-навигация и адреса существующей библиотеки; данные,
REST/CLI/MCP и дисковая схема сохраняются. Миграция хранения не требуется.
Каталог продолжает читать существующий полный снимок и фильтровать его локально.

## Владельцы и план

1. `compositions/layouts/project/ui/project-navigation` — порядок, разделитель и раскрытие.
2. `app/router` — проектные маршруты документов и крошки; `layouts/product` — совместимые
   перенаправления с query/hash/state. Существующие экраны документов и их потребители —
   новые ссылки. Провайдер данных остаётся у `domains/product-demo`, подключение —
   через публичный lazy-фасет `product-snapshot`.
3. Новый `compositions/screens/infrastructure` — самостоятельная проекция маршрута,
   созданная локальным генератором; единственный lazy-фасет, зависимость от `ui/state-panel`.
4. Обновить продуктовый контракт, карту URL, техническое состояние. Выполнить lint,
   typecheck, build Web, docs:check, Prettier и diff --check; проверить человеческие
   переходы отдельно от сохранности REST JSON на временной базе через agent-browser.

Основания: протокол Relay, единый интерфейсный стандарт, профиль в `apps/web/README.md`,
Unit Architecture (слои, зависимости, юниты, профиль), React Reference (routing,
styling, генерация TSX, quality и строгие правила TS/TSX), локальные шаблоны.
Новых обратных зависимостей или глубоких импортов план не вводит.

## Точка продолжения

Готовы порядок разделов, разделитель, свёрнутые группы, проектная библиотека с
перенаправлениями старых адресов и заглушка инфраструктуры. Lint/typecheck/build Web,
docs:check и diff --check прошли. В браузере проверены обе темы и четыре ширины,
клавиатура, создание/чтение/редактор, черновик после reload, сетевая ошибка с повтором,
SSE и конкурентная правка в двух вкладках. Подробности — в журнале.

Следующий шаг — пользовательская приёмка навигации. Развитие содержания инфраструктуры
и отделение хранения документов от продуктовой модели требуют самостоятельной работы.
Ветка `refactor/application-rebuild`, правки не закоммичены. Исходные изменения
исследователя связей сохранены. Собственный сервер 4897 и браузерная сессия закрыты.
Временная база и скрипт находятся в игнорируемом `.artifacts/navigation-check`.
