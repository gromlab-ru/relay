# Ключи продукта и самостоятельные реализации

Статус: реализовано и проверено. Основание — согласованный пользователем план и поручение
приступить к реализации. [План](PLAN.md), [журнал](JOURNAL.md).

## Цель и границы

Постоянная идентичность всех сущностей и связей определяется ID. Публичные интерфейсы
принимают ID или читаемый ключ. Ключи: FEATURE-N, SCENARIO-N, префикс приложения,
PREFIX-FI-N и PREFIX-SI-N. Реализации хранятся отдельно внутри каталога приложения по ID.
Конфликт ключей не объединяет записи и не разрушает связи; доступ по ID сохраняется.
Web должен давать удобные адреса, поиск связей и согласованный с дизайном показ ключей.

## Владельцы и источники

- Core product: идентичность, ключи, реализация, миграция, разрешение ссылок и готовность.
- REST/OpenAPI и SDK: транспорт общего контракта; project-runtime — local/HTTP.
- CLI/MCP: человекочитаемые команды, инструменты, ограниченные ответы.
- Web domains/product: адаптация и кеш; product-demo: существующая проекция экранов;
  compositions: интерфейс; app/router: маршруты. Только публичные фасеты, без обратных
  зависимостей от доменов к композициям и router.
- Документы: [продукт](../../product/entities/product/README.md),
  [Web](../../product/applications/web/PRODUCT.md), [контракт](../../reference/PRODUCT.md),
  [реализация](../../engineering/implementation/product.md).

Прочитаны обязательный протокол, единый стандарт, Unit Architecture, React Reference,
профиль React SPA, зависимости, маршрутизация и получение данных. При переходе к новым
областям реализации чтение профильных инструкций дополняется.
