# План реализации

## Контракты

1. ID неизменяемы; ссылки и физические пути используют ID. Ключи выдаются под блокировкой,
   не пересчитываются при чтении. FEATURE/SCENARIO имеют проектные последовательности.
   FI/SI первоначально наследуют номер требования; дальнейшая смена ключа не меняет связь.
2. Общий resolver принимает ключ или ID, проверяет тип и проект. Неоднозначность ключа —
   явная ошибка с кандидатами; ID остаётся доступен. Результаты содержат ID и ключ.
3. Реализации — отдельные записи с ревизией, авторством, историей, active и basis.
   Путь applications/<applicationId>/{features,scenarios}/<implementationId>.json;
   приложение — application.json. Состав — представление, не копия описаний.
4. Миграция возобновляема, сохраняет старые ID, Markdown, готовность, квитанции и историю
   исходного scope. Массовая запись состава не может публиковаться частично.
5. Выбор целей — компактный серверный список с фильтрами и продолжением; подробности
   загружаются адресно. Задачи и планы сохраняют только типизированные ссылки по ID.
6. Web: ключ рядом с названием, название визуально главное. Поиск ключа/названия,
   различение требования и реализации, клавиатура, копирование, старые ID-адреса.
   Кеш и черновики используют ID; ключи — в публичных адресах.
   Просмотр сценария вложен в фичу: /product/features/FEATURE-N/scenarios/SCENARIO-N;
   короткий прежний адрес перенаправляется, неверный родитель явно отклоняется.
   Раскрытие каталога не меняет URL и хранится как личное состояние по ID проекта.

## Порядок

- Core: ключи/resolver, тесты конкуренции/повторов/конфликтов, отдельные реализации,
  совместимое чтение и миграция, адресный доступ и компактные проекции.
- REST/OpenAPI/SDK, local/HTTP backend, CLI/MCP и связи задач/планов.
- Web: единое представление ключей, продуктовые экраны, маршруты и выбор связей.
- Проверки и документация после каждого смыслового этапа.

## Приёмка

Core/API: конкуренция, повтор, разные проекты, дубли ключей с доступом по ID,
миграция/повтор/прерывание, сохранность ссылок и готовности, ограниченность выборок.
CLI/MCP: отдельно человеческий вывод и JSON, схемы и русские описания.
Web: lint/typecheck/build, собственная headless agent-browser-сессия на временном
хранилище; обе темы, 1440/1024/768/390, прямые адреса, поиск и связи, черновики,
сеть, конфликт, Back/Forward и визуальная оценка. Новых frontend-автотестов нет.
Документы: docs:check, форматирование, diff-check, сборка/check скилла при изменении.
