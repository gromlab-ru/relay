# План перестройки библиотеки

1. Инвентаризировать источники и зафиксировать противоречия.
2. Ввести обязательный протокол всех работ агента и правила документации.
3. Переписать продуктовый обзор, карту возможностей, модель и пять приложений.
4. Отделить актуальное устройство от истории; перенести корневые материалы внедрения.
5. Обновить навигацию, проверить ссылки, форматирование и источники скилла.

## Приёмка

Локальная документация Web: добавить ссылки на библиотеку и исправить формулировки
о переходе на постоянные данные в `apps/web/README.md`. Владелец — документация
приложения вне `src`; архитектурные слои, фасеты, импорты и API не меняются.
Прочитаны `apps/web/AGENTS.md`, skills Unit Architecture и React Reference,
профиль React SPA и раздел Quality; приложение исследовано по маршрутам и провайдеру.
Проверки: ссылки, форматирование, локальные обязательные lint/typecheck/build.

- В корне нет тематических плана и журнала первого внедрения продукта.
- У каждого из пяти приложений есть продуктовый контракт и ссылка на технические источники.
- Действующие правила готовности и связей не требуют чтения моковых спецификаций.
- От общей концепции можно перейти к реализации, истории и следующему действию.
- `docs:check`, `skills:check`, форматирование изменённых документов и `git diff --check` пройдены.
- Архив сохраняет происхождение; прежние проверки не выдаются за новые.
