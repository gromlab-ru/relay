# Множественные доски проекта

**Статус: реализован этап досок, готов к пользовательской приёмке, 19 сентября 2026 года.**

## Цель и границы

Реализовать доски «Продукт», по одной доске каждого приложения и «Инфраструктура».
Пользователь задал slug в URL и собственную папку каждой доски с её сведениями и задачами.
Миграция не требуется: продукт разрабатывается. Новая модель задач — следующий этап.
Основание: [ознакомление](../web-prototype-orientation/README.md) и последующее поручение.

## План и владельцы

1. Core: модель доски, каталог `boards/<slug>/board.json` и `tasks/`, две системные доски
   при init; slug приложения, уникальность, неизменность адреса и создание его доски.
   Составная запись восстанавливается после прерывания под общей блокировкой.
2. Server/OpenAPI/SDK: постраничное чтение досок и чтение по slug; общий сервис Core.
3. Web: домен `domains/boards` владеет чтением и SSE-кешем; каркас проекта и его
   навигация показывают упорядоченный каталог; новый экран показывает отдельную доску.
   Форма приложения получает slug; старые задачи не подмешиваются в новые доски.
4. Проверить Core, серверные контракты, SDK, lint/typecheck/build Web и сценарии браузера.

Прочитаны протокол, единый стандарт, инструкции Core/Server/SDK/Web, skills
Unit Architecture, React Reference, REST API Codegen и генерации. Применены профиль
React SPA, слои, зависимости, маршрутизация и правила создания TSX.
Новые зависимости направлены `композиции → domains/boards → infra/tasks-api`;
домен не зависит от роутера или композиций. UI создаётся локальным генератором.

Контракты: название — одна строка, slug — адрес без разметки; внутренние связи по ID.
Списки имеют ограничение и продолжение, кеш разделён по проектам. Перенос старых данных
и смена модели задач не входят в работу. Общие колонки берутся из конфигурации проекта.
