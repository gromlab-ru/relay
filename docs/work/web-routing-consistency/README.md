# Последовательные маршруты Web

**Статус: завершено и проверено, 20 сентября 2026 года.**

## Цель и основание

Пользователь поручил сохранить карту во фронтенде и исправить нестыковки,
найденные в [аудите](../web-routing-audit/README.md). Область — только Web.
Каноническая [карта находится во фронтенде](../../../apps/web/ROUTING.md).

## План и владельцы

1. `app/router`: общий каркас `product`; явные маршруты редакторов; реализация
   `applications/:applicationRef/implementations/:entityRef[/edit]`; короткие прежние
   адреса — совместимые входы. Неработающий `work/:id` больше не обещает страницу.
2. `layouts/product`: общий Outlet и восстановление прокрутки. Отдельная маршрутная
   граница `product-snapshot` подключает существующий ProductDemoProvider только
   каталогам/редакторам полного снимка. Адресное чтение сценария/реализации остаётся
   адресным. Поднимается существующий ProductOutlet, его прежний публичный путь удаляется.
3. Существующие экраны/виджеты продукта: ссылки на реализацию в контексте приложения,
   URL редактора, проверка родителя, прямые возвраты без legacy-якоря и перенос query/state.
4. `project-board`: query открытой задачи и закрытие по прямой ссылке сохраняют фильтры;
   канонизация сохраняет hash. `relay`: адаптер внутренних Markdown-ссылок через Link
   подключается существующим UI-провайдером; local-префиксатор сохраняет query/hash/state.
5. Обновить карту, продуктовый контракт, инженерное состояние и журнал. Проверить
   lint/typecheck/build, адресные сценарии agent-browser, docs:check и форматирование.

## Архитектурный допуск и контракты

Прочитанные протокол, стандарт, skills Unit Architecture / React Reference и профиль
React SPA дополнены правилами юнитов/зависимостей, строгим style guide, инструкцией
генерации TSX и skill Template Generation. Новые компоненты создаются локальным CLI.
Зависимости: router → композиции → доменные/UI-фасеты; маршрутная граница подключает
доменные данные, не реализует их. Markdown-адаптер — внутренняя часть relay, UI не
зависит от router. Обратных зависимостей не добавляется.

ID, данные и ключи черновиков сохраняются; миграции хранилища нет. Канонический Web-адрес
реализации включает приложение, прежняя ссылка остаётся входом. Списки/пагинация не меняются.
Проверка: прямой и старый URL, неверный родитель, меню, просмотр → edit → сохранение/отмена,
Back/Forward/reload, возврат в каталог/приложение, задачи с query/hash, Markdown без reload.
