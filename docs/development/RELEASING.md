# Выпуск пакетов Relay

[Документация](../README.md) → Разработка → Релизы

Репозиторий: <https://github.com/gromlab-ru/relay>.

## Единая версия и совместимость

Начиная с `0.6.0`, каждый релиз выпускает **все три npm-пакета с одной версией**,
даже если изменения затронули только один компонент:

| Пакет                   | Манифест                   | Архив                         |
| ----------------------- | -------------------------- | ----------------------------- |
| `@gromlab/relay-cli`    | `apps/cli/package.json`    | `apps/cli/.artifacts/npm/`    |
| `@gromlab/relay-server` | `apps/server/package.json` | `apps/server/.artifacts/npm/` |
| `@gromlab/relay-mcp`    | `apps/mcp/package.json`    | `apps/mcp/.artifacts/npm/`    |

**Совпадение полной версии, включая суффикс RC, обозначает проверенный совместимый комплект.**
Например, CLI `0.6.0`, Server `0.6.0` и MCP `0.6.0` проходят совместную проверку в CI.
Совместимость смешанных версий не гарантируется. Устанавливайте и обновляйте используемые
пакеты вместе, закрепляя одинаковую точную версию вместо независимых диапазонов.

Версия CLI служит опорной при проверке; версии Server и MCP обязаны совпадать с ней.
Команда обновления меняет все три манифеста. Приватные workspaces сохраняют `0.0.0`,
их код собирается внутрь дистрибутивов. Серверный архив включает Web.

Единый Git-тег — `v<version>`, например `v0.6.0` или `v0.7.0-rc.1`.
Прежние теги `cli-v…`, `server-v…` и `mcp-v…` остаются историей независимых выпусков;
новый workflow запускается по общему тегу. Каждый выпуск имеет один GitHub Release.

## Подготовка версии

В тематической ветке выберите следующую свободную версию, большую текущей:

```bash
pnpm run release:version 0.6.1
```

Команда проверяет SemVer и одновременно обновляет три npm-манифеста, сохраняя остальные
поля. Она также подходит для перехода с независимых версий на общую `0.6.0`.
Git-коммит и тег создаются отдельно. В `pnpm-lock.yaml` workspace-зависимости заданы
через `link:`, поэтому смена собственных версий пакетов не изменяет lockfile.

Добавьте раздел с выбранной версией в каждый `apps/{cli,server,mcp}/CHANGELOG.md`.
Если компонент не менялся, укажите совместный выпуск с остальными пакетами.

```bash
pnpm install --frozen-lockfile
pnpm run release:check v0.6.1
pnpm run release:notes v0.6.1
pnpm run build
pnpm run check
pnpm run package:check
```

`release:check` отклоняет разные версии, неверный тег, неполный состав выпуска и
публичный workspace, который не включён в процесс публикации. Проверка входит в
`build`, `check` и `package:check` и выполняется до публикации.

`scripts/package.mjs` упаковывает скомпилированный JavaScript и внешние production-зависимости.
`scripts/smoke-relay.mjs` независимо устанавливает все три архива и проверяет:

- версии установленных пакетов и исполняемых команд;
- CLI напрямую и через local-сервер;
- серверную статику, Swagger и API;
- workspace с двумя базами и одинаковыми номерами задач;
- MCP, выбор проекта и отказ после остановки общего сервера.

Для отдельной диагностики сборки существуют `package:check:cli`, `package:check:server`
и `package:check:mcp`. Полную установочную проверку выполняет `package:check`.

## Публикация через CI

Для каждого из трёх npm-пакетов настройте Trusted Publishing:

- GitHub organization: `gromlab-ru`;
- repository: `relay`;
- workflow: `release.yml`;
- разрешённая операция: `npm publish`.

После проверки изменений и слияния pull request создайте один тег на принятом коммите:

```bash
git tag v0.6.1
git push origin v0.6.1
```

`release.yml` выполняет общий выпуск:

1. Проверяет тег, одинаковые версии и описания всех трёх пакетов.
2. Вызывает CI: сборка всех пакетов, проверки на Node.js 22/24 и установочные проверки.
3. Сохраняет три проверенных архива в одном артефакте `npm-packages`.
4. Получает этот артефакт по ID с проверкой digest, проверяет все архивы и существующие
   npm-версии, затем последовательно публикует CLI, Server и MCP через OIDC с provenance.
5. Создаёт общий GitHub Release с описаниями всех компонентов после успешной публикации комплекта.

Обычные версии получают npm dist-tag `latest`, предварительные — `next` и признак prerelease
в GitHub Release. Публикация использует ровно проверенные архивы, без повторной сборки.

Публикация в npm не атомарна: при сетевом сбое часть пакетов может уже появиться в registry.
Повторите неуспешные задания того же запуска, чтобы использовать те же архивы.
Уже опубликованные версии пропускаются только при совпадении SHA-512 integrity; другой
архив с тем же номером или ошибка доступа к registry останавливают выпуск до первой
новой публикации. Остальные пакеты допубликуются с той же версией.

Одновременно выполняется один релиз (`npm-publication`, без прерывания текущего запуска).
Дождитесь его завершения перед отправкой следующего тега: GitHub concurrency хранит
только один ожидающий запуск.

## Локальная публикация

После сборки и проверки всего комплекта авторизуйтесь в npm с правом публикации в `@gromlab`:

```bash
npm login
npm whoami
pnpm run release:publish v0.6.1
```

Одна команда публикует все три готовых архива. Без аргумента тег вычисляется из общей
версии манифестов; при наличии `RELEASE_TAG` проверяется его значение. Проверка integrity
и выбор dist-tag работают так же, как в CI.

Запускайте публикацию через `pnpm run`: npm-обёртке нужен `npm_execpath`, который задаёт
pnpm. Проверка метаданных и формирование описания также работают через `node` без установки зависимостей.
