## Скилл продукта

[`skills/tasks-cli`](../../skills/tasks-cli/SKILL.md) — инструкции для оркестратора
и субагентов, работающих с Tasks на одном хосте. Главный файл объясняет модель
и основной цикл; `reference` содержит подробные сценарии, команды и восстановление.
Весь необходимый материал находится внутри каталога скилла.

В пользовательском проекте:

```bash
npx skills add gromlab-ru/tasks-cli --skill tasks-cli
```

Выбор конкретного агента:

```bash
npx skills add gromlab-ru/tasks-cli --skill tasks-cli --agent opencode
```

Установщик размещает выбранный скилл в каталоге агента; OpenCode использует
проектный `.agents/skills/tasks-cli`. Установка добавляет инструкции, а CLI запускается
через `npx @gromlab/tasks-cli`. После установки перезапустите OpenCode, чтобы он
обнаружил скилл в новой сессии.

Skills 1.5.26 требует Node.js 22.20+, рекомендуется Node.js 24.
Сам Tasks поддерживает Node.js 22+; HTTP-режим появился в 0.3.0.
Команда установки из GitHub требует наличия скилла в выбранном опубликованном источнике.

## Скиллы разработки

Существующий [skills-lock.json](../../skills-lock.json) перечисляет четыре внешних скилла:

| Скилл                 | Источник                       |
| --------------------- | ------------------------------ |
| `react-reference`     | `gromlab-ru/js-reference`      |
| `rest-api-codegen-ru` | `gromlab-ru/rest-api-codegen`  |
| `svg-sprites-ru`      | `gromlab-ru/svg-sprites`       |
| `unit-architecture`   | `gromlab-ru/unit-architecture` |

Из корня репозитория:

```bash
pnpm run skills:install
```

Эквивалентная команда:

```bash
npx --yes skills@1.5.26 experimental_install
```

Она читает lock-файл и восстанавливает перечисленный набор в `.agents/skills`.
Проверьте результат и наличие `SKILL.md` у каждого скилла: команда экспериментальная,
а отдельные сетевые ошибки могут быть выведены в лог.

`computedHash` описывает содержимое установленной папки; он не является Git-коммитом
для checkout. Без `ref` восстановление берёт текущий источник и может обновить хеши
lock-файла. Изменения lock-файла следует просматривать при обновлении скиллов.
Это восстановление набора источников, а не аналог `pnpm install --frozen-lockfile`.

## Версионирование

| Путь                  | Роль                                                         |
| --------------------- | ------------------------------------------------------------ |
| `skills/tasks-cli/**` | Исходники распространяемого скилла, входят в Git             |
| `skills-lock.json`    | Источники внешних скиллов, входит в Git                      |
| `.agents/skills/**`   | Все проектные копии скиллов, исключены из Git без исключений |

Локальные скиллы, включая `template-generation`, также находятся вне Git.
Скиллы без источника в lock-файле автоматически не восстанавливаются после клонирования;
при необходимости их добавляют локально.

Установленная копия `.agents/skills/tasks-cli` также исключена из Git.
Продуктовые правки выполняются в `skills/tasks-cli`, затем обновляется установка.
Обычная сборка и запуск проекта не устанавливают скиллы автоматически.

## Изменение и проверка

1. Обновите `SKILL.md` и относящиеся к сценарию материалы `reference`.
2. Сверьте команды с CLI и публичной документацией. Основной файл должен оставаться
   достаточным для начала работы, подробности подключаются по необходимости.
3. Выполните `pnpm run docs:check`: проверяются также ссылки скилла относительно
   его собственного корня. Ссылки на соседний `docs` из установленного скилла недоступны.
4. Проверьте обнаружение скилла:

   ```bash
   npx skills@1.5.26 add ./skills/tasks-cli --list
   ```

5. Из отдельного временного проекта установите скилл по абсолютному пути исходников:

   ```bash
   npx skills@1.5.26 add /absolute/path/to/tasks/skills/tasks-cli --skill tasks-cli --agent opencode --yes
   ```

   Подставьте реальный путь. Проверьте установленный главный файл и все references,
   затем назначение оркестратором, исполнение конкретного ID без переменных URL,
   передачу результата и повторяемый отчёт.

Установка в текущий рабочий проект меняет его lock-файл, поэтому для проверки используйте
отдельный каталог. Перед выпуском `pnpm run package:check` проверяет README npm
и версионную ссылку на исходники продуктового скилла.
