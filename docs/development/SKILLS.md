# Скиллы Relay

[Документация](../README.md) → Разработка → Скиллы

## Скилл продукта

[`skills/relay`](../../skills/relay/SKILL.md) — готовое руководство для оркестратора и
работника: от паспорта и плана до исполнения, приёмки, выпуска и передачи контекста.
Главный файл даёт самостоятельный рабочий алгоритм, подробности находятся в `references`.

Локальная установка собранного пакета:

```bash
npx skills@1.5.26 add ./skills/relay --skill relay --agent opencode
```

После публикации изменений в репозитории:

```bash
npx skills add gromlab-ru/relay --skill relay
npx skills add gromlab-ru/relay --skill relay --agent opencode
```

Имя скилла — `relay`; прежний `relay-cli` заменён. Обновите установленную копию через
установщик. После обновления в OpenCode завершите и перезапустите его: текущая сессия
может сохранять ранее загруженные инструкции. Установщик Skills требует Node.js 22.20+;
для разработки рекомендуется Node.js 24. Пакеты Relay поддерживают Node.js 22+.

## Исходники и результат

```text
src-skills/relay/
├── skill.md
├── bundle.json
└── references/
scripts/skill-bundle/
├── build.mjs
├── check.mjs
├── lib.mjs
├── generate.mjs
├── bundle.test.mjs
└── examples.test.mjs
skills/relay/
├── SKILL.md
├── bundle-info.json
└── references/
```

- `src-skills/relay` — авторские инструкции и манифест пакета.
- `scripts/skill-bundle` — сборщик, генераторы справочников и проверки.
- `skills/relay` — распространяемый результат; целиком хранится в Git.
- `.agents/skills` — локальные установленные копии, исключённые из Git.

Главный исходник называется `skill.md`. Обнаруживаемый `SKILL.md` создаётся только в
готовом пакете. Другие каталоги с именем `skills` для исходников или сборщиков не
создаются: это предотвращает дублирование при обнаружении скиллов установщиком.

## Что собирается

Манифест [`bundle.json`](../../src-skills/relay/bundle.json) явно определяет:

- `files` — авторские материалы относительно `src-skills/relay`;
- `documents` — включаемую документацию продукта относительно корня репозитория;
- `generated` — справочники из определений CLI и схем Core;
- `aliases` — соответствие навигации исходных документов материалам пакета;
- `watch` — исходники контрактов, изменения которых требуют пересборки и ревью текста.

Справочник CLI получает команды, аргументы и параметры из Commander. Справочник
проектных документов получает поля, enums, обязательность и defaults из Zod-схем Core.
Операционные объяснения и смысл условий приёмки остаются авторскими материалами.

Сборщик разбирает Markdown, переписывает настоящие ссылки, сохраняет примеры кода и
проверяет якоря. Необъявленная локальная зависимость останавливает сборку. Обязательные
материалы доступны внутри пакета после его копирования отдельно от монорепозитория.

`bundle-info.json` содержит детерминированные хеши входных файлов. В сборке нет дат
генерации и текущего Git SHA, поэтому одинаковые источники дают одинаковый результат.
Пакет готовится и проверяется в `.artifacts`, затем обновляется каталог распространения.
Ошибка проверки не публикует неполный результат.

## Изменение и проверка

После `pnpm install --frozen-lockfile`, из корня репозитория:

```bash
pnpm run skills:build
pnpm run skills:check
pnpm run skills:test
pnpm run docs:check
npx skills@1.5.26 add ./skills/relay --list
```

Сборка использует TypeScript-исходники через tsx и не требует запуска Relay Server,
сборки Web или установки скилла. `skills:check` собирает ожидаемое содержимое во
временном каталоге и сравнивает с `skills/relay`, не исправляя его. Ручная правка,
устаревший файл, лишний файл или забытый прежний скилл дают ошибку.

В `pnpm run check` входят проверка актуальности и тесты скилла. Его сквозной тест
в `scripts/skill-bundle/examples.test.mjs` выполняет через MCP сценарий непосредственно
из собранного `EXAMPLES.md`: проверяются запросы,
связи, ревизии, успешная приёмка и ветка неуспешной проверки. Внешняя работа с кодом и
установка представлены фикстурой; производственный выпуск тест не выполняет.

Редактируйте источник или соответствующую каноническую страницу `docs`, затем
пересобирайте пакет. Сборка отражает изменения контрактов, но смысл инструкций при
изменении поведения всё равно требует ревью.

## Скиллы разработки

Внешние скиллы перечислены в [skills-lock.json](../../skills-lock.json):

```bash
pnpm run skills:install
```

Эта команда восстанавливает инструменты разработки в `.agents/skills`. Для продуктового
скилла используются `skills:build`, `skills:check` и отдельная установка готового `relay`.
