## Для кого предназначена доска

Основной процесс — оркестратор и субагенты на одном хосте. Оркестратор создаёт
и распределяет задачи, контролирует зависимости и принимает результаты. Агенты
работают через CLI/API. Человек наблюдает через UI и может дополнять задачи.

Запуск агентов и выбор модели выполняет ваш инструмент оркестрации.
Tasks предоставляет общую JSON-базу задач и операции над ней.

## Где находятся мои задачи

Выполните `config get --format json` и посмотрите `meta.configPath`, `meta.storagePath`.
В HTTP это пути сервера, с `--local` — выбранной локальной базы.
`storageDir` разрешается относительно конфига, а не рабочего каталога исходников агента.

Для проверки локальной копии задайте `--local --config /work/project/tasks.config.json`.
Если проект новый, начните с `init`; существующий конфиг повторно не создаётся.
[Настройки и приоритеты](reference/CONFIGURATION.md).

## Задача видна, но claim не работает

Обычный `list` показывает всю незавершённую работу. `claim` дополнительно требует
свободного исполнителя, статуса из `readyStatuses` и выполненных зависимостей.
В основном процессе субагент получает уже назначенную задачу и `claim` не выполняет.
Её `ready: false` ожидаемо, если исполнитель уже задан. При отсутствии назначения
или чужом исполнителе нужно сообщить оркестратору.

```bash
npx @gromlab/tasks-cli get 1 --fields id,status,assignee,blockedBy,ready --format json
npx @gromlab/tasks-cli links 1
npx @gromlab/tasks-cli list --ready
```

Подставьте ID своей задачи. `TASK_ASSIGNED` означает существующее назначение;
его изменение и выбор следующей работы контролирует оркестратор.

## После release задача не появилась в ready

`release` снимает исполнителя и сохраняет статус. Для повторного захвата статус
должен входить в `readyStatuses`; по умолчанию это `todo`.
Оркестратор согласует возврат в очередь и при необходимости снимает чужое назначение
через `release --force`. [Передача работы](guides/WORKFLOW.md#продолжение-и-передача-работы).

## Почему завершение детей или отмена не разблокировали работу

Родительство и зависимости — отдельные графы. Завершённые дети не меняют статус
родителя автоматически. Зависимость удовлетворена только при
`satisfiesDependencies: true`; начальный `cancelled` этим свойством не обладает.
Откройте `links` и проверьте конфигурацию статусов.

## Конфликт ревизии

Комментарий или отчёт тоже изменяет `revision` всего документа.
При `REVISION_CONFLICT` перечитайте задачу, сравните своё изменение с новым состоянием
и примените согласованный patch с актуальной ревизией.
В UI сравнение версий сохраняет введённый текст и позволяет выбрать значения полей.

## Сервер недоступен

1. Проверьте, что сервер запущен на этом хосте и выбран правильный порт.
2. Сверьте `--server-url`, `TASKS_SERVER_URL`, `server.url`. URL задаётся без `/api/v1`.
3. При `SERVER_INCOMPATIBLE` обновите и перезапустите сервер; обновление CLI не меняет
   уже запущенный процесс.
4. Если порт занят, выберите другой `--port` и передайте соответствующий URL агентам.

Для прямой записи используйте `--local --config <конфиг-оркестратора>`.
HTTP-ошибка не перенаправляет команду автоматически в `.tasks` агента.
Пример восстановления — [оркестрация](guides/ORCHESTRATION.md#прямая-запись-и-восстановление).

## Потерян ответ на добавление отчёта

Запись могла сохраниться до разрыва. Повторите прежний `--request-id`, автора
и содержимое, включая заголовок, summary и session-id. Если ключ генерировал CLI,
возьмите его из `error.details.requestId`.

Тот же ключ работает после рестарта и при `--local` на той же базе. Если получен
`IDEMPOTENCY_CONFLICT`, сравните исходную запись: новый текст означает новый шаг
и требует нового ключа. Для создания задачи, смены полей и назначений сначала
проверьте фактическое состояние — эти операции автоматически не повторяются.

## Не все задачи попали в ответ

`list` скрывает конечные статусы; включите их через `--all`.
Затем проверьте `meta.hasMore` и `meta.nextCursor`: `--all` у списка задач не снимает
байтовый бюджет. При `RESPONSE_TOO_LARGE` выберите поля, страницы или больший `--max-bytes`.
Для истории `--all` означает один полный ответ. [Правила вывода](reference/OUTPUT.md).

## Браузер показывает старые данные

Сверьте серверный проект, фильтры и статус соединения в шапке.
Для большой колонки используйте «Показать ещё». Счётчики групп показывают полную
базу, а поиск — размер текущей выборки.

После восстановления SSE данные перечитываются. Сообщение об ошибке хранилища
означает, что нужно проверить конфиг и `validate`. Черновики локальны для браузера
и вкладки; очистка browser storage удаляет их.

## Git слился, но validate сообщает ошибку

Текстовое слияние может создать цикл, отсутствующую ссылку или два независимых
документа с одним ID. Согласуйте JSON, имена файлов, ссылки и вложенные записи,
затем повторите `validate`. [Git и сохранность базы](guides/GIT.md).

## База требует миграции

При `MIGRATION_REQUIRED` выполните явный локальный `migrate` выбранного хранилища.
При `MIGRATION_IN_PROGRESS` повторите прерванную миграцию с тем же конфигом.
Исходники и таблица ID сохраняются в служебном каталоге.
[Порядок обновления](guides/MIGRATION.md).

Полный перечень диагностик: [коды ошибок](reference/ERRORS.md).
Если ответа нет, создайте [issue](https://github.com/gromlab-ru/tasks-cli/issues),
указав версию CLI и Node.js, команду, режим local/HTTP и код ошибки. Для воспроизведения
подойдёт минимальный пример задач с теми же связями.
