# Терминальный вывод

[Документация](../README.md) → Справочники → Терминал

В примерах `relay-cli` означает исполняемую команду пакета. Для запуска через npx
замените её на `npx @gromlab/relay-cli`.

Содержание: [цвета](#цвета), [представления](#представления), [ID](#числовые-id).

По умолчанию CLI выводит оформленный текст. Все представления используют одну
тему: цвет статуса, значок, ID задачи, жирный заголовок и приглушённые метаданные.

## Цвета

Значения по умолчанию:

| Элемент                              | Вид                                     |
| ------------------------------------ | --------------------------------------- |
| `todo`                               | Голубой `○ К работе`                    |
| `in_progress`                        | Жёлтый `● В работе`                     |
| `review`                             | Фиолетовый `◇ На проверке`              |
| Успешный конечный статус             | Зелёный `✓`; для `done` — `Выполнена`   |
| Остальные конечные статусы           | Серый `−`; для `cancelled` — `Отменена` |
| Блокеры                              | Красный `!` с количеством или номерами  |
| Номера, автор, время, служебные поля | Приглушённый текст                      |

Для произвольных статусов сохраняются их имена; свойства конечного статуса
и удовлетворения зависимостей берутся из конфигурации. Блокеры показываются
отдельно от статуса. Значки и подписи позволяют читать результат без цвета.
В рабочем списке у заблокированной задачи сохраняется подпись статуса,
а рядом выводится `! ждёт #2, #3`. Показываются до трёх ID, затем количество
остальных; все зависимости можно прочитать через `links`. В карточке и дереве
у заблокированной задачи `todo` используется подпись `Ожидает`.
Сохранённое значение статуса не меняется.

`--color auto` — режим по умолчанию. Автоматический цвет включается для TTY,
отключается при `TERM=dumb`, непустом `NO_COLOR` и `FORCE_COLOR=0`.
Другое заданное значение `FORCE_COLOR` включает автоматический цвет, если его
не запретили `NO_COLOR` или `TERM=dumb`. Явный флаг `always`/`never` имеет приоритет.
JSON никогда не содержит ANSI-кодов, в том числе в сообщениях об ошибках.

### Цвета проекта

Укажите `color` в нужном статусе `.relay/config.json`. Например, чтобы сделать
проверку синей, измените значение `statuses.review`:

```json
{ "terminal": false, "satisfiesDependencies": false, "color": "blue" }
```

Поддерживаются `black`, `red`, `green`, `yellow`, `blue`, `magenta`, `cyan`,
`white`, `gray`, `none`. Значение `none` оставляет сам статус без цветовых кодов.
Без настройки применяется стандартная тема. В `config get` виден текущий цвет.
Одинаковый цвет используется в карточке, списке, дереве, связях и обзоре конфига.
Значок и семантика завершения определяются свойствами статуса, независимо от цвета.

## Представления

```bash
relay-cli list
relay-cli list --all
relay-cli list --ready
relay-cli list --group backend
relay-cli overview
relay-cli overview 1 --limit 10
relay-cli get 3
relay-cli get 3 --full
relay-cli tree 1
relay-cli links 6
relay-cli comment list 3
relay-cli log list 3
relay-cli log search 3 --query "проверка"
relay-cli group list
```

- Список: отдельные секции групп с таблицами ID, названий, статусов и исполнителей.
  Группы упорядочены по имени; «Без группы» показана последней. В секции задачи идут по ID.
  По умолчанию видны незавершённые задачи (`terminal: false`), включая заблокированные.
  `--all` включает историю, `--status` выбирает заданный статус. Пустые группы скрыты.
  Счётчики относятся к текущей странице; заголовок показывает «показано N из M» по фильтру.
  Число задач ограничено только бюджетом `--max-bytes` или явным `--limit`.
  Если выборка не помещается, отображается курсор продолжения. Когда открытых задач нет,
  CLI предлагает `list --all`; пустая выборка по фильтрам имеет отдельное сообщение.
- Узкий терминал: секции групп с компактными карточками и переносами вместо тесной таблицы.
- Карточка: рамка с основными полями, описание, результат и счётчики контекста.
  `--full` включает комментарии и отчёты.
- Обзор: полные счётчики области и ограниченные разделы прогресса, готовой работы,
  проверки и блокеров. Для каждого раздела видно количество показанных и всех строк;
  внешние зависимости отмечены явно. Байтовый бюджет сокращает строки, сохраняя счётчики.
- Связи: названия и номера родителей, детей, зависимостей и блокеров.
- Дерево: ветви с номерами и цветными статусами, подзадачи по порядку номеров.
- Отчёты: цвет по типу, заголовок, автор, местное время и краткое саммари.
  `log get` открывает весь отчёт по его ID.
- Markdown: подсветка заголовков, выделений, ссылок и кода. Базовая лексическая
  подсветка поддерживает JSON, JS/TS, shell и HTTP. Исходные маркеры Markdown,
  пустые строки и отступы сохраняются; длинные строки переносятся.

Ширина берётся из терминала; для перенаправленного вывода можно задать `COLUMNS`.
Диапазон оформления — 24–160 колонок, по умолчанию 100. ANSI-последовательности
не занимают колонки, emoji и широкие символы учитываются по экранной ширине.
Курсор продолжения выводится одной копируемой строкой.

## Числовые ID

Новые задачи получают `1`, `2`, `3` и далее в пределах общего хранилища.
ID равен максимальному существующему плюс один и выделяется под той же блокировкой,
что и создание задачи. Он сохраняется в поле `id` и не зависит от фильтра,
сортировки, страницы или статуса. В таблицах он отображается как `#3`,
в командах используйте `3`. Отдельного поля `number` нет.

```bash
relay-cli create --title "Первая задача" --actor orchestrator
relay-cli get 1
relay-cli status 1 in_progress --actor backend-agent
```

Старое хранилище с UUID перенесите командой `migrate --actor human`.
Имена файлов и все ссылки тоже станут числовыми; исходники и соответствие ID
сохранятся в локальной резервной копии. После переноса используйте CLI,
поддерживающий формат задач v2.
