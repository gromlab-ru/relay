# Постоянные релизы

Самостоятельные релизы используют общие правила Core через Web, REST, [CLI](CLI.md)
и [MCP](MCP.md). Состав выбирается из [планов работ](PLANNING.md).

`release` — самостоятельная сущность с ключом `REL-<номер>`, ревизией, обозначением версии,
описаниями, плановой датой и `planIds`. Собственных этапов и задач нет.
Один релиз включает от 1 до 200 планов целиком; повтор ID запрещён. План может участвовать
в разных релизах, обозначение версии не является уникальным адресом.

## Состояния

`planned` допускает незавершённые планы. `cancelled` может быть явно перепланирован.
`released` фиксируется участником и требует завершённых, фактически готовых планов.
Новые включения отменённых планов запрещены; прежнее отменённое включение отображает
неготовность и требует пересмотра состава. Статусы планов и колонки задач не меняются.
Готовность до сохранения формы также читается серверной операцией preview.

Выпущенный релиз доступен для чтения. Его сохранённый результат отделён от актуальных
планов; повтор записи возвращает первоначальную квитанцию. Фиксация информации не
запускает публикацию, Git или CI/CD.

## Самодостаточный снимок

В одной транзакции сохраняются статус, автор, фактическая дата и технические записи
`release-snapshot` / `release-snapshot-entry`. Они не входят в публичный каталог.
Содержание каждой записи снимка — Markdown массивами строк на диске; архивные планы
сохраняют также строгую предметную структуру для прежнего представления состава.

Снимок включает планы, этапы, задачи и критерии, все обязательства задач, их продуктовые
цели и предметных родителей требований, проект и паспорт продукта, прямые прикреплённые материалы состава
и релиза. Сохраняются тексты, ID, ключи, ревизии и основание включения. Полный граф проекта
для выбора состава не используется. Будущие правки исходных текстов и готовности не
изменяют сохранённый результат.

Предел — 10000 записей и 48 МиБ исходного содержания снимка; дополнительно действуют
физические пределы записи 16 МиБ и общей транзакции 128 МиБ. Превышение прекращает всю
фиксацию, без частичного выпуска. Снимок читается страницами с постоянной версией.

Архивные адреса источников — сведения о происхождении сохранённого результата.
Технические записи снимка не образуют отдельный активный граф: текущие предметные
связи принадлежат релизу и выбранным планам. Публикация снимка не дублирует их.

После продуктовой записи владелец явно согласует группу `release-composition`:
релиз → проект (`part-of`), релиз → выбранный план (`includes`). Текущий граф не используется
для повторного построения исторического снимка. Ключи повтора, история, продуктовые линки
и связи публикуются общей восстанавливаемой операцией.
