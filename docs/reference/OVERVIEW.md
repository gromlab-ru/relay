## Область

```bash
npx @gromlab/tasks-cli overview
npx @gromlab/tasks-cli overview 1 --limit 10
npx @gromlab/tasks-cli overview 1 --format json
npx @gromlab/tasks-cli overview --review-status qa,acceptance
```

Последний пример требует соответствующих статусов в конфиге.
`overview [id]` читает один согласованный проверенный снимок. Без ID область —
весь проект; с ID — задача и все её потомки по `parentId`. Автор не нужен.
Внешние зависимости проверяются по полному графу.

## Разделы

1. **Прогресс:** задачи с непосредственными детьми и счётчики этих детей.
   Вложенные родители тоже включены. Порядок — по ID.
2. **Готовы к работе:** тот же критерий, что у `list --ready`, включая обычные
   родительские задачи, если они свободны и удовлетворяют правилам. Порядок — по ID.
3. **На проверке:** задачи в выбранных неконечных статусах. По умолчанию это
   `review`, если он определён и неконечный; иначе раздел пуст.
4. **Основные блокеры:** неудовлетворённые прямые зависимости открытых листовых
   задач области. Родительские агрегаты не увеличивают влияние только из-за наличия детей.

`--review-status` задаёт статусы через запятую. Неизвестный статус даёт `UNKNOWN_STATUS`,
конечный — `INVALID_REVIEW_STATUS`. Отдельный тип «эпик» для подсчёта прогресса не нужен.

## Влияние блокеров

| Поле                        | Значение                                                                  |
| --------------------------- | ------------------------------------------------------------------------- |
| `blockedCount`              | Сколько открытых листовых задач области непосредственно ждёт этот блокер  |
| `unblocksCount`             | Для скольких из них это единственная неудовлетворённая зависимость        |
| `readyAfterCompletionCount` | Сколько разблокируемых задач также свободны и находятся в `readyStatuses` |

Это результат гипотетического успешного завершения одного блокера. Разблокировка
не равна готовности к захвату: у задачи может быть исполнитель или другой статус.
Транзитивные потомки не добавляются к прямому влиянию.

Очередь проверки и блокеры сортируются по убыванию `readyAfterCompletionCount`,
затем `unblocksCount`, `blockedCount`; равенство разрешается меньшим ID.
Сам блокер может ждать другие задачи — его `blockedByCount` это показывает.

Блокер за пределами выбранного дерева имеет `outsideScope: true` и пометку в тексте.
Его влияние относится только к задачам выбранной области. Отменённая зависимость
остаётся блокером, пока не выполнена успешно или не пересмотрена сама связь.

## Счётчики

- `counts` — все карточки области.
- `leafCounts` — только карточки без детей.
- `progress.items[].children` — непосредственные дети конкретного родителя.

Во всех случаях есть `total`, `open`, `completed`, `terminal`, `byStatus`.
`completed` определяется `satisfiesDependencies`, `terminal` — свойством `terminal`.
Число конечных без успеха равно `terminal - completed`. `byStatus` содержит все
настроенные статусы, включая нулевые значения. Счётчики разных областей не складываются.

## Ограничение вывода и JSON

`--limit` задаёт максимум строк каждого раздела: `1–100`, по умолчанию `5`.
Байтовый бюджет может дополнительно уменьшить число строк с сохранением полных
счётчиков и хотя бы одной строки каждого непустого раздела. Если минимальная
сводка не помещается, возвращается `RESPONSE_TOO_LARGE`.

| Поле `data`                               | Содержимое                                    |
| ----------------------------------------- | --------------------------------------------- |
| `root`                                    | Выбранная задача или `null` для всего проекта |
| `version`                                 | Версия согласованного снимка                  |
| `limit`                                   | Запрошенный максимум строк на раздел          |
| `counts`, `leafCounts`                    | Полные счётчики                               |
| `reviewStatuses`                          | Фактически используемые статусы проверки      |
| `progress`, `ready`, `review`, `blockers` | Разделы вида `{ total, items }`               |

Компактная задача содержит `id`, `title`, `status`, `group`, `assignee`, `parentId`,
`revision`, `blockedByCount`. Разделы дополняют её счётчиками детей или влияния.
Описания и история читаются отдельно.

`meta.truncated` означает, что показаны не все строки; `meta.limitedByBytes` —
дополнительное сокращение по байтовому бюджету. Курсора у обзора нет: увеличьте
лимит/бюджет либо откройте нужную область и детали через `list`, `get`, `links`, `tree`.
