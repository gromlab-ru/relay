# Формат задачи

[Документация](../README.md) → Справочники → Формат хранения

**Файл `.relay/tasks/<task-id>.json` содержит всю задачу.** Общая конфигурация
проекта хранится отдельно в `.relay/config.json`.

Описание, саммари и тексты записей представлены массивами строк. В JSON видны
абзацы и блоки кода; CLI соединяет их настоящими переносами строк.

Фрагмент документа:

````json
{
  "version": 2,
  "id": 1,
  "title": "Добавить регистрацию",
  "description": [
    "## Требования",
    "",
    "- Добавить API.",
    "- Добавить форму.",
    "",
    "```ts",
    "  await register(user);",
    "```"
  ],
  "summary": ["Контракт API готов.", "", "Осталось подключить форму."],
  "comments": {
    "cmt_00000000000000000000000000000002": {
      "version": 1,
      "id": "cmt_00000000000000000000000000000002",
      "taskId": 1,
      "actor": "frontend-agent",
      "createdAt": "2026-09-12T12:00:00.000Z",
      "body": ["## Вопрос", "", "Какой формат ошибки возвращает API?"]
    }
  },
  "logs": {
    "log_00000000000000000000000000000003": {
      "version": 1,
      "id": "log_00000000000000000000000000000003",
      "taskId": 1,
      "actor": "backend-agent",
      "createdAt": "2026-09-12T12:05:00.000Z",
      "kind": "decision",
      "title": "Контракт ошибок",
      "summary": ["Единый формат ошибок для всех endpoint."],
      "sessionId": null,
      "body": [
        "## Решение",
        "",
        "Используем {code, message}.",
        "",
        "Контракт зафиксирован в openapi.yaml."
      ]
    }
  }
}
````

Полная карточка также имеет обязательные `status`, `group`, `tags`, `parentId`,
`dependsOn`, `assignee`, `createdAt`, `updatedAt`, `createdBy`, `updatedBy`,
`revision`. Необязательное значение группы, родителя или исполнителя — `null`.
Отсутствующий контекст представлен `{}`, пустой многострочный текст — `[]`.

`id` — положительное безопасное целое число JavaScript, от 1 до
`Number.MAX_SAFE_INTEGER`. Новый ID равен `max(id) + 1` и выделяется под общей
блокировкой. Пропуски не заполняются. Имя файла совпадает с ID: `.relay/tasks/1.json`.
`parentId` содержит число или `null`, `dependsOn` — массив чисел.

Необязательный `rank` хранит порядок в колонке. Это рациональное значение
в строковой форме; клиенту оно непрозрачно. Старые карточки без rank упорядочиваются
по ID. Изменение порядка сохраняется той же атомарной операцией, что и статус.

`number` отсутствует. Документы v1 с UUID доступны только команде `migrate`,
которая создаёт v2, сохраняет исходники и таблицу UUID → ID. Все вложенные
`taskId` при этом становятся числами. `id` самих комментариев и отчётов остаётся
строкой `cmt_…` / `log_…`; версия схемы этих вложенных записей остаётся `1`.

Названия и метаданные однострочны. Комментарии и отчёты добавляются новыми
записями; ключи совпадают с собственными ID. При `requestId` ключ детерминирован
его SHA-256 (первые 32 hex-символа с префиксом типа записи); иначе используется
случайный ID. Каждый `taskId` совпадает с ID содержащей задачи.

Пустые строки, отступы и завершающий перенос сохраняются. CRLF/CR нормализуются
в LF. Добавление записи изменяет `revision` и время изменения всей задачи.
Формат проверяется при чтении и записи; `validate` проверяет также связи.

Повтор записи с прежним `requestId`, автором и содержимым сохраняет исходную ревизию.
