## Полный конфиг

`init` создаёт `tasks.config.json`. Настройки редактируются в этом файле;
`config get` показывает действующую конфигурацию и пути.
Пример начального процесса с постоянным URL общей базы для агентов:

```json
{
  "version": 1,
  "storageDir": ".tasks",
  "defaultStatus": "todo",
  "readyStatuses": ["todo"],
  "statuses": {
    "todo": { "terminal": false, "satisfiesDependencies": false, "color": "cyan" },
    "in_progress": { "terminal": false, "satisfiesDependencies": false, "color": "yellow" },
    "review": { "terminal": false, "satisfiesDependencies": false, "color": "magenta" },
    "done": { "terminal": true, "satisfiesDependencies": true, "color": "green" },
    "cancelled": { "terminal": true, "satisfiesDependencies": false, "color": "gray" }
  },
  "server": { "port": 3000, "url": "http://127.0.0.1:3000" },
  "output": { "format": "text", "defaultLimit": 20, "maxBytes": 16384 }
}
```

`init` создаёт `server.port`, но не задаёт `server.url`: до настройки URL CLI работает
напрямую. Пример выше включает HTTP для рабочих команд. `server` всегда запускает
локальный процесс. Оркестратор, сервер и субагенты рассчитаны на один хост.
Оркестратор задаёт URL в конфиге, запускает сервер и обеспечивает конфиг в рабочих
копиях. Субагент вызывает обычные команды; установка переменных подключения ему не требуется.

## Поля

| Поле                                   | Правило / значение по умолчанию                                              |
| -------------------------------------- | ---------------------------------------------------------------------------- |
| `version`                              | Обязательно `1`                                                              |
| `storageDir`                           | Обязательный путь; `init` задаёт `.tasks`; разрешается относительно конфига  |
| `defaultStatus`                        | Обязательный существующий неконечный статус; при `init` — `todo`             |
| `readyStatuses`                        | Непустой массив существующих неконечных статусов; при `init` — `["todo"]`    |
| `statuses`                             | Обязательный словарь статусов; порядок ключей определяет колонки             |
| `statuses.<имя>.terminal`              | Конечный статус, по умолчанию `false`                                        |
| `statuses.<имя>.satisfiesDependencies` | Успешное завершение, по умолчанию `false`; `true` только у конечного статуса |
| `statuses.<имя>.color`                 | Необязательный цвет; при отсутствии используется стандартное оформление      |
| `server.port`                          | Целое `0–65535`, по умолчанию `3000`                                         |
| `server.url`                           | Необязательный HTTP(S) origin для CLI                                        |
| `output.format`                        | `text` или `json`, по умолчанию `text`                                       |
| `output.defaultLimit`                  | `1–100`, по умолчанию `20`; страницы групп, комментариев и отчётов           |
| `output.maxBytes`                      | `1024–16777216`, по умолчанию `16384`; байты UTF-8 ответа CLI                |

Секции `server` и `output` необязательны: их отсутствие включает значения по умолчанию.
Схема строгая — неизвестные поля считаются ошибкой.
Имя статуса содержит до 64 букв, цифр, `_` и `-`, начинается с буквы или цифры.
Цвета: `black`, `red`, `green`, `yellow`, `blue`, `magenta`, `cyan`, `white`, `gray`, `none`.

Название статуса не определяет успех: собственный `accepted` может удовлетворять
зависимости, а отменённая задача с `terminal: true` — оставаться блокером.
[Семантика процесса](../concepts/TASKS.md#статусы).

## Выбор конфига

Приоритет: **`--config` → `TASKS_CONFIG` → поиск вверх от текущего каталога**.
Поиск останавливается на ближайшем `tasks.config.json`.
Относительный `--config` разрешается от рабочего каталога вызова.

```bash
npx @gromlab/tasks-cli --local --config /work/orchestrator/tasks.config.json config get
```

В HTTP-режиме `config get` показывает **конфигурацию серверного проекта**, включая
`meta.configPath` и `meta.storagePath`. Файлы из `--file` и `--description-file`
читаются на стороне вызывающего агента.

## Выбор транспорта

```text
--local → --server-url → TASKS_SERVER_URL → server.url → прямой Core
```

- `--local` игнорирует любые HTTP-настройки.
- При явном URL из флага или окружения локальный конфиг не требуется.
- Если URL не задан, CLI работает с локальными файлами.
- Запущенный сервер сам по себе не переключает CLI на HTTP.
- При ошибке HTTP возвращается ошибка; прямой доступ выбирается явно.

Рабочие команды поддерживают оба режима. `init` создаёт локальный проект и при
явном HTTP требует `--local`. `migrate` при настроенном HTTP требует `--local`.
Команда `server` запускает локальную базу выбранного конфига независимо от URL.

## Порт и URL

Порт запуска: **`--port` → `TASKS_PORT` → `server.port` → `3000`**.
`0` поручает ОС выбрать свободный порт; адрес выводится после запуска.
Изменение порта применяется при следующем запуске сервера.

`server.url` определяет адрес подключения CLI, а `server.port` — порт запуска.
При смене порта обновите URL у агентов. При динамическом порте передайте им адрес
из ответа сервера. URL имеет вид `http://127.0.0.1:3000`, без `/api/v1`, credentials,
query и hash. Сервер продукта слушает loopback `127.0.0.1`.

```bash
npx @gromlab/tasks-cli server --port 3001 --actor human
npx @gromlab/tasks-cli --server-url http://127.0.0.1:3001 list
```

Первую команду запускают в отдельном терминале. `human` здесь подписывает дополнения
из UI; субагенты передают собственных авторов в CLI.

## Переменные окружения

| Переменная                                   | Назначение                                                            |
| -------------------------------------------- | --------------------------------------------------------------------- |
| `TASKS_CONFIG`                               | Путь к конфигу                                                        |
| `TASKS_SERVER_URL`                           | Адрес HTTP-сервера для CLI                                            |
| `TASKS_ACTOR`                                | Автор записей; `--actor` имеет приоритет                              |
| `TASKS_PORT`                                 | Порт сервера; `--port` имеет приоритет                                |
| `NO_COLOR`, `FORCE_COLOR`, `TERM`, `COLUMNS` | Оформление [терминала](TERMINAL.md)                                   |
| `TASKS_API_URL`, `TASKS_WEB_PORT`            | Адрес API-прокси и порт Vite только в [разработке](../DEVELOPMENT.md) |

Bash:

Пример дополнительного переопределения для диагностики или специальной интеграции.
В обычном процессе используется `server.url` из конфига:

```bash
export TASKS_SERVER_URL=http://127.0.0.1:3000
export TASKS_ACTOR=backend-agent
npx @gromlab/tasks-cli list --ready
```

PowerShell:

```powershell
$env:TASKS_SERVER_URL = "http://127.0.0.1:3000"
$env:TASKS_ACTOR = "backend-agent"
npx @gromlab/tasks-cli list --ready
```
