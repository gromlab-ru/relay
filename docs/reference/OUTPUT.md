## Форматы и конверты

`--format text` выводит таблицы, карточки и Markdown. `--format json` возвращает
структурированный ответ без ANSI. Если флаг не задан, используется `output.format`
из конфига; начальное значение — `text`. Справка и версия всегда текстовые.

Ответ изменения полей задачи:

```json
{ "ok": true, "data": { "id": 1, "revision": 2 } }
```

Ответ страницы:

```json
{
  "ok": true,
  "data": { "items": [] },
  "meta": { "hasMore": false, "nextCursor": null }
}
```

Форма `data` зависит от команды; в `meta` могут быть дополнительные счётчики
и признаки ограничения. Значение `meta` необязательно у непостраничных ответов.

При именованном обращении CLI добавляет `meta.project`. В режиме реестра курсоры
также связаны с именем проекта и хранилищем; продолжайте страницу в том же проекте.
У MCP собственный конверт `structuredContent`/`content` и общий байтовый бюджет;
см. [ответы MCP](MCP.md#ответы-и-ошибки).

Ошибка сопровождается ненулевым кодом завершения:

```json
{
  "ok": false,
  "error": {
    "code": "REVISION_CONFLICT",
    "message": "Карточка изменилась после чтения",
    "details": { "expected": 3, "actual": 4 }
  }
}
```

`details` необязательно. Слишком большие детали заменяются `details.omitted: true`.
Для выбора действия используйте `error.code`, а не текст сообщения.
[Коды завершения и ошибок](ERRORS.md).

## Выбор полей

```bash
npx @gromlab/tasks-cli get 1 --fields id,status,summary,revision --format json
npx @gromlab/tasks-cli description 1 --format json
npx @gromlab/tasks-cli get 1 --full --max-bytes 262144
```

`get` без `--full` исключает словари комментариев и отчётов, оставляя их счётчики.
`--fields` явно выбирает сохранённые и вычисляемые поля, включая `comments` и `logs`.
Неизвестное поле даёт `UNKNOWN_FIELD`.

В JSON-ответах задач Markdown представлен массивом строк, в продуктовых DTO — строкой
с переводами строк. Дисковое хранение Markdown продукта v2 использует массивы строк.
В текстовом режиме содержание рендерится как Markdown, пустые строки и отступы сохраняются.
См. [терминал](TERMINAL.md), [продукт](PRODUCT.md) и
[обязательный стандарт интерфейсов](../development/INTERFACE-STANDARD.md).

## Страницы

| Команды                                                | Без `--limit`                                      | Значение `--all`                                                                |
| ------------------------------------------------------ | -------------------------------------------------- | ------------------------------------------------------------------------------- |
| `list`                                                 | По числу задач лимита нет; действует `--max-bytes` | Включить конечные статусы; совместим с `--limit` и `--cursor`                   |
| `group list`, `comment list`, `log list`, `log search` | `output.defaultLimit`, обычно 20                   | Выдать все записи одним ответом в бюджете; несовместим с `--limit` и `--cursor` |
| `overview`                                             | До пяти строк каждого раздела                      | Флага нет; курсора нет                                                          |

Явный `--limit` принимает `1–100`. При продолжении повторяются команда и фильтры,
включая `--all` у списка задач. Лимит страницы и байтовый бюджет можно изменить.
Берите непрозрачный курсор из `meta.nextCursor`, пока `meta.hasMore` равно `true`.

```bash
npx @gromlab/tasks-cli list --all --limit 2 --format json
npx @gromlab/tasks-cli list --all --limit 2 --cursor "<nextCursor>" --format json
```

Подставьте настоящий курсор из первого ответа. Повреждённый курсор или изменение
фильтров дают `INVALID_CURSOR`. Порядок по умолчанию: задачи — ID, группы — имя,
записи — от новых к старым. `list --sort board` использует сохранённый порядок доски.

CLI читает актуальные данные. REST-доска имеет собственную пагинацию снимка,
с `BOARD_CHANGED` при изменении версии между страницами; см. [API](API.md#списки-и-пагинация).

## Байтовый бюджет

`--max-bytes` принимает `1024–16777216` байт. По умолчанию используется
`output.maxBytes = 16384`. Измеряется реальный UTF-8 ответ выбранного формата,
включая оформление и курсор. Для слишком большого неделимого результата
возвращается `RESPONSE_TOO_LARGE`.

Обычная страница сокращается с сохранением продолжения. Полный ответ с `--all`
у записей должен помещаться целиком. Обзор сокращает строки разделов, сохраняя
полные счётчики; `meta.limitedByBytes` отличает это от ограничения числом строк.
Подробности: [обзор](OVERVIEW.md).

## Ограничения хранения

| Содержимое                           | Лимит UTF-8 |
| ------------------------------------ | ----------- |
| Название задачи или заголовок отчёта | 1024 байта  |
| Описание задачи или тело отчёта      | 256 КиБ     |
| Саммари задачи или отчёта            | 4096 байт   |
| Комментарий                          | 64 КиБ      |
| Полный JSON задачи                   | 16 МиБ      |

Увеличение `--max-bytes` меняет выдачу, а не эти лимиты.
Сервер дополнительно ограничивает HTTP-тело запроса 1 МиБ.
