# Формат задачи

**Файл `.tasks/tasks/<task-id>.json` содержит всю задачу.** Общая конфигурация
проекта хранится отдельно в `tasks.config.json`.

Описание, саммари и тексты записей представлены массивами строк. В JSON видны
абзацы и блоки кода; CLI соединяет их настоящими переносами строк.

Фрагмент документа:

````json
{
  "version": 1,
  "id": "tsk_00000000000000000000000000000001",
  "title": "Добавить регистрацию",
  "description": [
    "## Требования",
    "",
    "- Добавить API.",
    "- Добавить форму.",
    "",
    "```ts",
    "  await register(user);",
    "```"
  ],
  "summary": ["Контракт API готов.", "", "Осталось подключить форму."],
  "comments": {
    "cmt_00000000000000000000000000000002": {
      "version": 1,
      "id": "cmt_00000000000000000000000000000002",
      "taskId": "tsk_00000000000000000000000000000001",
      "actor": "frontend-agent",
      "createdAt": "2026-09-12T12:00:00.000Z",
      "body": ["## Вопрос", "", "Какой формат ошибки возвращает API?"]
    }
  },
  "logs": {
    "log_00000000000000000000000000000003": {
      "version": 1,
      "id": "log_00000000000000000000000000000003",
      "taskId": "tsk_00000000000000000000000000000001",
      "actor": "backend-agent",
      "createdAt": "2026-09-12T12:05:00.000Z",
      "kind": "decision",
      "title": "Контракт ошибок",
      "summary": ["Единый формат ошибок для всех endpoint."],
      "sessionId": null,
      "body": [
        "## Решение",
        "",
        "Используем {code, message}.",
        "",
        "Контракт зафиксирован в openapi.yaml."
      ]
    }
  }
}
````

Полная карточка также имеет обязательные `status`, `group`, `tags`, `parentId`,
`dependsOn`, `assignee`, `createdAt`, `updatedAt`, `createdBy`, `updatedBy`,
`revision`. Необязательное значение группы, родителя или исполнителя — `null`.
Отсутствующий контекст представлен `{}`, пустой многострочный текст — `[]`.

Названия и метаданные однострочны. ID постоянны и генерируются без общего
счётчика. Комментарии и отчёты добавляются новыми записями; их ключи совпадают
с собственными ID. Каждый `taskId` совпадает с ID содержащей задачи.

Пустые строки, отступы и завершающий перенос сохраняются. CRLF/CR нормализуются
в LF. Добавление записи изменяет `revision` и время изменения всей задачи.
Формат проверяется при чтении и записи; `validate` проверяет также связи.
