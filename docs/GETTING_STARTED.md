# Первый проект

[Документация](README.md) → Первый проект

Оркестратор создаёт и назначает задачи, субагенты читают контекст и пишут отчёты,
человек наблюдает через UI. Оркестратор, сервер и агенты работают на одном хосте.

Ниже показан CLI-процесс одной базы. Для общего MCP после `init` запустите
`npx @gromlab/tasks-mcp` и подключите агентов к `http://127.0.0.1:3010/mcp`.
Без `server.url` MCP сам запускает REST API, задачи читаются как `task_get({ id: 1 })`.
Для нескольких проектов используется [реестр](reference/CONFIGURATION.md#реестр-проектов),
CLI-префикс проекта и поле `project` MCP-инструментов. [Справочник MCP](reference/MCP.md).

## Требования

Нужны Node.js 22+ и npm/npx. Пакет включает CLI, сервер и готовую веб-доску.
Проверка версии и справки:

```bash
npx @gromlab/tasks-cli --version
npx @gromlab/tasks-cli --help
```

Для воспроизводимой сессии можно указать версию: `npx @gromlab/tasks-cli@0.3.0`.
Скилл для агента устанавливается отдельно: [инструкция](development/SKILLS.md).

## База и конфиг

В новом проекте оркестратор выполняет:

```bash
npx @gromlab/tasks-cli init
```

Создаются `tasks.config.json` и `.tasks/`. Для общей серверной базы оркестратор
добавляет URL в секцию существующего конфига:

```json
{ "server": { "port": 3000, "url": "http://127.0.0.1:3000" } }
```

Остальные поля сохраняются. **CLI сам выбирает API по `server.url`. Без URL
операции локальные.** `server.port` задаёт порт запуска, а не выбор транспорта.
Настройку подключения выполняет оркестратор, субагенты используют готовый конфиг.

Начальный процесс — `todo → in_progress → review → done`, есть также `cancelled`.
Статусы и их семантика настраиваются в [конфигурации](reference/CONFIGURATION.md).

## Сервер

При наличии URL оркестратор обеспечивает запуск сервера:

```bash
npx @gromlab/tasks-cli server --actor human --open
```

Доска — http://127.0.0.1:3000, Swagger — http://127.0.0.1:3000/api/docs.
`human` подписывает возможные дополнения человека из UI. Сервер работает до `Ctrl+C`;
следующие команды выполняются в другом терминале того же проекта.
При изменении порта оркестратор обновляет соответствующий URL в конфиге клиентов.

## Назначение и выполнение

Оркестратор ставит задачу и назначает исполнителя. В новой базе ID будет `1`:

```bash
npx @gromlab/tasks-cli create "Подготовить API проекта" --group backend --actor orchestrator
npx @gromlab/tasks-cli update 1 --assignee backend-agent --status in_progress --actor orchestrator
```

Субагент получает этот ID и имя автора. В его каталоге уже есть конфиг проекта,
поэтому переменные URL и выбор local/HTTP не нужны:

```bash
npx @gromlab/tasks-cli get 1 --format json
npx @gromlab/tasks-cli log add 1 --actor backend-agent --text "Контракт описан, реализую обработчик"
npx @gromlab/tasks-cli update 1 --summary "Обработчик готов, выполняю проверки" --actor backend-agent
```

Субагент не вызывает `claim` и не выбирает другую задачу самостоятельно.
Для существующей базы используйте ID из поручения, а не `1` из примера.

## Приёмка

После отчёта субагента оркестратор переводит задачу на проверку и проверяет критерии:

```bash
npx @gromlab/tasks-cli status 1 review --actor orchestrator
npx @gromlab/tasks-cli get 1 --full
```

После фактической приёмки:

```bash
npx @gromlab/tasks-cli status 1 done --actor orchestrator
npx @gromlab/tasks-cli list --all
npx @gromlab/tasks-cli validate
```

Обычный `list` показывает незавершённую работу, `--all` включает конечные статусы.
Все изменения идут через API по конфигу. При недоступности сервера возвращается ошибка,
а восстановление организует оркестратор.
