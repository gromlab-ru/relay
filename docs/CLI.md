# Команды CLI

В примерах `tasks-cli` — исполняемая команда установленного `@gromlab/tasks-cli`.
Её можно заменить на `npx @gromlab/tasks-cli` или `node dist/cli/main.js`.
`<task-id>`, `<comment-id>` и `<log-id>` заменяются ID из ответов CLI.

## Общие параметры

| Параметр                      | Назначение                                                |
| ----------------------------- | --------------------------------------------------------- |
| `--config <path>`             | Явный конфиг вместо поиска ближайшего `tasks.config.json` |
| `--actor <id>`                | Автор записи; имеет приоритет над `TASKS_ACTOR`           |
| `--format text\|json`         | Настоящий многострочный текст или структурированный JSON  |
| `--color auto\|always\|never` | Автоматическая, принудительная или отключённая подсветка  |
| `--max-bytes <N>`             | Объём UTF-8 ответа, от 1024 байт до 16 МиБ                |
| `--help`                      | Справка по команде                                        |
| `--version`                   | Версия из `package.json`                                  |

Начальный конфиг задаёт текстовый режим, лимит 16 КиБ и страницу из 20 элементов.
Для машинной обработки передайте `--format json`. Справка и версия всегда текстовые.
Для чтения автор не нужен, для записи обязателен.

Текстовый режим оформляет статусы, таблицы, карточки, связи и Markdown.
Цвет автоматически включается в TTY; `NO_COLOR` отключает автоматическую подсветку.
Явные `--color always` и `--color never` имеют приоритет над окружением.
`--format json` всегда отключает ANSI-коды. Подробности: [терминал](TERMINAL.md).

## Настройка проекта

```bash
tasks-cli init --storage .tasks
tasks-cli config get
tasks-cli group list
```

`storageDir` разрешается относительно конфига. Это позволяет нескольким worktree
обращаться к одной базе через общий `--config`.
Группы показывают `total`, успешные `completed` и все конечные `terminal` задачи.

## Создание и изменение

```bash
export TASKS_ACTOR=orchestrator

tasks-cli create --title "API пользователей" --group backend --tags api,registration --stdin <<'MD'
## Требования

- Добавить POST /users.
- Возвращать ошибки в формате {code, message}.
MD

tasks-cli create --title "Форма регистрации" --group frontend --parent <parent-id> --depends-on <backend-id>
tasks-cli update <task-id> --summary 'Контракт готов' --if-revision 3
```

Поля `create`/`update`: `--title`, `--description`, `--description-file`, `--stdin`,
`--summary`, `--summary-file`, `--status`, `--group`, `--parent`, `--tags`,
`--depends-on`, `--assignee`.

`--stdin` читает описание. `--description-file -` и `--summary-file -` также
читают stdin. Один поток нельзя использовать для нескольких полей одновременно.
`--file` и аналогичные параметры — необязательные источники ввода;
работа через CLI не требует создания внешних файлов с отчётами.

`--clear-group` и `--clear-parent` снимают соответствующие значения.
Пустые `--description ""`, `--summary ""`, `--tags ""`, `--depends-on ""` очищают
поле. Отсутствующее поле сохраняется. Теги и зависимости передаются через запятую;
`--depends-on` заменяет весь набор, а `deps add/remove` меняет одну связь.

Задачи получают постоянные номера от 1. Везде вместо `<task-id>` можно передать
номер: `get 3`, `status 3 done`, `--parent 1`, `--depends-on 2,3`.
Также принимаются полный UUID и его однозначный префикс длиной от восьми символов,
включая `tsk_`. В JSON поле `number` содержит номер, а `id` и сохранённые ссылки — UUID.

Для старого хранилища назначьте номера явно:

```bash
tasks-cli number --actor orchestrator
```

Команда назначает номера в порядке создания, увеличивает revision изменённых
документов и не меняет уже уникальные номера. Повторный запуск без изменений
ничего не записывает. После Git-слияния команда также исправляет совпавшие номера:
ранняя задача сохраняет номер, поздняя получает новый. До исправления неоднозначная
числовая ссылка возвращает ошибку; полный UUID остаётся однозначным.

## Чтение задачи и контекста

```bash
tasks-cli list --ready --group frontend
tasks-cli list --status review --assignee frontend-agent
tasks-cli list --parent <parent-id> --tag registration
tasks-cli list --search "формат ошибок"
tasks-cli get <task-id>
tasks-cli get <task-id> --full
tasks-cli get <task-id> --fields id,status,summary --format json
tasks-cli description <task-id>
tasks-cli summary <task-id>
tasks-cli links <task-id>
tasks-cli tree <parent-id> --depth 2
```

`get` показывает карточку и число записей, `--full` добавляет все комментарии
и отчёты. Хранение общего контекста в одном файле не увеличивает автоматически
объём каждой выдачи агенту.

`description` и `summary` возвращают непосредственно многострочный Markdown
в текстовом режиме. Абзацы, пустые строки и отступы кодовых блоков сохраняются.
В JSON-режиме многострочные поля представлены массивами строк.

`links` показывает родителя, детей, зависимости, блокируемые задачи и актуальные
блокеры с номерами, названиями и цветными статусами. `tree` в текстовом режиме
рисует иерархию, в JSON возвращает список с `depth`; корень имеет глубину 0.
При ограничении глубины устанавливается `meta.truncated`.

## Назначение и зависимости

```bash
tasks-cli assign <task-id> backend-agent
tasks-cli claim <task-id> --actor backend-agent
tasks-cli status <task-id> in_progress --actor backend-agent
tasks-cli status <task-id> done --actor backend-agent
tasks-cli release <task-id> --actor backend-agent
tasks-cli release <task-id> --force --actor orchestrator
tasks-cli deps add <task-id> <dependency-id>
tasks-cli deps remove <task-id> <dependency-id>
```

`claim` атомарно занимает свободную доступную задачу. Доступность определяется
`readyStatuses`, отсутствием исполнителя и выполненными зависимостями.
Статус меняется отдельно. `assign` — явное назначение оркестратором.

Удовлетворённость зависимости определяется `satisfiesDependencies`, а не
названием статуса. Отмена не считается успешным выполнением. Переоткрытие
зависимости обновляет блокеры, но не меняет автоматически статус других задач.

Команды изменения полей карточки поддерживают `--if-revision`.
Добавление комментария или отчёта также увеличивает `revision`: это изменение
того же самодостаточного документа.

## Комментарии

```bash
tasks-cli comment add <task-id> --stdin <<'MD'
## Проверка

Основной сценарий работает.

Осталось проверить повторный запрос.
MD

tasks-cli comment list <task-id> --author backend-agent --limit 10
tasks-cli comment get <task-id> <comment-id>
```

Источник выбирается один: `--text`, `--stdin` или `--file`.
Список показывает автора, время и короткий многострочный фрагмент.
`comment get` выводит полную запись. Комментарии добавляются новыми записями;
исправление можно описать следующим комментарием.

## Отчёты агентов

````bash
tasks-cli log add <task-id> --kind summary --title "Результат работы" --stdin <<'MD'
## Сделано

- Реализован API.
- Добавлены интеграционные проверки.

## Проверка

```text
npm test
```

Все тесты прошли.
MD

tasks-cli log list <task-id> --kind summary --limit 5
tasks-cli log get <task-id> <log-id>
tasks-cli log search <task-id> --query "интеграционные" --kind summary
````

Типы: `progress`, `decision`, `execution`, `error`, `summary`.
Дополнительно доступны `--summary` с многострочным кратким результатом
и `--session-id`. Заголовок `--title` остаётся однострочным.

`log get` возвращает отчёт целиком. `log list` показывает краткие саммари;
`log search` возвращает подходящие отчёты, номер первой подходящей строки,
число подходящих строк и фрагмент. Поиск буквальный, с учётом регистра.

Фильтры списка и поиска: `--author`, `--kind`, `--session-id`, `--since`, `--until`.
Дата задаётся как `YYYY-MM-DD` или ISO 8601 с часовым поясом.

## Ограничения и пагинация

- Название задачи и заголовок отчёта: до 1024 байт UTF-8.
- Описание и тело отчёта: до 256 КиБ.
- Саммари: до 4096 байт.
- Комментарий: до 64 КиБ.
- Один JSON задачи: до 16 МиБ. Превышение проверяется до сохранения.

Списки задач, групп, комментариев и отчётов, а также поиск поддерживают
`--limit` от 1 до 100 и `--cursor`. В JSON ответе используются `data.items`,
`meta.hasMore`, `meta.nextCursor`, `meta.truncated`. В текстовом режиме курсор
показывается строкой `Продолжение: --cursor ...`.

Курсор привязан к команде и фильтрам; при продолжении можно менять размер страницы
и байтовый бюджет. Задачи идут от старых к новым, комментарии и отчёты — наоборот,
группы — по имени. Это постраничное чтение актуальных данных.

CLI измеряет реальный объём UTF-8 ответа, включая ANSI-коды. Списки уменьшают страницу без пропуска
продолжения. Для слишком большой неделимой карточки или записи возвращается
`RESPONSE_TOO_LARGE`: увеличьте `--max-bytes` или выберите нужные поля.

## Ошибки и проверка данных

```bash
tasks-cli validate
```

Проверка читает каждый самодостаточный документ, включая комментарии и отчёты,
проверяет схемы, принадлежность записей, статусы, ссылки и циклы.

| Код завершения | Значение                                            |
| -------------- | --------------------------------------------------- |
| 0              | Успех                                               |
| 2              | Неверные параметры или конфигурация                 |
| 3              | Объект или файл не найден                           |
| 4              | Конфликт revision, назначения, графа или блокировки |
| 5              | Повреждение данных или ошибка ввода-вывода          |

В JSON-режиме ответ имеет форму `{ "ok": true, "data": ..., "meta": ... }`
либо `{ "ok": false, "error": { "code", "message", "details" } }`.
Слишком большие детали ошибки заменяются `details.omitted: true`.
