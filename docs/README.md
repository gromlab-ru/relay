# Документация Relay

[О продукте](../README.md) · [Первый проект](GETTING_STARTED.md) ·
[Справочник CLI](reference/CLI.md) · [Диагностика](TROUBLESHOOTING.md)

Relay организует задачи одного проекта (local) или нескольких проектов (workspace).
Оркестратор ставит задачи и принимает результаты; человек наблюдает через UI
и при необходимости добавляет уточнения. Основа — локальная JSON-база;
CLI, MCP, веб-доска и API используют одни бизнес-правила.
Выберите вопрос или пройдите путь от первого проекта к своему рабочему процессу.

## С чего начать

1. [Создать первый проект](GETTING_STARTED.md) — требования, запуск и первая задача.
2. [Разобраться в модели задач](concepts/TASKS.md) — статусы, связи, исполнитель и контекст.
3. [Пройти жизненный цикл](guides/WORKFLOW.md) — постановка, выполнение, проверка и передача.
4. [Подключить агентов](guides/ORCHESTRATION.md) или [открыть веб-доску](guides/WEB.md).

Для агента есть [готовый скилл Relay](../skills/relay/SKILL.md):
`npx skills add gromlab-ru/relay --skill relay`.
[Установка и требования](development/SKILLS.md#скилл-продукта).

## Версии и примеры

Документация соответствует исходникам выбранной ветки или тега. История выпусков —
в [CHANGELOG](../apps/cli/CHANGELOG.md). Для HTTP-режима нужен сервер с поддержкой
`relay-projects-v1`; при обновлении перезапускается и сервер.

Пользовательские примеры используют `npx @gromlab/relay-cli`. В синтаксисе справочника
`<id>` означает ID из ответа CLI, а `[параметр]` — необязательную часть команды.
Многострочные команды и `export` написаны для Bash; пример окружения PowerShell есть
в [конфигурации](reference/CONFIGURATION.md#переменные-окружения).

При изменении поведения обновляйте соответствующий справочник и руководство;
`pnpm run docs:check` проверяет локальные ссылки и якоря.
