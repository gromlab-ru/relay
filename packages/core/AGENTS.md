# Core: обязательные правила

Прочитай `../../docs/development/INTERFACE-STANDARD.md` перед проектированием модели.

- Зафиксируй владельца, инварианты, границы агрегата и семантику каждого текстового поля.
- Заголовок — строка без переносов; краткое описание — многострочный обычный текст;
  полное описание, требования и инструкции — Markdown.
- В JSON-хранилище Markdown — массив строк. Внешняя строка преобразуется кодеком хранения.
  Сохраняй пустые строки, значимые пробелы и точное содержание; не меняй текст при чтении.
- Отделяй дисковую схему от публичного DTO. Изменение хранения требует версии и миграции.
- ID, ссылки, ревизии, история, идемпотентность и готовность сохраняются при технической миграции.
- Все изменения проходят общую блокировку; одна запись публикуется атомарно.
  Прерванная миграция должна быть возобновляемой и не допускать тихого пропуска данных.
- Не добавляй новые служебные каталоги без назначения и правил восстановления.
- Проверяй инварианты, конкуренцию, повтор, повреждённые данные и совместимость чтения;
  форматирование требований само по себе не доказывает их полноту.
