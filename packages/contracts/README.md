# Общий контракт REST и SSE

Импорт: `import type { BoardResponse } from "#contracts"`.
Типы и переносимые константы находятся в `src/index.ts`; здесь нет зависимостей
от Core, NestJS, Node.js или React.

Источник требований: [PLAN.md](../../PLAN.md), описание протокола —
[docs/API.md](../../docs/API.md), интерфейс — [UI_SPEC.md](../../UI_SPEC.md).

Важные соглашения:

- Health/context работают в каркасе; остальные DTO задают целевой контракт бэкенд-агента.
- У всех списков курсор расположен в `meta.nextCursor`, а элементы — в `data.items`.
- `data.version` доски относится к снимку, `task.revision` — к документу задачи.
- `rank` — непрозрачная строка; порядок вычисляет Core.
- Markdown в полях задач — массив строк; `text` добавляемой записи — строка.
- Автор HTTP-изменений берётся из контекста сервера; исполнитель — поле задачи.
- Contracts не заменяет runtime-валидацию. На HTTP-границе используются схемы Zod.

При изменении контракта одновременно обновить типы, описание, HTTP-проверки и клиент.
