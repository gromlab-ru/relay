## Соединение и конкурентность

- Production-сервер: несколько минут простоя, одна подписка, heartbeat без ошибок.
- Через отдельный Vite-прокси: за 81 секунду получено пять heartbeat,
  соединение установлено один раз, ошибок и предупреждений нет.
- Короткий перезапуск API: тот же экземпляр EventSource восстановил подписку;
  наблюдение за DOM не зафиксировало предупреждения о разрыве.
- Длительное отключение: предупреждение появилось, введённое название сохранилось.
- Пока сервер был отключён, карточка изменена другим клиентом через Core.
  После запуска появились актуальные данные и новая группа, локальное название осталось.
- Сохранение старой ревизии открыло сравнение версий. Выбор своей версии и последующее
  сохранение прошли успешно.

### Отмена SSE в dev-режиме

- Дополнительно проверены именно `http://127.0.0.1:5173/api/v1/events` и прямой
  API на порту 3000. Оба вернули 200 и передавали heartbeat без обрыва
  в течение 35 секунд наблюдения; чтение завершено заданным лимитом времени.
- В браузере отдельно воспроизведён цикл подписка → освобождение → подписка.
  До исправления создавались **2** EventSource и первый немедленно закрывался.
- После исправления тот же цикл создаёт **1** EventSource без раннего закрытия.
- Разрыв между освобождением и повторной подпиской в 40 мс также сохраняет
  единственный поток: **0** закрытий и **0** ошибок.
- После окончательного освобождения закрытие произошло один раз: ресурс очищен.
- Отдельно остановлен backend за Vite-прокси. В ответах SSE зафиксирован 502:
  прежняя реализация оставалась отключённой даже после запуска backend.
- С исправлением зафиксированы повторные запросы после 502 и последующий 200.
  Индикатор вернулся в «Синхронизировано», предупреждение исчезло, 108 загруженных
  карточек остались на доске. Маркер `same-page-after-502` сохранился:
  восстановление произошло без перезагрузки страницы.
