# Работа в playground

- Общайся с пользователем и веди документацию на русском языке.
- Эта папка — рабочий корень демо-workspace. Прочитай `README.md` перед началом.
- Перед наполнением прочитай `../../docs/reference/PRODUCT-CONTENT.md`.
  Название — одна строка, summary — многострочный обычный текст; полные описания,
  требования и инструкции — структурированный Markdown. Фича объясняет цель, правила
  и критерии; сценарий — участника, предусловия, шаги, ошибки и проверяемый результат.
  После сохранения перечитай запись; `product lint` помогает найти слабую структуру.
- Проекты: `coffee-shop` и `p2p-rental`; их требования находятся в `product-spec.md`
  в корне каждого проекта. Кода продуктов пока нет.
- `node init.mjs` инициализирует пустые проекты и сохраняет существующие данные.
- Сейчас наполнение не задано. Создавай записи Relay только в рамках поручения пользователя;
  не генерируй примерные задачи и не отмечай требования выполненными без проверки.
- Для CLI используй `pnpm --silent run cli <project> <команда>` из этой папки.
  Для записи указывай автора. `pnpm --silent run cli projects list` проверяет подключение.
- Для двух проектов нужен Server с `relay.workspace.json`. Разработчик запускает его
  вместе с Web из корня Relay; подробности в README. Не считай однопроектный сервер
  кофейни общим сервером workspace.
- `pnpm run mcp` запускает HTTP MCP на `http://127.0.0.1:4710/mcp`.
  Подключение этого адреса к агенту выполняется настройками его MCP-клиента.
  Всегда передавай имя проекта в инструменты MCP.
- Историю, планы, требования и решения веди через публичные CLI/MCP-интерфейсы Relay,
  а не ручным редактированием внутренних JSON. Перед изменением читай актуальную запись.
- ТЗ аренды — копия внешнего документа: его относительные ссылки относятся к исходному
  репозиторию, а не к существующим файлам или выполненным работам playground.
- Проверки, меняющие данные, согласуй с текущей задачей; не очищай накопленную память
  и не перезапускай чужие процессы без поручения.
