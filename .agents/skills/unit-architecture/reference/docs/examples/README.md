# Примеры

Примеры показывают отдельные архитектурные решения. Это не обязательные шаблоны каталогов и не runnable demo.

[Профиль React SPA](./react-spa-project-profile.md) отличается от остальных примеров: он показывает целостный набор командных соглашений, заполняющий свободные решения архитектуры. Его фасеты, сегменты, группы и framework-правила не являются рекомендуемыми значениями по умолчанию.

В примерах используются группы `layouts`, `pages`, `screens`, `widgets` и сегменты `styles`, `types`, `ui`, `providers`, `hooks`, `libs`, `utils`, `stores`. Архитектура не определяет этот словарь и не устанавливает различия между `libs`, `utils`, `helpers` или другими именами: команда приложения самостоятельно проектирует внутреннюю структуру юнита.

Во всех примерах `index.ts` является маркером фасета и зарезервирован во всём frontend root. В SSR-примере, примере Next.js и профиле React SPA дополнительно объявлены специализированные маркеры. Поэтому каждый показанный `index.ts` однозначно объявляет содержащую его папку юнитом и не используется как локальный реэкспорт.

Папки и файлы примеров именуются в kebab-case. Минимальная форма UI-юнита выглядит так:

```text
unit-name/
├── index.ts
├── unit-name.tsx
├── styles/
│   └── unit-name.module.css
└── types/
    └── unit-name.type.ts
```
