# Физическая структура

Unit Architecture нормирует владельцев и публичные границы, но оставляет внутреннюю структуру юнита проекту.

Команда фиксирует выбранные соглашения структуры, словарь сегментов и группы композиций в [архитектурном профиле проекта](./project-profile.md). Профиль может явно оставить любую из этих частей свободной.

## Структурные сущности

```text
Layer
└── [Group*]
    └── Unit
        ├── Facet+
        ├── File*
        ├── Segment*
        └── Unit*
```

## Фасет

Фасет — объявленный файл или путь публичной точки входа юнита. Только юниты имеют фасеты.

Проект определяет в архитектурном профиле однозначное соглашение фасетов для всего frontend root. Маркерами могут быть явно задокументированные пути, например `index.ts`, `client.ts`, `browser.ts` или `server.ts`; базовая архитектура не выбирает их имена. Наличие любого объявленного маркера делает содержащую его папку юнитом.

Один маркер нельзя одновременно использовать как фасет и локальный файл реэкспортов. Если проект использует `index.ts` как маркер, внутренние `index.ts` запрещены: внутренняя папка остаётся без `index.ts` либо становится отдельным юнитом и проходит все проверки юнита.

Маркер должен открывать непустую часть публичного API. Пустой маркер всё равно объявляет папку юнитом, но делает этот юнит некорректным.

## Сегмент

Сегмент группирует внутреннюю реализацию по выбранному проектом направлению. Архитектура не устанавливает:

- обязательный набор сегментов;
- их имена;
- допустимые типы файлов;
- необходимость папок внутренних единиц;
- глубину локальной реализации.

Обе формы допустимы:

```text
query-client/
├── index.ts
├── create-query-client.ts
└── query-client.type.ts
```

```text
unit/
├── index.ts
├── unit-name.tsx
├── styles/
├── types/
├── ui/
├── providers/
├── hooks/
├── libs/
├── utils/
└── stores/
```

Вторая форма показывает словарь сегментов, используемый в примерах документации. Архитектура не определяет различия между `libs`, `utils`, `helpers` или любыми другими выбранными именами. Их смысл и содержимое устанавливает команда приложения.

Сегмент не имеет фасета и не импортируется как самостоятельный владелец.

## Форма UI-юнита в примерах

Для UI-проекций примеры используют минимальную базовую форму:

```text
unit-name/
├── index.ts
├── unit-name.tsx
├── styles/
│   └── unit-name.module.css
└── types/
    └── unit-name.type.ts
```

`index.ts` является фасетом. Папки и файлы в примерах именуются в kebab-case. Это соглашение набора примеров, а не требование Unit Architecture к приложениям.

## Группа

Группа содержит только юниты и другие группы. Она используется для навигации и может находиться в слое либо внутри выбранной проектом области юнита.

```text
compositions/
├── layouts/        # Группа
│   └── main-layout/
├── screens/        # Группа
│   └── catalog-screen/
└── widgets/        # Группа
    └── header/
```

Если папка содержит собственную реализацию, она не является группой. Если она содержит маркер фасета, она объявлена юнитом независимо от остального содержимого.

## Внутренняя папка

Свобода внутренней структуры не отменяет роль слоя. Папка `app/providers` может содержать техническую сборку готовых Providers, но не реализацию самих Providers и контекстов. Папка `app/ui` не является местом хранения продуктового UI: отображаемые проекции принадлежат `compositions`, а остальные возможности — соответствующим владельцам.

Папка без маркера фасета может колоцировать файлы вокруг component, hook, Provider, service или другого механизма. Она не становится юнитом и не участвует в графе зависимостей.

```text
header/
├── index.ts
└── utils/
    ├── get-navigation-label.ts
    └── get-navigation-label.test.ts
```

`utils` здесь является внутренним сегментом юнита Header, а не вложенным юнитом.

## Как различить папки

| Папка | Ответственность | Фасет | Реализация | Узел графа |
|---|---:|---:|---:|---:|
| Юнит | Да | Да | Да | Да |
| Некорректно выделенный юнит | Любая | Да, возможно пустой | Любая | Да |
| Сегмент | Нет | Нет | Да | Нет |
| Группа | Нет | Нет | Нет | Нет |
| Внутренняя папка | Нет отдельно от владельца | Нет | Да | Нет |

Маркер фасета всегда объявляет папку юнитом. Ответственность, непустой связный API и корректные зависимости определяют, является ли этот юнит архитектурно корректным. Ответственность без маркера фасета остаётся частью ближайшего объявленного владельца и не получает отдельной границы.
