# Публичный API и фасеты

У каждого юнита один логический публичный API. Фасеты физически разделяют этот API по средам выполнения или другим объявленным проектом ограничениям.

## Минимальная граница

Юнит имеет хотя бы один непустой фасет.

Физические маркеры фасетов определяет проект для всего frontend root. Unit Architecture не задаёт их имена: проект объявляет подходящие файлы или пути в своём профиле.

Маркеры, назначение, способы потребления и ограничения сред фиксируются в [архитектурном профиле проекта](./project-profile.md) до изменения публичной границы.

В SPA обычно используется один `index`:

```text
header/
├── index.ts
└── ...
```

```ts
export { Header } from './header'
export type { HeaderProps } from './types/header.type'
```

Наличие маркера фасета объявляет содержащую его папку юнитом. Маркер должен открывать реальный API; пустой маркер означает некорректный юнит, а не отсутствие архитектурной границы.

Зарезервированный маркер нельзя использовать для локальных реэкспортов. Если проект объявил `index.ts` маркером, любой `index.ts` внутри архитектурного дерева обозначает фасет юнита, а внутренние папки без самостоятельной ответственности такого файла не имеют.

## Разделённые среды

Если приложение имеет SSR или другие несовместимые среды выполнения, проект может объявить специализированные фасеты. В документации используются имена:

```text
index    → универсальная часть API
client   → клиентская framework-граница
browser  → browser-only код
server   → server-only код
```

Эти имена являются примерами, а не обязательным соглашением Unit Architecture. Проект явно документирует все используемые маркеры; наличие одного или нескольких маркеров объявляет содержащую их папку одним юнитом, даже если его API физически разделён на несколько фасетов.

## Универсальный index

При разделённых средах `index`, если существует, экспортирует только код, безопасный во всех поддерживаемых средах:

- `export type`;
- чистые утилиты;
- универсальные модели и контракты;
- исполняемый код с полностью совместимым транзитивным графом.

Он не импортирует и не реэкспортирует несовместимые специализированные фасеты прямо или транзитивно.

Если универсального API нет, `index` не создаётся:

```text
analytics/
├── browser.ts
└── ...
```

## Один экспорт — один фасет

Исполняемая возможность размещается в минимально подходящем фасете и не дублируется между средами. Тип может быть повторно указан только через безопасный type-only контракт, если инструменты проекта действительно исключают runtime-связь.

## Scope-aware публичность

Публичность фасета определяется областью юнита:

- фасет корневого юнита доступен разрешённым потребителям слоя;
- фасет вложенного юнита доступен непосредственному родителю;
- внешний код использует API родителя либо требует подъёма юнита;
- сегменты и внутренние папки фасетов не имеют.

## Минимальный API

Фасет открывает только возможности, необходимые реальным потребителям. Он не экспортирует внутренние stores, contexts, adapters или helpers только ради тестирования или предполагаемого переиспользования.

## Проверка среды

Совместимость фасета определяется всем достижимым исполняемым графом, а не только его собственным файлом. `tree shaking`, директива framework, условие `typeof window` или имя файла сами по себе не доказывают безопасность среды.
