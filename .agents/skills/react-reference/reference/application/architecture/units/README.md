# Роли юнитов React SPA

Этот раздел уточняет, как роли Unit Architecture применяются в React SPA. Общие свойства юнита, колокацию, фасеты и
направления зависимостей определяет skill `unit-architecture`. Если skill недоступен, используй его
[публичный репозиторий](https://github.com/gromlab-ru/unit-architecture) по правилам
[`архитектурного раздела`](../README.md). Физические маркеры и сегменты проекта закреплены в
[`архитектурном профиле`](../project-profile.md).

## Пять ролей

Проект использует пять ролей юнитов:

| Роль | Результат для потребителя | Документ |
| --- | --- | --- |
| `compositions` | Продуктовая блочная UI-проекция | [`compositions.md`](compositions.md) |
| `domains` | Предметная возможность | [`domains/README.md`](domains/README.md) |
| `infra` | Техническая возможность | [`infra.md`](infra.md) |
| `ui` | Универсальная визуальная возможность | [`ui.md`](ui.md) |
| `shared` | Чистый детерминированный фундамент | [`shared.md`](shared.md) |

Роль выбирается по результату, которым владеет юнит, а не по типу файлов или используемой библиотеке.

## Как выбрать роль

1. Сформулируй связный результат для потребителя без названий файлов и библиотек.
2. Определи, является результат проекционным, предметным, техническим, универсально-визуальным или фундаментальным.
3. Найди ближайшего существующего владельца этой ответственности.
4. Создавай новый юнит только при отдельном публичном контракте и самостоятельной границе зависимостей.
5. Примени фасеты и сегменты из архитектурного профиля.
6. Проверь публичные пути, направления зависимостей и отсутствие циклов.

| Вопрос | Роль |
| --- | --- |
| Юнит собирает готовые возможности в продуктовую область интерфейса? | `compositions` |
| Юнит определяет предметные модели, операции и ожидаемые исходы? | `domains` |
| Юнит предоставляет интеграцию или технический ресурс без предметного смысла? | `infra` |
| Юнит предоставляет универсальную визуальную возможность? | `ui` |
| Юнит предоставляет чистый контракт без предметной, проекционной, технической или визуальной роли? | `shared` |

Если подходят несколько строк, формулировка описывает механизм вместо результата. Уточни, что именно получает
потребитель и по какой причине будет изменяться владелец.

## React не определяет роль

React-компонент является механизмом реализации и сам по себе не создаёт юнит. JSX может находиться в композиционном,
доменном, инфраструктурном или UI-юните:

- композиционный компонент отображает продуктовую проекцию;
- доменный компонент использует предметный контракт своего домена;
- инфраструктурный компонент подключает техническую возможность, например через компонент Provider;
- UI-компонент предоставляет универсальное визуальное поведение.

Provider, hook, store, service, большой файл или отдельная папка также не определяют роль и не обосновывают новый юнит.
Папка становится юнитом только при наличии маркера фасета, но корректность этой границы подтверждают ответственность,
контракт и зависимости.

## Компонент и компонент-юнит

Внутренний React-компонент принадлежит ближайшему юниту и может использовать его реализацию. Компонент-юнит имеет
собственный фасет и подчиняется рекурсивным правилам Unit Architecture:

- родитель импортирует непосредственного ребёнка через фасет;
- ребёнок не импортирует родителя, предков или соседних детей;
- родитель передаёт данные и действия через публичный контракт ребёнка;
- внешние потребители не выполняют глубокие импорты вложенного юнита.

Не добавляй фасет только потому, что JSX вынесен в отдельный файл. Если компонент использует внутренние модели, хуки
или вспомогательные функции родителя, он остаётся внутренней реализацией этого владельца.

## Граница app

`app` запускает React и связывает готовые публичные API с его средой выполнения. Точки входа, дерево Provider,
конфигурация маршрутов и глобальные обработчики ошибок могут находиться непосредственно в `app` без фасетов: эти файлы
имеют форму, заданную фреймворком, и не образуют отдельную проектную ответственность.

Проект не создаёт юниты `app` по умолчанию. Если код в `app` получает самостоятельный переиспользуемый контракт, сначала
проверь, не принадлежит ли он одной из пяти ролей выше.

## Проверка

- Для юнита сформулирован один результат для потребителя.
- Роль выбрана по ответственности, а не по наличию JSX, Provider, hook или библиотеки.
- React-компонент без самостоятельного контракта остался внутренней реализацией.
- Новый фасет соответствует архитектурному профилю.
- `app` не присвоил предметную, техническую или проекционную ответственность.
- Публичные зависимости соответствуют Unit Architecture и не образуют циклов.
