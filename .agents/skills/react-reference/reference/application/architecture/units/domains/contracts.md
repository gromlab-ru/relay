# Доменные контракты

## Публичный API

Домен публикует только собственные:

- входные данные и команды;
- модели и результаты;
- события и доступные формы состояния;
- предметные операции;
- React-хуки и предметный UI, которыми он владеет;
- типы ожидаемых ошибок конкретных операций.

Публичная операция называется в предметных терминах: `getCurrentUser`, `signIn`, `updateOrder`. Слова `adapter`,
transport и название источника данных не входят в экспортируемое имя.

Внешний потребитель импортирует контракт только через фасет домена:

```ts
import {
  getCurrentUser,
  signIn,
  useGetCurrentUser,
} from 'domains/authentication'
import type { CurrentUser } from 'domains/authentication'
```

GET-операция публикуется вместе с GET-хуком. Хук является стандартным способом получить серверное состояние для
отображения React, а обычная операция остаётся доступна для императивного сценария и кода вне жизненного цикла React.
Операции изменения вызываются как обычные асинхронные функции.

```text
GET для отображения → публичный доменный хук
императивный GET → публичная доменная операция
изменение → публичная доменная операция
```

## Граница источника

Не публикуй через доменный фасет:

- DTO и созданные генератором типы;
- методы API-клиента или SDK;
- статусы HTTP и технические ошибки транспорта;
- записи хранилища;
- внутренние адаптеры, mapper-функции и фабрики ошибок.

Исходный DTO всегда преобразуется явным mapper в собственную доменную модель, даже если их текущая структура
совпадает. Предметные входные данные также преобразуются в запрос источника, если операция принимает данные. Только
доменные типы попадают в состояние, кеш, хуки, UI и публичный результат.

```text
предметные входные данные → mapper запроса → запрос источника
исходный DTO → mapper ответа → доменная модель
```

Изменение внешнего контракта должно ограничиваться адаптером и mapper, пока предметный контракт домена остаётся
прежним.
