# Доменные адаптеры

Адаптер является границей домена с API-клиентом, SDK, хранилищем или другим внешним источником. Его реализация находится
внутри домена, а предметная операция публикуется через фасет этого домена.

Роль адаптера выражается расположением и именем файла, а экспортируемая функция называется в предметных терминах:

```ts
// adapters/get-current-user.adapter.ts
export const getCurrentUser = async (): Promise<CurrentUser | null> => {
  const currentUserDto = await identityApi.authentication.getCurrentUser()

  return mapCurrentUserDto(currentUserDto)
}
```

Публичный фасет повторно экспортирует ту же функцию без псевдонима и обёртки:

```ts
export { getCurrentUser } from './adapters/get-current-user.adapter'
```

Не добавляй `getCurrentUserAdapter`, `authenticationAdapter.getCurrentUser()` или отдельный service только для
повторного вызова той же функции. Термин adapter описывает архитектурную роль, а публичное имя выражает предметную
операцию.

Публичная операция не управляет кешем SWR, состоянием React или жизненным циклом дерева компонентов. Она остаётся
обычной асинхронной операцией с доменным контрактом и может использоваться вне React. Обязательную синхронизацию кеша
после успешного вызова выполняет доменный хук, действие или другой явный владелец жизненного цикла.

GET-операция публикуется даже при наличии SWR-хука. Для данных, участвующих в отображении React, потребитель использует
хук; прямая операция предназначена для императивного сценария или кода вне жизненного цикла React.

## Внешняя операция

Адаптер использует готовую возможность публичного фасета инфраструктурного юнита. Для REST это может быть метод
собранного API-клиента либо отдельная операция с уже настроенным `HttpClient`:

```ts
const petDto = await petStoreApi.pets.getPet({ id: petId })
```

```ts
const petDto = await getPet(petStoreHttpClient, { id: petId })
```

Оба варианта используют один настроенный транспорт. Отдельная операция допустима, когда потребитель не должен включать
весь API-клиент в свой чанк. Не создавай `HttpClient`, API-клиент, URL, авторизацию или транспортную политику внутри
доменного адаптера. Граница технической возможности описана в [`infra.md`](../infra.md), а создание клиента — в
[`@gromlab/rest-api-codegen`](../../../../libraries/rest-api-codegen/README.md).

## Преобразование данных

Адаптер использует внутренние mapper-функции для преобразования предметных входных данных в запрос источника и ответа
источника в предметный результат. Даже тождественное преобразование должно явно вернуть доменный тип.

```ts
export const mapPetDto = (petDto: PetDto): Pet => ({
  id: petDto.id,
  name: petDto.name,
})
```

DTO не сохраняется в доменном состоянии или кеше и не передаётся доменному UI.

## Ошибки

Адаптер интерпретирует известную ошибку источника в контексте операции и создаёт ожидаемую доменную ошибку. Для
изменяющей или императивной операции неизвестный сбой преобразуется в `ApplicationDefect`:

```ts
try {
  const petDto = await petStoreApi.pets.updatePet({
    id: input.id,
    name: input.name,
  })

  return mapPetDto(petDto)
} catch (error) {
  if (isPetUpdateConflictSourceError(error)) {
    throw createPetUpdateConflictError(input.id)
  }

  throw toApplicationDefect('pets.updatePet', error)
}
```

Не публикуй исходную техническую ошибку как ожидаемый контракт домена.

### GET-адаптер для SWR

Если GET-адаптер служит загрузчиком SWR-хука с типом `SWRResponse<Data, OperationError>`, он обязан преобразовать каждый
неуспешный исход в `OperationError`. После известных исходов преобразуй оставшийся сетевой сбой, неизвестный ответ или
другое исключение в предусмотренную ошибку временной недоступности:

```ts
try {
  const petDto = await petStoreApi.pets.getPet(petId)

  return mapPetDto(petDto)
} catch (error) {
  if (isPetNotFoundSourceError(error)) {
    throw createPetNotFoundError(petId)
  }

  throw createPetTemporarilyUnavailableError()
}
```

Не выбрасывай из такого адаптера `ApplicationDefect`, если тип ошибки SWR-хука его не включает. Неизвестная ошибка не
передаётся наружу и не становится кодом `UNEXPECTED`: адаптер классифицирует её как допустимый неуспешный исход именно
этой GET-операции. SWR-хук не повторяет проверку и не меняет ошибку.

Примеры полной классификации находятся в адаптерах демо:
[`getCurrentSession`](../../../../../demo-app/src/domains/authentication/adapters/get-current-session.adapter.ts) сводит
отсутствие авторизации к `null`, а прочие сбои — к временной недоступности;
[`getCurrentUser`](../../../../../demo-app/src/domains/user/adapters/get-current-user.adapter.ts) сводит любой
неуспешный исход загрузки профиля к ошибке временной недоступности.

Порт или интерфейс репозитория добавляй только при нескольких реализациях, сборке во время выполнения или отдельной
границе тестирования. Возможная замена источника в будущем сама по себе не требует дополнительной абстракции.
