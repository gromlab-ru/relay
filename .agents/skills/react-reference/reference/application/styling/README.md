# Стилизация React SPA

Для обработки CSS используй PostCSS, локальные стили изолируй через CSS Modules, а код CSS пиши по
[`styleguide/css.md`](../../styleguide/css.md). Установку и настройку PostCSS выполняй по
[`libraries/postcss/README.md`](../../libraries/postcss/README.md).

Если проект уже использует другую рабочую систему стилей, следуй проекту. Не добавляй PostCSS или параллельную
систему переменных в рамках локальной задачи без отдельного решения о переходе.

## Начальные общие стили

Общие визуальные стили принадлежат юниту темы. Новое приложение с принятой Mantine-конфигурацией начинает с трёх
файлов:

```text
src/ui/themes/styles/
├── index.css
├── media.css
└── variables.css
```

| Файл | Ответственность |
| --- | --- |
| `variables.css` | Общие CSS-переменные приложения |
| `media.css` | Именованные условия `@custom-media` |
| `index.css` | Единственная runtime-точка подключения темы и общих визуальных стилей |

Готовое содержимое файлов и способ подключения находятся в
[`libraries/postcss/configuration.md`](../../libraries/postcss/configuration.md#начальные-файлы).

Эти файлы сохраняют свои роли по мере роста приложения. При необходимости добавляй рядом отдельные файлы сброса и
типографики. Подключай их через `index.css`. Не превращай один из трёх начальных файлов в хранилище несвязанных правил.

`media.css` не импортируется в `index.css`: PostCSS передаёт его объявления каждому обрабатываемому CSS-файлу через
`@csstools/postcss-global-data`.

## Стилизация компонентов внешней библиотеки

Если используется примитив или компонент внешней библиотеки, применяй способы стилизации в следующем порядке:

1. Используй публичные средства библиотеки: свойства, варианты, тему, CSS-переменные и другие предусмотренные точки
   настройки.
2. Если средствами библиотеки нельзя получить нужный результат, передай компоненту локальный класс и опиши его в
   CSS Module ближайшего владельца.

Не обращайся к внутренним селекторам и структуре DOM библиотеки. Используй только документированные точки передачи
классов, например `className` или `classNames`.

Не добавляй глобальный селектор для переопределения компонента. Переданный класс и относящиеся к нему правила
принадлежат тому же владельцу, который размещает и настраивает компонент.

Публичные средства темы, свойства и CSS-переменные Mantine описаны в
[`libraries/mantine/usage.md`](../../libraries/mantine/usage.md#стили).

## Владение стилями

- CSS Module размещается рядом с владельцем DOM и визуального поведения.
- CSS Module одного владельца не импортируется другим владельцем.
- Повторение оформления само по себе не делает CSS Module общим.
- Общие переменные и медиавыражения имеют одно центральное место.
- `index.css` подключается ровно один раз внутренней реализацией `ThemeProvider`.
- Конфигурация PostCSS относится к сборке и не получает искусственный фасет времени выполнения.

## Порядок работы

1. Проверь публичные средства стилизации используемого компонента, общие переменные и медиавыражения.
2. Определи владельца DOM и создавай локальный CSS Module рядом с ним.
3. Используй общие переменные и именованные медиавыражения по правилам CSS.
4. Расширяй общие стили только для правила, которое действительно действует во всём приложении.
5. Запусти проверки проекта и производственную сборку, если менялись PostCSS, общие стили или граф импортов CSS.

## Проверка

- Внешний компонент сначала стилизован через публичные средства библиотеки.
- Дополнительный класс передан через документированную точку расширения и описан в CSS Module владельца.
- Локальные стили принадлежат владельцу DOM и находятся в CSS Module.
- Общие переменные и медиавыражения не продублированы.
- `index.css` подключён один раз, а `media.css` не импортирован как обычный CSS.
- Код соответствует [`styleguide/css.md`](../../styleguide/css.md).
- Производственная сборка подтверждает преобразование вложенности и именованных медиавыражений.
