# UI и библиотека компонентов

Этот раздел определяет выбор готовых визуальных решений и создание собственных универсальных компонентов в слое
`ui`. Общий порядок создания React-компонентов независимо от слоя находится в
[`Создании компонентов`](../components/README.md). Страницы и каркасы не становятся частью слоя `ui` из-за наличия JSX.

## Приоритет решений

1. Проверь существующий публичный компонент проекта. Если его назначение и контракт подходят, используй фасет владельца.
2. Найди подходящий примитив, компонент или готовое поведение Mantine. Mantine является основной библиотекой проекта.
3. Настрой публичные свойства или собери композицию готовых компонентов. Не повторяй уже предоставленное библиотекой
   поведение собственной реализацией.
4. Создай собственную визуальную возможность, только если готовые решения не покрывают требуемый контракт. Сначала
   определи владельца по архитектуре; собственный компонент не обязательно принадлежит верхнеуровневому `ui`.

Не добавляй другую библиотеку компонентов без отдельного решения по набору технологий. Не оборачивай каждый компонент
Mantine ради переименования, повторного экспорта или нескольких значений свойств по умолчанию.

## Собственный компонент в ui

Критериями выделения общего UI-юнита владеет
[`архитектурный документ`](../architecture/units/ui.md#критерий-отдельного-юнита). Применяй их к реальным потребителям,
а не к предполагаемому переиспользованию.

1. Определи универсальный визуальный результат и потребителей. Контракт не должен зависеть от предметных моделей,
   маршрутов или конкретной страницы.
2. Проверь, можно ли реализовать результат композицией Mantine, не скрывая полезный публичный API за лишней обёрткой.
3. Создай юнит в `src/ui/<name>` по [`правилам компонентов`](../components/README.md) через `ui-unit`.
4. Адаптируй свойства, DOM и стили к реальному контракту. Публикуй только нужный компонент и его публичный тип.
5. Подключи юнит к потребителям через фасет и проверь поведение во всех подтверждённых местах использования.

Локальная часть экрана сначала остаётся у экрана. Доменный визуальный контракт остаётся у домена. Не переноси компонент
в `ui` только ради одинакового расположения файлов.

## Тема и стили

Настройка Mantine, общей темы и проектного `ThemeProvider` находится в
[`libraries/mantine/README.md`](../../libraries/mantine/README.md). Общая визуальная конфигурация принадлежит `ui/themes`,
а `app` подключает её публичный провайдер.

Для оформления сначала используй публичные свойства, тему и CSS-переменные библиотеки. Дополнительные локальные стили
применяй по [`правилам стилизации`](../styling/README.md#стилизация-компонентов-внешней-библиотеки), не обращаясь к
внутренним селекторам библиотеки. Общие переменные и медиавыражения не дублируются в отдельных компонентах.

## Проверка

- Проверены существующие компоненты проекта и возможности Mantine.
- Собственный компонент добавляет нужное поведение, а не повторяет публичный API библиотеки.
- Размещение в слое `ui` подтверждено архитектурными критериями и реальными потребителями.
- Новый компонент создан CLI по общим правилам, а не ручным копированием шаблона.
- Контракт не зависит от предметной модели; импорты соответствуют правилам слоя `ui`.
- Стили применяются через публичные точки настройки библиотеки.
