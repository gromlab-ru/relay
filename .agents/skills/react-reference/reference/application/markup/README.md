# Вёрстка по макету

Используй этот раздел до написания JSX, когда нужно перенести макет в приложение. Цель: определить смысловые части,
их владельцев и поведение, затем реализовать интерфейс по [`правилам компонентов`](../components/README.md),
[`UI`](../ui/README.md) и [`стилизации`](../styling/README.md).

## Разбор макета

1. Определи страницу или область приложения, пользовательские действия и уже существующий каркас.
2. Найди постоянные области: шапку, навигацию, нижнюю панель. Сравни связанные страницы, чтобы не принять локальный блок
   за общий каркас.
3. Выпиши смысловые блоки, данные и действия каждого. Отдельно отметь состояния загрузки, ошибки, отсутствия данных,
   недоступного действия и открытых диалогов, если они предусмотрены сценарием.
4. Проверь варианты для разных ширин, длинного текста и изменяемого количества элементов. Если макет не определяет
   значимое поведение, задай вопрос, а не придумывай продуктовый сценарий.
5. Найди существующие компоненты, тему, размеры, иконки и возможности Mantine. Используй принятые решения, не добавляя
   другую библиотеку ради внешнего сходства.

## Декомпозиция до JSX

Слой или прямоугольник в редакторе макета не равен React-компоненту. Сначала назови назначение области, затем выбери
владельца по [`архитектуре`](../architecture/units/README.md). Для каждой выделенной части определи входные данные,
действия и причину её изменения.

| Часть макета | Исходное решение |
| --- | --- |
| Постоянная компоновка нескольких страниц | Существующий или обоснованно новый `layouts/*` |
| Содержимое одной страницы | `screens/*` |
| Локальный смысловой блок экрана | Компонент внутри `screens/<name>/ui/` без фасета, если нет отдельного контракта юнита |
| Самостоятельная крупная область интерфейса | Композиционный юнит; в `widgets` поднимается только при подтверждённом назначении и потребителях |
| Предметная визуальная возможность | Публичный UI соответствующего домена, если такой контракт действительно выделен |
| Универсальное визуальное поведение | Готовое решение UI либо собственный юнит по критериям слоя `ui` |
| Отступ, линия или простая обёртка | Разметка и стили ближайшего владельца, не новый компонент автоматически |

Декомпозиция не требует фасета у каждого фрагмента. Вложенный компонент-юнит получает самостоятельный контракт и
соблюдает зависимости родителя и детей. Папка `ui/` внутри экрана или каркаса остаётся сегментом этого владельца.
Не создавай заранее одинаковые деревья каталогов для всех областей.

## Разбор на примере демо

[`Главная страница`](../../../demo-app/src/compositions/screens/home/home.screen.tsx) и
[`кабинет`](../../../demo-app/src/compositions/screens/account/account.screen.tsx) используют один
[`MainLayout`](../../../demo-app/src/compositions/layouts/main/main.layout.tsx). Постоянные панели принадлежат каркасу,
а начальный блок главной страницы и профиль пользователя своим экранам.

[`Header`](../../../demo-app/src/compositions/layouts/main/ui/header/) остаётся у `MainLayout`, поскольку обслуживает
его верхнюю область. Его переключатель темы также находится рядом с фактическим владельцем. Эти компоненты имеют
подтверждённые границы в демо; это не требование выделять такую же иерархию в каждом новом каркасе.

Три карточки главной страницы показывают разные статические сведения и остаются в JSX экрана. Одинаковая форма карточек
не требует превращать их в общий виджет или искусственный массив данных. Если появится отдельное поведение карточки,
сначала проверь локальный компонент. Правила написания и дальнейшего разбиения JSX находятся в
[`стиле JSX и TSX`](../../styleguide/jsx-tsx.md#декомпозиция-jsx).

## Реализация

1. Подключи нужный каркас и создай экран по [`инструкции страниц`](../pages/README.md).
2. Создай выделенные компоненты через генератор. Примеры шаблонов находятся только в
   [`demo-app/.templates/`](../../../demo-app/.templates/README.md); не копируй их вручную.
3. Сначала собери смысловую HTML-структуру и основные связи компонентов. Затем реализуй расположение, типографику,
   цвета и детали через публичные средства Mantine и CSS Modules.
4. Адаптируй поведение от узкого экрана к широкому по [`правилам CSS`](../../styleguide/css.md). Не переноси абсолютные
   координаты из редактора в обычную потоковую вёрстку и не закрепляй высоты текстовых блоков без причины.
5. Подключи реальные данные и действия через API владельцев. Не считай статический макет полным описанием поведения.
6. Подключи иконки по [`правилам иконок`](../icons/README.md), не заменяя существующие ресурсы похожими символами.

## Проверка результата

- Сравни интерфейс с макетом при одинаковой ширине: порядок блоков, размеры, отступы, типографику, цвета и иконки.
- Проверь мобильную и широкую версии, промежуточные ширины, длинный текст и отсутствие случайной горизонтальной прокрутки.
- Проверь реальные состояния сценария, а не только заполненный макет.
- Пройди основные действия клавиатурой; проверь фокус, смысловые элементы и доступные названия.
- Убедись, что локальные компоненты и CSS не подняты к общему владельцу без причины.
- Выполни проверки проекта. Сборка не заменяет визуальную проверку в браузере.
