# Создание страниц

Страница состоит из экранного сценария и его подключения к URL. Вёрстка, состояния отображения и композиция готовых
возможностей принадлежат `compositions/screens`. Дерево URL находится в `app/router`. Для обычной страницы отдельный
посредник между ними не нужен. Архитектурные границы определяет
[`профиль проекта`](../architecture/project-profile.md#граница-app-и-compositions).

## Порядок работы

1. Определи назначение страницы, адрес, нужный каркас и состояния: начальное, загрузку, ошибку, пустой и успешный результат.
   Добавляй только состояния, которые возможны в этом сценарии.
2. Найди публичные возможности доменов, нужные виджеты и компоненты UI. Если есть макет, сначала выполни
   [`разбор и декомпозицию`](../markup/README.md).
3. Создай экран через генератор. Для нового экранного юнита используй `ui-unit`, а не ручной TSX или копию соседней страницы.
4. Адаптируй свойства и стили, собери разметку и подключи готовые доменные хуки и операции. Предметные правила и работу
   с техническим API оставь у их владельцев.
5. Подключи экран к `app/router` напрямую. Каркас выбирается вложенностью маршрутов, а не импортом каркаса внутри экрана.
6. Добавь маршрутную границу только при отдельном поведении: доступе, подготовке параметров URL, провайдере для ветки
   или условном выборе экрана. Применяй [`правила маршрутизации`](../routing/README.md).
7. Проверь страницу по списку в конце документа и выполни команды проекта.

## Пример новой страницы

Ниже показано создание начального экрана `home` в приложении, где его ещё нет. В демо он уже реализован:
[`HomeScreen`](../../../demo-app/src/compositions/screens/home/). Не запускай команды поверх существующего юнита.
Для другой новой страницы выбери её собственное имя и адрес, сохранив порядок действий.

### Генерация

Из корня приложения прочитай [`локальные шаблоны`](../../../demo-app/.templates/README.md) и все файлы `ui-unit`.
Выполни [`инструкцию генерации`](../components/tsx-generation.md), затем запусти:

```bash
npm run create -- ui-unit home src/compositions/screens
```

Успешный запуск создаёт весь начальный комплект:

```text
src/compositions/screens/home/
├── index.ts
├── home.tsx
├── styles/
│   └── home.module.css
└── types/
    └── home-props.type.ts
```

Не создавай эти файлы до CLI. Отсутствие шаблонов требует настройки генератора, а не ручного обхода.

### Адаптация

1. Переименуй реализацию в `home.screen.tsx`, компонент в `HomeScreen`, тип свойств в `HomeScreenProps`, собственные
   параметры в `HomeScreenParams`, а файл типа в `types/home-screen-props.type.ts`. Обнови импорты и экспорт фасета.
2. Опиши реальный контракт. В примере корень экрана является `section`, поэтому выведи `RootAttrs` из
   `ComponentPropsWithoutRef<'section'>` и исключи `children`, которыми управляет сама страница. Удали `children` также
   из собственных параметров и ненужный импорт `ReactNode`. Без собственных параметров `HomeScreenParams` имеет тип
   `object`, как в демо.
3. Адаптируй `styles/home.module.css`: он оформляет DOM экрана и не импортирует CSS Module каркаса.
4. Замени текст JSDoc и содержимое заготовки. Прими `className` и остальные разрешённые атрибуты корня через свойства.

Сокращённая реализация показывает форму компонента, а не предлагает создать файл вручную:

```tsx
import { Container, Title } from '@mantine/core'
import cl from 'clsx'
import styles from './styles/home.module.css'
import type { HomeScreenProps } from './types/home-screen-props.type'

/**
 * Показывает начальную страницу приложения.
 *
 * Используется для:
 *  - отображения основного содержимого стартовой страницы
 */
export const HomeScreen = (props: HomeScreenProps) => {
  const { className, ...rootAttrs } = props

  return (
    <section {...rootAttrs} className={cl(styles.root, className)}>
      <Container size="lg">
        <Title order={1}>Рабочий пример React Reference</Title>
      </Container>
    </section>
  )
}
```

Фасет `index.ts` публикует компонент:

```ts
export { HomeScreen } from './home.screen'
```

Полный результат находится в демо: [`реализация`](../../../demo-app/src/compositions/screens/home/home.screen.tsx),
[`тип свойств`](../../../demo-app/src/compositions/screens/home/types/home-screen-props.type.ts) и
[`CSS Module`](../../../demo-app/src/compositions/screens/home/styles/home.module.css).

### Подключение

В существующем `app/router/app-router.tsx` импортируй `HomeScreen` через `compositions/screens/home` и добавь его в
`children` нужного каркаса. Для начальной страницы запись имеет форму:

```ts
{
  index: true,
  Component: HomeScreen
}
```

Для обычного адреса используй `path`, например `path: 'help'`, без `index: true`. Не пересоздавай всё дерево роутера ради
одной страницы. Полное подключение каркаса, экранов и границ показано в
[`app-router.tsx`](../../../demo-app/src/app/router/app-router.tsx).

Статический экран использует `index.ts`. Для подтверждённой динамической загрузки экран публикует `lazy.ts`, а роутер
подключает его через `lazy: () => import('compositions/screens/<name>/lazy')` по
[`правилам загрузки`](../routing/README.md#динамическая-загрузка). Отдельный `HomeRoute`, который только возвращает
`HomeScreen`, не создаётся.

## Содержимое экрана

Экран собирает разметку страницы из Mantine, публичных UI-компонентов, виджетов и собственных внутренних компонентов.
Для каждого нового внутреннего компонента также запускай генератор. Не поднимай локальный блок в `widgets` только
из-за размера или предполагаемого повторного использования.

GET-состояние получает публичный доменный SWR-хук, изменение выполняет публичная доменная операция. Экран показывает
состояния и завершает пользовательское действие, но не вызывает HTTP-клиент и не преобразует DTO. Примеры:
[`AccountScreen`](../../../demo-app/src/compositions/screens/account/account.screen.tsx) получает профиль и выполняет
выход, [`SignInScreen`](../../../demo-app/src/compositions/screens/sign-in/sign-in.screen.tsx) владеет формой и результатом
входа. Подробные правила находятся в [`Данных`](../data-fetching/README.md) и [`Формах`](../forms/README.md).

Если один экран нужен нескольким маршрутам, не копируй его. Передай различающиеся параметры через свойства.
Отдельная маршрутная привязка параметров и переходов может принадлежать `route-boundaries`. Не вводи такую границу,
если у экрана пока нет этой потребности.

## Проверка

- Зафиксированы выполненная команда генерации и путь нового экрана.
- Реализация, тип свойств и стили адаптированы; нет текста шаблона и пустого маршрутного посредника.
- Страница открывается по прямому URL и при переходе из приложения; работают возврат и обновление страницы.
- Каркас не дублируется внутри экрана; статический или динамический импорт проходит через нужный фасет.
- Проверены нужные состояния данных, повторные действия, ожидаемые ошибки и доступ к защищённой странице.
- Предметные операции остаются в доменах, временное состояние интерфейса имеет подходящего владельца.
- Проверены узкий и широкий экран, клавиатура, заголовки и доступные названия элементов управления.
- Выполнены [`проверки проекта`](../quality/README.md#проверки); в демо используется `npm run check`.
