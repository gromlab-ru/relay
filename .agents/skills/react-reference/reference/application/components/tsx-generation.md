# Создание TSX через генератор

Каждый новый `.tsx` в коде приложения создавай через `npx @gromlab/create` из локального шаблона проекта. Правило
действует во всех прикладных областях и архитектурных слоях, независимо от размера реализации, повторяемости,
наличия JSX, собственного DOM или публичного контракта.

Это относится к обычным и внутренним компонентам, экранам, каркасам, маршрутным границам, провайдерам, гардам и
компонентам обработки ошибок. Перечень не ограничивает правило: тесты, истории компонентов и другие новые файлы
с расширением `.tsx` тоже требуют генерации. Не добавляй отдельные шаблоны для ещё не используемых категорий файлов.

Не создавай новую папку компонента, его `.tsx`, начальный тип свойств, CSS Module и фасет вручную до запуска CLI.
Не копируй соседний компонент или содержимое шаблона вместо запуска генератора. Простота или одноразовое использование
не являются основанием для обхода этого порядка.

## Системные исключения

Без компонентного каркаса допускаются только файлы запуска и связующей конфигурации:

| Файл в демо | Допустимая ответственность |
| --- | --- |
| [`main.tsx`](../../../demo-app/src/app/main.tsx) | Запуск окружения и подключение корня React |
| [`app.tsx`](../../../demo-app/src/app/app.tsx) | Соединение готовых публичных провайдеров и маршрутизатора |
| [`app-router.tsx`](../../../demo-app/src/app/router/app-router.tsx) | Дерево URL и подключение готовых компонентов через их публичные API |

Исключение определяется ответственностью, а не именем файла или размещением в `app`. Файл не должен реализовывать
собственный интерфейс, предметное поведение или техническую возможность. Если такая ответственность появилась,
выдели её к надлежащему владельцу через генератор, а в системном файле оставь подключение.

Реализации провайдера, гарда, `RoutePending` и `RouteErrorBoundary` не относятся к исключениям, даже если используются
только при запуске или находятся в `app`.

Исходники в `.templates/` являются настройкой генератора, а не создаваемым кодом приложения: их можно создавать и
редактировать вручную. Код библиотек и выход других генераторов не превращай в заготовки `@gromlab/create`.
REST-клиент и SVG-спрайт создаются своими инструментами; их файлы нельзя редактировать вручную.

## Порядок работы

1. Определи ответственность, ближайшего владельца и необходимость собственного фасета по
   [`архитектурному профилю`](../architecture/project-profile.md) и [`обзору юнитов`](../architecture/units/README.md).
2. Для нового `.tsx` проверь применимость системного исключения. Если оно не подходит, продолжай через генератор.
3. Найди `.templates/` нужного приложения, прочитай её `README.md` и все файлы выбранного шаблона. Если шаблонов нет,
   выполни [`настройку генератора`](../../libraries/create/README.md#настройка-приложения).
4. Выбери шаблон по архитектурной форме и каталог вывода по владельцу. Не выбирай слой по названию шаблона.
5. Проверь, что целевая папка компонента ещё не существует. Запусти закреплённую команду из корня приложения по
   [`правилам CLI`](../../libraries/create/README.md#запуск).
6. Проверь код завершения и созданные файлы. Адаптируй заготовку в том же изменении, не оставляя демонстрационное
   содержимое, неиспользуемые типы и стили.
7. Проверь структуру, публичные импорты и поведение. Выполни применимые проверки из
   [`Quality`](../quality/README.md#проверки) и укажи в результате команду генерации и созданные пути.

Изменение или перенос существующей реализации без создания нового компонента не требует перегенерации. Выделение
нового компонента при декомпозиции требует. Не перегенерируй незатронутые файлы ради единообразия.

## Выбор шаблона

В [`демо`](../../../demo-app/.templates/README.md) используются две формы одного каркаса:

| Шаблон | Когда использовать |
| --- | --- |
| `ui-component` | Внутренняя реализация ближайшего владельца без собственного фасета, в том числе провайдер или гард |
| `ui-unit` | Самостоятельный компонент-юнит с подтверждённой ответственностью и публичным контрактом |

Оба шаблона применяются во всех допустимых слоях. Не создавай отдельные шаблоны `provider`, `guard`, `screen`, `boundary`
или `dialog` только из-за назначения компонента: его поведение появляется при адаптации общей заготовки.

Публикация компонента через фасет домена не делает компонент отдельным юнитом. Например, домен может экспортировать
внутренний `AuthenticationProvider`, созданный через `ui-component`, без фасета в папке провайдера.

Если файл имеет другую форму, например тест с JSX, используй профильный локальный шаблон этой формы. Если его нет,
сначала закрепи размещение по правилам владельца, добавь нужный шаблон и только затем создай файл через CLI.

## Адаптация каркаса

Итоговую файловую форму определяет [`Создание компонентов`](README.md#базовая-структура). После генерации:

- Сохрани собственную папку компонента и единые места реализации, типов и стилей. Не переноси `.tsx` прямо в общий
  сегмент `ui/` или `providers/` после удаления ненужных частей.
- Замени JSDoc заготовки назначением и реальными сценариями применения по
  [`правилам TSX`](../../styleguide/jsx-tsx.md#верхнеуровневый-комментарий-компонента).
- Опиши реальные свойства. Если их нет, удали параметр функции, тип свойств, его импорт и публичный экспорт.
- Если нет собственного корневого DOM, удали `RootAttrs`, передачу DOM-атрибутов и искусственную обёртку. Провайдер
  может подключать контекст или возвращать `children`, а гард выбирать переданное содержимое.
- Удали CSS Module и его импорт, если собственные стили не нужны. Не удаляй общие стили владельца вместе с локальной
  заготовкой компонента.
- У юнита оставь только нужный фасет и реальные публичные экспорты. Для исключительно динамического экрана или границы
  замени начальный `index.ts` на `lazy.ts` с реэкспортом компонента под именем `Component`. Не помещай JSX в фасет.
- Примени принятое именование роли: `.screen.tsx` для экрана, `.layout.tsx` для каркаса, `.boundary.tsx` для маршрутной
  границы. Согласованно измени имена, импорты и экспорты, не меняя общей структуры. Не создавай отдельный шаблон ради
  суффикса имени.

Результат `@gromlab/create` после создания принадлежит разработчику. Его редактируют как обычный исходный код, не
помещают в `generated/` и не перезаписывают при обновлении шаблона.

## Отсутствующий шаблон и ошибки

Если существующий шаблон нарушает принятые правила, исправь его до генерации. Если правила не позволяют однозначно
определить новую форму, зафиксируй проблему в [`DOCUMENTATION-GAPS.md`](../../../DOCUMENTATION-GAPS.md) и задай
короткий вопрос. Отсутствие шаблона или недоступность CLI не разрешает создавать `.tsx` вручную.

При ошибке не повторяй генерацию с `--overwrite`. Проверь каталог запуска, аргументы и уже созданные файлы. Если это
существующий компонент, редактируй его; если ошибочны имя или путь, исправь их. Перезапись требует отдельного явного
разрешения и проверки затрагиваемых файлов.
