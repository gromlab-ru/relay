# Структура приложения

Начни здесь, если нужно собрать базовый каркас React SPA или понять, как соединены его основные части. Владельцев,
публичные фасеты и зависимости определяет [`архитектурный профиль`](../architecture/project-profile.md). Этот раздел
применяет его к устройству и запуску приложения, не вводя второй набор архитектурных правил.

## Полная карта

```text
<корень приложения>/
├── .templates/                   локальные шаблоны генератора компонентов
├── index.html                    HTML-точка входа Vite
├── package.json                  зависимости и команды
├── vite.config.ts                настройка сборки
├── tsconfig*.json                настройки TypeScript
├── postcss.config.mjs            обработка CSS
├── public/                       статические файлы
└── src/
    ├── app/
    │   ├── main.tsx              запуск React и нужного окружения
    │   ├── app.tsx               подключение публичных провайдеров и роутера
    │   └── router/
    │       └── app-router.tsx    дерево URL
    ├── compositions/
    │   ├── layouts/              постоянные каркасы
    │   ├── route-boundaries/     отдельное поведение маршрутных веток
    │   ├── screens/              страницы и экранные сценарии
    │   └── widgets/              самостоятельные крупные блоки интерфейса
    ├── domains/                  предметные контракты, состояние и операции
    ├── infra/                    технические возможности и внешние интеграции
    ├── ui/                       универсальные визуальные возможности и тема
    └── shared/                   чистые общие функции, типы и данные
```

Это карта допустимых частей, а не команда создать все каталоги. Добавляй слой, группу или сегмент только вместе с
реальной ответственностью. Например, демо пока не содержит `widgets/`: его локальные блоки не требуют такой группы.
Имена файлов настройки сохраняй принятыми в конкретном приложении.

Не копируй целиком демо вместе с авторизацией, MSW и REST-клиентом. Они показывают законченный сценарий, но не являются
обязательными зависимостями любой страницы. Единственный пример локальных шаблонов находится в
[`demo-app/.templates/`](../../../demo-app/.templates/README.md).

## Группы композиций

Точные границы групп закреплены в [`архитектурном профиле`](../architecture/project-profile.md#структура-compositions).
При сборке приложения используй их так:

| Группа | Что создаём | Как подключаем |
| --- | --- | --- |
| `layouts` | Общую компоновку с навигацией, шапкой и местом для страницы | Роутер подключает каркас, каркас выводит вложенный маршрут через `Outlet` |
| `screens` | Вёрстку страницы, её состояния и композицию публичных доменных возможностей, виджетов и UI | Роутер подключает экран напрямую либо его выбирает маршрутная граница |
| `widgets` | Крупную самостоятельную область интерфейса, не являющуюся целой страницей | Экран или каркас использует публичный компонент блока |
| `route-boundaries` | Проверку доступа, привязку параметров URL, область жизни провайдера или условный выбор экрана | Роутер подключает границу только для нужной ветки |

Группа не имеет собственного `index.ts`. Например, `layouts/main/index.ts` принадлежит юниту `main`, а
`layouts/index.ts` не создаётся. Шапка одного каркаса остаётся внутри этого каркаса, а не поднимается в `widgets` про запас.

## Порядок сборки приложения

1. Проверь существующие команды и настройки. Для нового приложения настрой Vite и алиасы слоёв по
   [`Платформе`](../platform/README.md), TypeScript по [`правилам кода`](../../styleguide/typescript/README.md).
2. Настрой единственный локальный набор шаблонов и команду `create` по
   [`инструкции генератора`](../../libraries/create/README.md#настройка-приложения) до создания компонентов.
3. Подключи Mantine и публичный `ThemeProvider` по [`инструкции библиотеки`](../../libraries/mantine/README.md).
   Общие стили и PostCSS настрой по [`Стилизации`](../styling/README.md). Не размещай реализацию темы в `app`.
4. Создай нужный каркас и первый экран через CLI. Внутренние компоненты ожидания и ошибок также требуют генерации.
5. Настрой `app/router/app-router.tsx` по [`Маршрутизации`](../routing/README.md), подключив каркас и экран через фасеты.
6. В `app/app.tsx` соедини публичные провайдеры и `RouterProvider`. Добавляй только необходимые провайдеры; учитывай их
   зависимости и нужную область жизни. Провайдер конкретной ветки не нужно автоматически делать глобальным.
7. В `app/main.tsx` найди корневой DOM-элемент, подготовь нужное окружение и вызови `createRoot` с корневым компонентом.
   Технические ресурсы запускай через API их владельцев.
8. Запусти приложение и проверки проекта. Убедись, что прямое открытие начального и вложенного URL даёт нужный результат.

`main.tsx`, `app.tsx` и конфигурация роутера могут быть связующими файлами без компонентного каркаса только в пределах
[`системных исключений`](../components/tsx-generation.md#системные-исключения). Другие компоненты в `app` по-прежнему
создаются генератором.

## Создание MainLayout

Если приложению нужен общий каркас, создай его через генератор из корня приложения:

```bash
npm run create -- ui-unit main src/compositions/layouts
```

Команда предназначена для приложения без `layouts/main`. В демо этот юнит уже существует; не запускай генератор поверх
него. Перед запуском прочитай выбранный шаблон по [`общей инструкции`](../components/tsx-generation.md).

1. Переименуй созданный `main.tsx` в `main.layout.tsx`, компонент в `MainLayout`, а тип в `MainLayoutProps` и
   `types/main-layout-props.type.ts`. Согласуй импорты и экспорт в `index.ts`.
2. Адаптируй свойства и CSS Module под корневой элемент каркаса. Для каркаса Mantine используй публичные средства `AppShell`.
3. Размести постоянные области и `Outlet` в области основного содержимого. Не импортируй сюда список экранов.
4. Если шапке, навигации или нижней панели нужны собственные компоненты, создай их через CLI внутри `main/ui/`.
   Внутреннюю реализацию и самостоятельный вложенный юнит различай по [`правилам компонентов`](../components/README.md).
5. Подключи `MainLayout` в конфигурации роутера и опиши страницы в `children`. Для другой постоянной компоновки отдельной
   ветки используй её собственный каркас, только если такая потребность уже есть.

Рабочую реализацию показывают [`MainLayout`](../../../demo-app/src/compositions/layouts/main/main.layout.tsx), его
[`свойства`](../../../demo-app/src/compositions/layouts/main/types/main-layout-props.type.ts) и
[`стили`](../../../demo-app/src/compositions/layouts/main/styles/main.module.css). Связь с URL находится в
[`app-router.tsx`](../../../demo-app/src/app/router/app-router.tsx).

## Проверка

- Каждый каталог из карты имеет реальное назначение; пустые группы не созданы.
- `app` связывает публичные API, не реализуя тему, предметные правила или страницы.
- Каркас подключён через React Router и выводит вложенный маршрут через `Outlet`.
- Экран не получил пустой маршрутный компонент только ради подключения.
- Новые компоненты созданы CLI, их типы и стили адаптированы к реальному поведению.
- Смена страниц не дублирует постоянную разметку и не меняет область жизни провайдеров случайно.
- Типы, сборка и прямое открытие URL проверены.
