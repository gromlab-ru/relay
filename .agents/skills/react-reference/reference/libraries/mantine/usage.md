# Использование Mantine

Этот документ описывает механику использования уже выбранного компонента Mantine. Порядок выбора между Mantine,
семантическим HTML и собственным компонентом определяется в [`application/ui`](../../application/ui/README.md).

## Импорты

Импортируй компоненты и библиотечные хуки напрямую из публичного API пакета:

```tsx
import { Button, Group, TextInput } from '@mantine/core'
import { useDisclosure } from '@mantine/hooks'
```

Не создавай общий проектный файл повторных экспортов Mantine. Он скрывает происхождение API, усложняет обновление и
не создаёт самостоятельной проектной ответственности.

## Свойства компонента

Сначала используй публичные свойства компонента для размера, отступов, расположения, состояния и визуального
варианта:

```tsx
<Button loading={isSaving} size="md" type="submit" variant="filled">
  Сохранить
</Button>
```

Не дублируй внутреннее состояние компонента Mantine в React state или Zustand. Храни только состояние сценария,
которое действительно принадлежит приложению.

## Семантика

Выбирай правильный HTML-элемент независимо от используемого визуального компонента. Для полиморфного компонента
используй документированное свойство `component`:

```tsx
<Text component="h1" size="xl" fw={700}>
  Публикации
</Text>
```

Не заменяй заголовок, ссылку или кнопку универсальным `div`. Если Mantine не добавляет нужного поведения или
оформления, используй обычный семантический HTML.

## Стили

Применяй способы стилизации в порядке, определённом в
[`application/styling`](../../application/styling/README.md#стилизация-компонентов-внешней-библиотеки):

1. Публичные свойства, варианты, тема и CSS-переменные Mantine.
2. Локальный класс через документированное свойство `className` или `classNames`.

Используй опубликованные CSS-переменные Mantine в CSS Modules:

```css
.root {
  padding: var(--mantine-spacing-md);
  border: 1px solid var(--mantine-color-default-border);
  border-radius: var(--mantine-radius-md);
  color: var(--mantine-color-text);
}
```

Проектную переменную создавай, когда приложению требуется собственный смысл поверх темы. Связь таких переменных с
Mantine описана в [`configuration.md`](configuration.md#подключение-стилей). Не копируй значение переменной Mantine
под новым проектным именем без нового смысла. Не обращайся к недокументированным внутренним селекторам и структуре DOM
компонента.

## Тема и цветовая схема

- Общие настройки изменяй в `ui/themes/config/theme.config.ts`.
- Не импортируй объект `theme` в компоненты.
- Используй публичные CSS-переменные для оформления в CSS.
- Используй `useMantineTheme`, только когда значение темы требуется для вычисления во время выполнения.
- Получай принятую приложением цветовую схему и действие переключения через фасет `ui/themes`, если такой контракт
  создан.

## Дополнительные пакеты

Подключай дополнительный пакет Mantine только для конкретной задачи. Проверь:

- совпадение версии с `@mantine/core`;
- необходимость отдельного Provider;
- необходимость импорта слоистых стилей;
- отсутствие уже установленного решения с той же ответственностью.

## Проверка

- Компоненты импортированы из публичного API Mantine.
- Сначала использованы публичные свойства и переменные библиотеки.
- Сохранена правильная HTML-семантика и доступное имя интерактивного элемента.
- Локальные классы переданы через документированный API и принадлежат ближайшему владельцу.
- Внутренняя конфигурация `ui/themes` не импортируется потребителями.
- Новый пакет Mantine добавлен только при фактической необходимости и использует общую версию.
