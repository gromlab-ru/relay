# @gromlab/create

`@gromlab/create` создаёт начальный каркас из локальной `.templates/`. Обязательность генерации, выбор формы и
системные исключения определяет [`Создание TSX`](../../application/components/tsx-generation.md). Этот документ описывает
настройку и запуск инструмента, но не выбирает владельца или архитектурный слой.

## Настройка приложения

1. Найди корень нужного React SPA, его `package.json` и существующую `.templates/`. В монорепозитории это корень
   приложения, а не обязательно корень репозитория.
2. Прочитай локальные инструкции. Не заменяй действующий набор шаблонов и не создавай вторую `.templates/` для того же
   приложения. Если обязательные инструкции задают несовместимое решение, согласуй переход вместо обхода правила.
3. Для нового приложения используй [`набор демо`](../../../demo-app/.templates/README.md) как исходную форму двух
   локальных шаблонов: `ui-component` и `ui-unit`. Размести их в `<корень приложения>/.templates/` и адаптируй к принятым
   зависимостям и именованию. Это настройка приложения, а не ручное создание его компонентов.
4. Добавь в `package.json` команду `create` по [`манифесту демо`](../../../demo-app/package.json), если такой команды
   ещё нет. Сохрани существующие команды проекта. Закрепи версию CLI и используй `--skip-update`, чтобы генерация не
   предлагала глобальное обновление инструмента.
5. Выполни пробную генерацию обоих шаблонов в свободный временный каталог и проверь типы результата в окружении
   приложения. После адаптации проверь также компонент без DOM и маршрут только с `lazy.ts`.

Единственный рабочий набор внутри этого skill находится в `demo-app/.templates/`. Не создавай его вторую копию в
корне skill, общий исходный каталог, синхронизацию наборов или символические ссылки.

## Запуск

CLI не требует глобальной установки. Его общая форма:

```bash
npx @gromlab/create <шаблон> <имя> [путь]
```

Для воспроизводимого запуска используй проектную команду `npm run create -- <шаблон> <имя> <путь>`. В демо она
вызывает `npx` с закреплённой версией; источник версии находится в [`package.json`](../../../demo-app/package.json).

Запускай команды из корня приложения, непосредственно содержащего `.templates/`:

```bash
npm run create -- ui-component authentication-provider src/domains/authentication/providers
npm run create -- ui-component auth-guard src/domains/authentication/ui
npm run create -- ui-unit empty-state src/ui
```

Это примеры для новых сущностей. Не запускай их повторно поверх существующих компонентов демо.

- CLI ищет `.templates/` только в текущем рабочем каталоге, не поднимаясь к родителям.
- `<шаблон>` является именем непосредственного подкаталога `.templates/`.
- `<имя>` задаёт переменную `name` в именах папок, файлов и содержимом.
- `[путь]` является родительским каталогом вывода относительно рабочего каталога; абсолютный путь тоже допустим.
  В проектных командах указывай относительный путь явно. Финальную папку `{{name.kebabCase}}` создаёт CLI по шаблону.
- Опции `--templates`, `--templatesPath`, `--templates-path`, `--out` и `--output` не поддерживаются.
- Если целевая папка или файл уже существуют, обычный запуск завершается ошибкой. Не создавай папку компонента
  заранее и не добавляй `--overwrite` для обхода этой защиты.

## Устройство шаблона

Каждый непосредственный подкаталог `.templates/` содержит самостоятельное дерево вывода. В именах и содержимом
используются `{{name}}` и преобразования регистра: `{{name.pascalCase}}`, `{{name.camelCase}}`, `{{name.kebabCase}}`,
`{{name.snakeCase}}`, `{{name.screamingSnakeCase}}`.

Проектные шаблоны используют только `name`: имя React-компонента записывается в `PascalCase`, имена папок и файлов
в `kebab-case`. В шаблоне хранятся настоящие начальные импорты, JSDoc, тип свойств и CSS, а не только пустые файлы.

Каркас использует React, `clsx` и CSS Modules. В демо эти зависимости и обработка CSS уже настроены. Если в целевом
проекте используется другое принятое решение, адаптируй шаблон до запуска, а не добавляй библиотеку ради заготовки.

Не добавляй условные файлы, наследование шаблонов или произвольные флаги, не проверив их поддержку в закреплённой
версии CLI. Различия поведения компонентов реализуются после генерации по
[`правилам адаптации`](../../application/components/tsx-generation.md#адаптация-каркаса).

## Проверка

- Генерация выполняется из правильного корня и завершается с кодом `0`.
- В именах и содержимом нет неподставленных `{{name...}}`.
- У `ui-component` нет фасета, а `ui-unit` публикует минимальный необходимый контракт после адаптации.
- Типы и импорты результата проверены компилятором приложения.
- Повторный запуск без `--overwrite` не изменяет существующие файлы и сообщает об ошибке.
- Применимые проверки приложения проходят после удаления временных примеров.
