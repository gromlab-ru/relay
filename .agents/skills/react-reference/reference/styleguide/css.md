# CSS

Применяй эти правила к общим CSS-файлам и CSS Modules, если проект не задаёт более точный стиль. Порядок выбора между
стилем проекта и строгим применением skill определён в [`README.md`](README.md#режим-применения).

Для новых React-приложений CSS обрабатывается PostCSS. Его установка и настройка описаны в
[`libraries/postcss/README.md`](../libraries/postcss/README.md).

## Перед изменением

1. Найди общие переменные и темы.
2. Найди шкалу `@custom-media` в `media.css`.
3. Проверь, где находится CSS Module владельца изменяемого DOM.
4. Используй существующие правила и не создавай дубликаты переменных или медиавыражений.

## Форматирование

- Используй отступ в 2 пробела и одно свойство на строку.
- Оставляй одну пустую строку между правилами верхнего уровня.
- Оставляй одну пустую строку перед вложенным блоком.
- Сохраняй принятый в проекте порядок свойств.
- Если порядка нет, располагай связанные свойства рядом: положение, модель блока, оформление, текст, остальное.

```css
.root {
  position: relative;
  display: flex;
  width: 100%;
  padding: var(--space-4);
  border-radius: var(--radius-control);
  background: var(--color-surface-page);
  color: var(--color-text-primary);
}
```

Не переставляй свойства во всём существующем файле ради соответствия рекомендуемому порядку.

## Имена классов

В CSS Module называй реальный корневой элемент `.root`, а остальные локальные классы пиши в `camelCase`:

```css
.root {
  display: grid;
}

.contentItem {
  min-width: 0;
}

.submitButton {
  justify-self: end;
}
```

Редкие глобальные классы называй в `kebab-case`. Не смешивай `camelCase` и `kebab-case` в одном CSS Module.

## Вложенность

Используй вложенность для:

- псевдоклассов;
- псевдоэлементов;
- модификаторов базового класса;
- медиавыражений, изменяющих текущее правило.

```css
.root {
  color: var(--color-text-primary);

  &:hover {
    color: var(--color-action-primary);
  }

  &::before {
    content: '';
  }

  @media (--md) {
    display: grid;
  }
}
```

Не вкладывай классы элементов в `.root`. Адресуй элемент собственным локальным классом вместо каскада:

```css
.root {
  display: flex;
}

.title {
  font-weight: 600;
}
```

Не используй `.root .title`, если разметка позволяет назначить элементу класс `.title` напрямую.

## Модификаторы

Модификатор оформляй отдельным коротким классом с начальным `_`: `._active`, `._disabled`, `._compact`. Применяй его
только вместе с базовым классом.

```css
.root {
  color: var(--color-text-on-action);

  &._danger {
    background: var(--color-action-danger);
  }
}
```

В коде компонента одновременно передай `styles.root` и `styles._danger`. Не используй модификатор как
самостоятельный класс и не кодируй его в имени базового класса как `.button--danger` или `.button_danger`.

Если вариант описывает самостоятельный элемент, а не состояние или вариант базового класса, создай обычный класс с
понятным именем.

## Mobile First и медиавыражения

Базовое правило описывает отображение на малом экране. Расширяй его для больших экранов через именованные условия с
`min-width` из общего `media.css`.

```css
.cardGrid {
  display: grid;
  grid-template-columns: 1fr;

  @media (--md) {
    grid-template-columns: repeat(2, 1fr);
  }
}
```

- Размещай медиавыражение внутри изменяемого селектора.
- Используй существующее именованное условие вместо числового значения.
- Не добавляй откат через `max-width`, если правило можно выразить от малого экрана к большому.
- Используй `--xs` с `max-width` только для необходимого ограничения сверху.
- Не создавай второй набор контрольных точек рядом с `media.css`.

Числовое условие допустимо для уникального порога одного компонента, который не относится к общей шкале. Оставь
короткий комментарий с причиной. Если порог повторяется, добавь именованное условие в общую шкалу.

## Переменные

Используй общую CSS-переменную для повторяемого значения с единым смыслом: цвета, отступа, шрифта, радиуса или другого
элемента оформления.

- Используй существующую переменную вместо копирования её значения.
- Не создавай переменную только для замены одного локального значения.
- Не создавай новое имя для уже существующего смысла.
- Одноразовое значение оставляй в CSS Module владельца.
- Не создавай в CSS второй набор значений поверх темы Mantine.

## Владение CSS Modules

- CSS Module принадлежит владельцу DOM и визуального поведения.
- Размещай его рядом с этим владельцем.
- Не импортируй CSS Module одного владельца в код другого владельца.
- Не выноси локальные классы в общие стили.
- Если оформление должно переиспользоваться, выдели общий UI-компонент или переменную, а не общий CSS Module.
- Не создавай пустой CSS Module для сущности без собственного DOM.

Общие CSS-файлы содержат только правила приложения в целом: переменные, медиавыражения, сброс, базовую типографику и
темы.

## Комментарии

- Пиши комментарий в форме `/* Причина. */`.
- Объясняй неочевидное ограничение или обходное решение.
- Не пересказывай свойства и значения.
- Удаляй устаревший комментарий вместе с изменением правила.

## Проверка

- Сохранён стиль существующего проекта или явно включён строгий режим styleguide.
- В CSS Module корневой класс называется `.root`, остальные классы используют `camelCase`.
- Вложенность ограничена псевдоселекторами, модификаторами и медиавыражениями.
- Модификатор оформлен отдельным классом `._modifier` и применяется вместе с базовым классом.
- Адаптивные правила следуют Mobile First и используют общую шкалу `@custom-media`.
- Медиавыражение находится внутри изменяемого селектора.
- Общие переменные не дублируются.
- CSS Module не пересекает границу владельца.
- Производственная сборка преобразует вложенность и именованные медиавыражения.
