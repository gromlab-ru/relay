# Возможности REST API Codegen

REST API Codegen создаёт единую среду для работы с REST API. Клиент можно сгенерировать из OpenAPI, собрать вручную, дополнить своими операциями или использовать только в том объёме, который нужен конкретной части приложения.

## Автоматическое создание API-клиента

Если в проекте есть OpenAPI, REST API Codegen автоматически создаёт готовый API-клиент. Он включает модели, операции, полное дерево API и HTTP-клиент, который можно настроить под требования проекта.

## Ручное создание API-клиента

Если OpenAPI ещё нет, API-клиент можно создать вручную. Пользователь описывает модели и операции сам, но использует тот же HTTP-клиент, тот же способ сборки API и те же возможности настройки, что и при автоматической генерации.

Когда OpenAPI появится, ручные операции можно постепенно заменить сгенерированными. При этом не придётся заново проектировать клиент, менять общие настройки запросов или переписывать весь код приложения.

## TypeScript из коробки

Модели, параметры запросов и ответы сразу получают TypeScript-типы. Редактор подсказывает доступные методы и их аргументы, а ошибки можно заметить ещё до выполнения запроса. Ручные операции используют ту же систему типов, что и сгенерированные.

## Гибко настраиваемый HTTP-клиент

Автоматически сгенерированные и ручные API-клиенты используют один подход к настройке HTTP-транспорта. В одном месте можно задать адрес API, заголовки, авторизацию, обработку ответов и ошибок, повторы, отмену запросов и другие общие правила.

Перехватчики позволяют изменять запросы перед отправкой, обрабатывать ответы и централизованно реагировать на ошибки. При необходимости можно заменить Fetch, сериализацию параметров и разбор ответов собственной реализацией.

## Патчинг API-клиента

Если OpenAPI содержит ошибку или в ней не хватает нужной операции, не обязательно ждать исправления от владельца API. Можно сгенерировать клиент из доступной спецификации, написать исправленную операцию вручную и заменить ею ошибочную операцию либо добавить новую.

Сгенерированные файлы при этом остаются без изменений. Когда спецификацию исправят, ручной патч можно удалить и вернуть сгенерированную операцию.

## API-клиент как конструктор

Вы сами определяете, какие методы будут доступны в каждом API-клиенте. Можно собрать полный клиент, небольшой клиент для отдельного домена или создать собственную структуру API с удобными названиями методов.

Из одних и тех же операций можно создать сколько угодно API-клиентов. У каждого клиента может быть свой набор методов и свой HTTP-транспорт с отдельными настройками, авторизацией и обработкой ошибок.

## Использование одной операции

Если нужен только один запрос, не обязательно создавать отдельный API-клиент или подключать полное дерево операций. Можно импортировать одну операцию, передать ей HTTP-клиент и вызвать напрямую.

Такой вариант подходит для небольших модулей, хуков и других мест, где важно не подключать в клиентский чанк лишние операции.

## NPM пакет как SDK для нескольких приложений

API-клиент можно хранить внутри приложения или вынести в отдельный пакет. Несколько приложений смогут использовать общий SDK и при этом выбирать подходящий способ подключения: полный клиент, небольшой доменный клиент или отдельные операции.

## Agent skill

Вместе с проектом доступен русскоязычный agent skill для OpenCode и Claude-compatible агентов. В нём собраны инструкции и рецепты по использованию REST API Codegen в существующих проектах.
