# Рецепты

Выберите раздел по тому, что вы сейчас делаете.

## [Пакет](./package/index.md)

Подойдёт, если REST-клиент оформляется как отдельный package boundary:

- в любом монорепозитории;
- для нескольких приложений;
- через npm-реестр;
- с собственными точками входа и проверкой сборки;
- с временными ручными исправлениями поверх сгенерированного кода.

## [React](./react/index.md)

Здесь собраны примеры для браузерного приложения:

- полный API-клиент;
- ручное описание API, если OpenAPI пока нет;
- исправление одного неверно описанного метода;
- SWR;
- JWT, cookie, обновление токена, повтор запросов и загрузка файлов.

## [Next.js App Router](./nextjs/index.md)

Здесь собраны примеры, специфичные для Next.js:

- отдельные API-клиенты для route-specific чанков;
- cookie-аутентификация на сервере.

## Как выбрать подход

| Ситуация | Что делать |
| --- | --- |
| Есть актуальная OpenAPI | Сгенерировать клиент |
| OpenAPI пока нет | Описать типы и запросы вручную: [React](./react/manual-client.md) |
| В OpenAPI неверен один метод | Добавить временное исправление: [React](./react/broken-endpoints.md) или [пакет](./package/generated-with-corrections.md) |

После этого выберите форму использования:

- полный клиент, если нужна большая часть API;
- отдельные клиенты, если страницам нужны разные наборы операций;
- отдельная операция, если хук вызывает один метод API.

Во всех вариантах настройки адреса, авторизации и обработки ошибок хранятся в одном экземпляре `HttpClient`.
