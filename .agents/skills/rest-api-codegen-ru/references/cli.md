# CLI

CLI читает OpenAPI-спецификацию и записывает сгенерированный REST API-клиент в указанный каталог.

## Запуск

Основной способ запуска - `npx` с явно указанной версией:

```bash
npx --yes @gromlab/rest-api-codegen@5.2.4 \
  --input <openapi.json-or-url> \
  --output <directory>
```

Если пакет установлен в проекте, доступна команда `rest-api-codegen` с теми же параметрами.

Генерация не входит в публичный программный API пакета и запускается через CLI.

## Параметры

| Параметр | Обязательный | Описание |
| --- | --- | --- |
| `-i, --input <path>` | да | Путь к локальной JSON-спецификации или URL с протоколом HTTP(S). |
| `-o, --output <path>` | да | Каталог, в который будет записан сгенерированный клиент. |
| `-V, --version` | нет | Выводит версию CLI. |
| `-h, --help` | нет | Выводит справку. |

## Входная спецификация

Локальный файл читается относительно текущего рабочего каталога. Для URL CLI выполняет один запрос и использует тело ответа как спецификацию.

Входные данные разбираются как JSON. Перед генерацией проверяется минимальная структура документа:

- корневое значение является объектом;
- указано строковое поле `openapi` или `swagger`;
- поле `info` является объектом;
- поле `paths` является объектом.

Эта проверка подтверждает структуру входного документа, но не проверяет семантическую корректность каждого endpoint.

## Результат генерации

CLI создаёт следующий набор файлов:

```text
generated/
├── create-api-client.ts
├── data-contracts.ts
├── http-client.ts
├── index.ts
├── operations-tree.ts
└── operations/
    ├── index.ts
    └── <operation>.ts
```

| Файл | Содержимое |
| --- | --- |
| `data-contracts.ts` | Типы данных, параметры запросов, тела запросов и перечисления из OpenAPI. |
| `operations/<operation>.ts` | Отдельная типизированная операция одного endpoint. |
| `operations/index.ts` | Общая точка экспорта всех операций. |
| `operations-tree.ts` | Полное дерево операций, сгруппированное по данным спецификации. |
| `http-client.ts` | `HttpClient`, типы запросов и `ApiError`. |
| `create-api-client.ts` | `createApiClient` и типы для связывания дерева операций с `HttpClient`. |
| `index.ts` | Общая точка экспорта сгенерированного клиента. |

Сгенерированный клиент самодостаточен: во время выполнения он не импортирует код из `@gromlab/rest-api-codegen`.

### Общая точка экспорта

`index.ts` экспортирует:

- все типы данных;
- все операции по именам и в объекте `operations`;
- `operationsTree` и его тип;
- `HttpClient`, `ApiError`, `ContentType` и связанные типы;
- `createApiClient` и типы дерева операций.

### Операции

Для каждого endpoint создаётся отдельная функция. Она принимает совместимый HTTP-клиент первым аргументом, затем параметры endpoint и настройки конкретного запроса.

Имена операций берутся из OpenAPI. Если подходящего имени нет или несколько имён конфликтуют, генератор создаёт безопасное уникальное имя.

### Дерево операций

`operationsTree` содержит все операции и используется для создания полного API-клиента:

```ts
const api = createApiClient(httpClient, operationsTree);
```

Группировка строится по первому OpenAPI tag. Операции без группы могут находиться в корне дерева.

### `HttpClient`

Сгенерированный `HttpClient` получает начальный `baseUrl` из первого строкового `servers[0].url`, если он указан в спецификации. Приложение может переопределить адрес при создании `HttpClient`.

## Обновление output-каталога

CLI считает указанный output-каталог полностью управляемым результатом генерации.

Новый клиент сначала создаётся во временном каталоге. Если его содержимое совпадает с текущим результатом, существующий каталог не заменяется. Если содержимое изменилось, новый каталог устанавливается целиком, а прежний используется как резервная копия на время замены.

Следствия:

- устаревшие файлы удаляются;
- ручные файлы внутри output-каталога также удаляются;
- ошибка загрузки, разбора или генерации не повреждает существующий результат;
- ручной код нужно хранить за пределами output-каталога.

Если новый результат установлен, но резервную копию не удалось удалить, CLI завершает генерацию и выводит предупреждение с путём к резервной копии.

## Вывод и коды завершения

Во время работы CLI показывает текущий этап и прогресс генерации. После завершения выводятся количество операций, моделей и файлов, путь к результату и время выполнения этапов.

| Код | Значение |
| --- | --- |
| `0` | Генерация завершилась успешно либо результат уже был актуален. |
| `1` | Ошибка параметров, входной спецификации, сети, генерации или записи результата. |
