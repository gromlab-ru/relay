# Фичи и сценарии: рабочее видение

Дата: 18 сентября 2026 года.

Статус: материал проектирования UI-прототипа на моковых данных. Итоговое поведение перенесено
в [спецификацию сущности «Продукт»](docs/product/entities/product/README.md) 18 сентября 2026 года.
Для реализации ядра, хранения и агентских инструментов использовать эту спецификацию,
включая явно зафиксированные открытые решения. Ниже сохранён ход формирования интерфейса.

## Назначение

Фичи — первая смысловая декомпозиция продукта. Фича описывает устойчивую возможность,
её назначение, общие правила и границы. Сценарии раскрывают конкретное поведение внутри
этой возможности. Фичи и сценарии сохраняются после завершения реализовавших их задач.

Группы фич и произвольная вложенность подфич на этом этапе не вводятся:

```text
Фича «Каталог товаров»
├── Найти товар по названию
├── Отфильтровать товары по характеристикам
├── Отсортировать результаты
└── Посмотреть карточку товара
```

Оформление заказа — другая фича со своими сценариями, если продукт поддерживает покупку.
Сценарий описывает действие и наблюдаемый результат, а задача — работу по его созданию
или изменению. Например, «Найти товар» — сценарий, «Добавить поиск с учётом опечаток» — задача.

## Представление в интерфейсе

Основной экран — двухуровневое дерево:

```text
▾ [в работе] Каталог товаров
  ├── [готово] Поиск по каталогу
  ├── [в работе] Фильтрация
  └── [не готово] Сортировка
```

- По умолчанию все фичи свёрнуты. При возвращении со страницы фичи сохраняется выбранное раскрытие.
- Клик по блоку фичи раскрывает и сворачивает сценарии; стрелка дублирует это действие.
- Название фичи открывает её страницу с описанием и сценариями.
- Клик по заголовку не переключает раскрытие. Ветки визуально соединены с родителем.
- Одно компактное действие сворачивает все видимые фичи либо раскрывает их, если все свёрнуты.
- Название сценария открывает эту страницу на соответствующем подразделе.
- У каждого сценария собственные название, Markdown-описание, статус и постоянный ID.
  Ссылка опирается на ID и сохраняется после переименования.
- Сценарии представлены самостоятельными записями моковой модели, а не только заголовками
  общего Markdown. На странице фичи это разделы с отдельным редактированием.
- Поиск находит фичи и сценарии, сохраняя родительский контекст совпадений, и раскрывает
  найденные ветки. После очистки поискового запроса дерево снова сворачивается.
- Фильтр готовности относится к фиче целиком. Скрытые поиском сценарии продолжают
  участвовать в расчёте её статуса.

## Готовность

Три состояния обозначаются круглыми индикаторами с доступными текстовыми подписями:

- **Готово:** заполненный круг с галочкой, приглушённый зелёный из палитры Relay.
- **В работе:** заполненный круг с галочкой, приглушённый золотисто-охристый.
- **Не готово:** пустой круг с серым контуром.

Подпись «В работе» обозначает промежуточную готовность. У фичи это означает,
что её сценарии готовы частично.
Заливки спокойные, согласованы с графитовой темой и адаптируются к светлой и тёмной схемам.

Это индикаторы, а не интерактивные чекбоксы. В прототипе готовность сценария задаётся
в его редакторе; готовность фичи вычисляется автоматически:

1. Все сценарии готовы — фича готова.
2. Есть готовые или частично готовые сценарии, но готовы не все — фича частично готова.
3. Все сценарии не готовы — фича не готова.
4. Сценариев нет — серый индикатор и пояснение «Сценарии не описаны».

Пустой набор не считается готовым. Добавление нового незавершённого сценария меняет
готовую фичу на частично готовую: индикатор относится к текущему описанному объёму.
Количество закрытых задач само по себе не определяет готовность сценария.
В дереве используются только три состояния: «Готово», «В работе», «Не готово».

## Приложения: объявление своего вклада

Приложение выбирает, какие фичи и какие сценарии оно реализует. У выбранной фичи
есть описание общего вклада приложения, у каждого выбранного сценария — собственное
описание того, что приложение должно обеспечить для выполнения общего контракта.

Каждый вклад содержит **«Заголовок вклада»** (одна строка о реализации), **«Описание вклада»**
(подробный Markdown) и собственную готовность. Название самой фичи или сценария берётся
из общего продукта; заголовок вклада принадлежит приложению и отображается под этим названием.

```text
Веб
└── Каталог вещей
    Вклад: интерфейс поиска и выбора вещей.
    ├── Поиск по каталогу
    │   Вклад: поле запроса, выдача, пустые результаты и повтор после ошибки.
    └── Просмотр карточки вещи
        Вклад: фотографии, характеристики и условия аренды.
```

- Исходные фичи и сценарии общие для продукта; приложение ссылается на их постоянные ID.
- Выбор фичи не включает все сценарии автоматически. Их выбирают отдельно либо действием
  «Выбрать все сценарии». Выбор сценария включает его родительскую фичу.
- Фичу можно подключить без сценариев и описать общий вклад; интерфейс явно показывает,
  что сценарии ещё не выбраны. Снятие выбора фичи исключает и её сценарии.
- Каждая выбранная фича и каждый выбранный сценарий должны иметь заголовок и описание вклада.
  Пока они не заполнены, ввод остаётся черновиком; сохранение показывает, что нужно дополнить.
- Выбор выражает заявленную ответственность. Он не меняет готовность общего сценария.
- У вклада в фичу и у вклада в каждый сценарий есть собственный статус реализации в приложении:
  «Готово», «В работе», «Не готово». Приложение описывает реализацию и отдельно отмечает,
  что выполнило свою часть контракта. Статусы редактируются рядом с описанием вклада.
- В дереве приложения и редакторе используются те же спокойные круглые индикаторы,
  что и в общем каталоге. Выбор элемента и его готовность — отдельные действия.
- Изменение названия или описания фичи сохраняет выбранный состав и тексты приложений.

### UI приложений

Список показывает название, тип, назначение и число выбранных фич и сценариев.
На странице приложения — описание и дерево его участия с фичами, свёрнутыми по умолчанию.
Оформление строк и линий общее с каталогом фич. Под названием каждого элемента показывается
заголовок вклада приложения; подробный Markdown находится в редакторе.
Клик по блоку фичи раскрывает сценарии. Клик по названию фичи или сценария открывает
редактирование соответствующего вклада. Отдельная ссылка справа открывает исходное
продуктовое описание с возможностью вернуться к приложению.

После создания приложения действие «Выбрать фичи и сценарии» открывает отдельный редактор:
дерево выбора с поиском слева, описание вклада выбранного элемента справа. Исходный
контракт можно прочитать рядом. На узком экране выбор и редактирование идут последовательно.
Переключение между элементами, поиск и временное снятие выбора сохраняют набранные тексты
в черновике. Сохранение применяет весь выбранный состав, отмена возвращает подтверждённый.
У прежних вкладов без заголовка он первоначально формируется из сохранённого текста;
полное описание, собственные состояния и введённые данные остаются сохранены.

В прототипе используются текущие фичи и приложения «Веб», «API» и «Админка».
Модель и черновики остаются локальными для проекта и вкладки. Старые описания и правки
сохраняются при обновлении моковой модели. Связи с работой и расчёт готовности по вкладам
приложений проектируются следующим этапом после просмотра этого UI. В текущих моках
изменение готовности вклада сохраняется у приложения; общий статус продукта ещё не пересчитывается.

### Следующий этап: общая готовность по приложениям

Сценарий считается выполненным, когда все приложения, объявившие участие в нём,
отметили свою реализацию готовой. Аналогичное требование действует для общего вклада
в фичу; готовность самой фичи также учитывает её сценарии.

- Все участвующие приложения отметили «Готово» — контракт выполнен на уровне этих вкладов.
- Выполнена только часть вкладов или есть «В работе» — промежуточное состояние.
- Все вклады «Не готово» — реализация не готова.
- Отсутствие заявленных участников само по себе не является подтверждением готовности.

Точные правила совместного учёта общего вклада в фичу и вкладов в её сценарии,
изменения состава участников и подтверждений реализации уточняем на этапе связывания с ядром.

## Документы продукта

Последний пункт внутри «Продукта» — «Документы». Это общая библиотека самостоятельных
Markdown-материалов: ТЗ проекта, описания ожидаемого поведения, правила и решения.
Один документ сможет относиться сразу к нескольким областям:

```text
Продукт целиком
├── Фича
└── Сценарий фичи
Приложение целиком
├── Реализация фичи
└── Реализация сценария
```

В текущей итерации реализован UI на моках: каталог с поиском, фильтрами и сортировкой,
чтение Markdown, создание и редактирование с локальным черновиком. Название и текст
обязательны; краткое описание помогает читать каталог. Документ допустим без связей.

Связи на данном этапе — только визуальные примеры с множественным выбором и метками.
Выбор родителя не отмечает детей автоматически. Примеры не связаны с ID реальных фич,
сценариев и приложений. Настоящие отношения и показ документов в карточках продуктовых
областей остаются для следующего этапа после согласования интерфейса.

## Будущие связи с работой и готовностью

Планы и задачи смогут ссылаться на фичу целиком и на конкретные сценарии. Из фичи будет
видна связанная работа по всем её сценариям. Общие работы допускают связь только с фичей;
технические общепроектные работы не требуют искусственной фичи.

Приложение будет описывать свой вклад в сценарии общей фичи:

```text
Каталог товаров
├── Создать и изменить товар   ← Админка + API
├── Найти товар                ← Сайт + API
└── Посмотреть карточку товара ← Сайт + API
```

Одно приложение поддерживает несколько сценариев, а один сценарий может требовать
нескольких приложений. Копии сценариев для каждого приложения не создаются. Готовность
сценария предполагает реализацию необходимых частей и проверку целого поведения;
готовый API сам по себе не означает готовый пользовательский сценарий.

Точные контракты связей, подтверждений готовности и версий согласуем перед этапом ядра.

## Текущий этап: моки

- Переработать каталог в дерево фич и сценариев внутри существующего раздела «Продукт».
- Показать страницу фичи с описанием, вычисляемой готовностью и подразделами сценариев.
- Дать создать и отредактировать сценарий, его Markdown и статус с локальным сохранением.
- Проверить изменение статуса родителя, прямые ссылки, поиск, пустые состояния, ошибки,
  черновики, клавиатуру, светлую/тёмную темы и мобильный экран.
- Сохранить текущую изоляцию данных по проекту и вкладке в `sessionStorage`.
- Дать приложению выбрать фичи и сценарии и отдельно описать каждый вклад.
- Моковые связи с планами и задачами пока остаются на уровне фич и приложений.
  Их детализация и расчёт готовности по вкладам относятся к следующему этапу.
